# 外设板移植

usb正常发送后红外数据后，由于主板的引脚冲突，所以最终决定所有的数据都通过usb发给算法板。但是不是单纯的发数据，是要参考之前项目的协议，在上面进行复用。

移植的数据发送链路有三个线程（原始是通过串口发送的，rt_device_wrtie），分别是

1.task_comm_soc_boost：两个任务，一个数据更新（dataupdate，负责将定义的模块结构体全局变量拷贝到comm_soc的大结构体中，最后发包都是从这个结构体中取得），一个把更新后的数据推送到队列中

2.task_comm_soc_tx：从队列中取数据进行组包，组包包括帧头（0xAA 0xAA），header结构体（包括发送者、接收者、数据包长度、systick），smallpack结构体（也就是数据包，包括mod_id（提前定义好的，用来识别你是什么mod），mod偏移，payload的长度，以及负载（负载就是定义的mod的具体结构体））、crc16(对header和data校验)、sum、帧尾(0x55 0x55)（上行数据）

3.task_comm_soc_rx:对上面发送的包进行解码，根据mod把它分发会各模块（下行数据）

数据发送链路是：

在各个任务中对定义的全局mod结构体进行更新，然后在dataupdate中将其拷贝到comm_soc大结构体中（也是全局），然后在通过队列推送，然后在tx线程中取队列组包进行发送。



## 帧格式

一帧经过转义后的线上格式如下：

```text
AA AA | escaped(Header + Data + CRC16 + SUM) | 55 55
```

去除转义后的逻辑格式如下：

```text
AA AA | Header(8B) | Data(len B) | CRC16(2B) | SUM(1B) | 55 55
```

所有多字节字段均为小端序（Little Endian）。

### 帧头和帧尾

- 帧头：`0xAA 0xAA`
- 帧尾：`0x55 0x55`
- 转义控制字：`0xA5`

帧头和帧尾只用于传输层定界，不属于 Header、Data 或 CRC 的校验内容。

### Header：8 字节

| 0 | 1 | `start_chip_id` | `uint8` | `0x0D`，UI 板 |
| 1 | 1 | `target_chip_id` | `uint8` | `0x01`，SOC |
| 2 | 2 | `len` | `uint16 LE` | Data 区长度，不含 Header、CRC、SUM |
| 4 | 4 | `systick_ms` | `uint32 LE` | UI 板 RT-Thread tick，单位 ms |

###  

### 一帧完整示例

以下示例假设：

```text
start_chip_id       = 0x0D
target_chip_id      = 0x01
systick_ms          = 500
ir_left_data        = 0x01
ir_right_data       = 0x20
ir_left_success     = 99%
ir_right_success    = 90%
flags               = 0x05   (bit0=对准，bit2=检测到红外)
```

Header：

```text
0D 01 0E 00 F4 01 00 00
```

解释：`0D 01` 是源/目标地址，`0E 00` 表示 Data 长度 14 字节，`F4 01 00 00` 表示 `systick_ms=500`。

Data 区只有一个 `0x7A` SmallPack：

```text
7A 00 0B  01 20 63 5A 05 F4 01 00 00 00 00
|  |  |   |--------------------------------|
|  |  |             11B 红外载荷
|  |  mod_len=11
|  mod_offset=0
mod_type_id=0x7A
```

对 `Header + Data` 计算 CRC16，得到：

```text
CRC16 = 0x0CC2
线上小端字节 = C2 0C
SUM = 0x3C
```

去掉帧头和帧尾、但已经包含 CRC/SUM 的 `body` 为：

```text
0D 01 0E 00 F4 01 00 00
7A 00 0B 01 20 63 5A 05 F4 01 00 00 00 00
C2 0C 3C
```

最终线上发送的完整字节流为：

```text
AA AA
0D 01 0E 00 F4 01 00 00
7A 00 0B 01 20 63 5A 05 F4 01 00 00 00 00
C2 0C 3C
55 55
```

连续写成一行：

```text
AA AA 0D 01 0E 00 F4 01 00 00 7A 00 0B 01 20 63 5A 05 F4 01 00 00 00 00 C2 0C 3C 55 55
```

接收端去掉 `AA AA` 和 `55 55` 后：

1. 读取 Header，得到 `data_len=14`；
2. 读取 14 字节 Data；
3. 读取 CRC `C2 0C`，计算结果应为 `0x0CC2`；
4. 读取 SUM `3C`，对 Header、Data、CRC 的所有字节求和后低 8 位应为 `0x3C`；
5. 解析 `0x7A`，得到左数据 `0x01`、右数据 `0x20`、左右成功率 `99%/90%`、flags `0x05`、时间戳 `500 ms`。

该示例中的所有字节都没有触发转义。实际数据中若出现 `A5`、`AA` 或 `55`，线上必须在该字节前增加一个 `A5`，接收端去转义后再进行上述偏移解析。



## 转义规则

发送端会对帧头和帧尾之间的所有逻辑字节进行转义，包括：

- Header
- Data
- CRC16 两字节
- SUM

若待发送字节等于以下任意值：

```text
0xA5、0xAA、0x55
```

则在线上发送：

例如：

```text
逻辑字节：AA 55 A5 12
线上字节：A5 AA A5 55 A5 A5 12
```

接收端状态机要求：

1. 在空闲状态寻找连续的 `AA AA`；
2. 进入帧内状态后，遇到 `A5`，将它作为转义前缀丢弃，并把下一个字节原样写入逻辑缓冲区；
3. 只有未被转义的连续 `55 55` 才表示帧结束；
4. 遇到非法转义字节时丢弃当前帧并重新寻找帧头；
5. 接收缓冲区必须支持跨 USB read 的半帧、粘包和多帧。

转义后的 `A5 AA` 不能当成帧头，转义后的 `A5 55` 不能当成帧尾。



## Data 区：SmallPack 序列

Header 的 `len` 指定 Data 区的字节数。Data 由一个或多个 SmallPack 首尾连接组成：

```text
SmallPack = mod_type_id(1B) | mod_offset(1B) | mod_len(1B) | mod_buf(mod_len B)
```

| 字段          |      长度 | 说明                             |
| ------------- | --------: | -------------------------------- |
| `mod_type_id` |         1 | 模块 ID                          |
| `mod_offset`  |         1 | 模块分片序号；非分片模块固定为 0 |
| `mod_len`     |         1 | 当前模块载荷长度，最大 255       |
| `mod_buf`     | `mod_len` | 模块载荷                         |



## CRC16 校验

CRC16 的覆盖范围是：

```text
Header(8B) + Data(len B)
```

不包含：

- `AA AA` 帧头
- CRC16 自身
- SUM
- `55 55` 帧尾

参数必须严格使用：

| 参数           | 值                              |
| -------------- | ------------------------------- |
| 多项式         | `0x8005`，反射实现使用 `0xA001` |
| 初值           | `0xFFFF`                        |
| 输入反射       | 是                              |
| 输出反射       | 是                              |
| 最终异或       | `0x0000`                        |
| CRC 线上字节序 | 低字节在前（LE）                |



## SUM 校验

SUM 是传输层字节和校验：

```text
SUM = (sum(Header + Data + CRC16 两字节) & 0xFF)
```

其中 CRC16 两字节按线上逻辑顺序参与累加，即低字节先加、高字节后加。SUM 本身也属于转义范围。



## 红外接收解码 `0x7A`

当前固件每约 50 ms 发送一个 `0x7A` SmallPack：

```text
mod_type_id = 0x7A
mod_offset  = 0
mod_len     = 11
```

载荷是 `ModIrDecodeResultFb`，总长度 11 字节：

| 偏移 | 长度 | 字段                    | 类型        | 说明                       |
| ---: | ---: | ----------------------- | ----------- | -------------------------- |
|    0 |    1 | `ir_left_data`          | `uint8`     | 左传感器方向位掩码         |
|    1 |    1 | `ir_right_data`         | `uint8`     | 右传感器方向位掩码         |
|    2 |    1 | `ir_left_success_rate`  | `uint8`     | 左传感器解码成功率，0~100% |
|    3 |    1 | `ir_right_success_rate` | `uint8`     | 右传感器解码成功率，0~100% |
|    4 |    1 | `flags`                 | `uint8`     | 状态位字段                 |
|    5 |    4 | `timestamp_ms`          | `uint32 LE` | UI 板 tick 时间戳，单位 ms |
|    9 |    2 | `reserved2`             | 2 字节      | 保留，当前不解析           |

`flags` 定义：

|     位 | 名称               | 含义                       |
| -----: | ------------------ | -------------------------- |
|   bit0 | `is_align_charger` | 是否对准充电桩             |
|   bit1 | `is_near_charger`  | 是否靠近充电桩             |
|   bit2 | `is_find_ir`       | 是否检测到红外信号         |
|   bit3 | `sensor_type`      | `0=MGS` 三代，`1=MGV` 二代 |
| bit4~7 | `reserved`         | 保留                       |



方向位掩码定义：

|   位 | 十六进制 | 含义               |
| ---: | -------: | ------------------ |
| bit0 |   `0x01` | 右远光 `R_FAR`     |
| bit1 |   `0x02` | 右中远光 `Rm_FAR`  |
| bit2 |   `0x04` | 左中远光 `Lm_FAR`  |
| bit3 |   `0x08` | 左远光 `L_FAR`     |
| bit4 |   `0x10` | 右近光 `R_NEAR`    |
| bit5 |   `0x20` | 右中近光 `Rm_NEAR` |
| bit6 |   `0x40` | 左中近光 `Lm_NEAR` |
| bit7 |   `0x80` | 左近光 `L_NEAR`    |
