## 第 1 轮：FOC 双电机项目（已问，部分已答）

**题 1（L1 架构切入）** ESP32 双核跑 FreeRTOS，双电机 FOC 怎么分配到两个核？任务怎么划分、怎么同步？为什么这么分？

- **候选人回答**：通过核绑定 API（`xTaskCreatePinnedToCore`）把不同任务绑到不同核。一个核专管电机控制（实时性隔离），另一个核负责串口命令、IPC、蓝牙（放蓝牙协议的那个核，确保电机运行不受影响）。
  - 优先级划分：电机控制优先级最高（实时性要求）。
  - 电机控制任务内容：① 接收串口队列发送的命令；② 更新传感器值；③ 执行收到的命令（8 种模式之一）；④ 更新全局数据。
  - 串口解析、状态监控放在另一个核。
- **面试官批注**：核隔离思路正确；但"电机优先级最高不受影响"说法有坑（双核各自独立调度，优先级只在本核生效）；"更新全局数据"存在跨核竞态风险（见追问 C）。

**题 2（L2 硬核验伪）** 现场写 Park 变换矩阵；电角度从哪来？机械角度怎么换电角度？矩阵里 cos/sin 怎么算（查表/库函数）？

- **候选人回答**：PARK 矩阵是 2×2 三角函数矩阵，已默写出来（未展示）。电角度来自 AS5600 磁编码器反馈，电角度 = 物理角度 × 极对数，电机极对数为 7。"这个不清楚"（cos/sin 计算方式未答）。
- **面试官批注**：AS5600 为 I2C 磁编码器，与 10kHz 电流环的时序矛盾是硬伤（见追问 B）；Park 矩阵与 cos/sin 实现未实际展示，需补。

**题 3（L3 SVPWM 细节）** SVPWM 怎么实现？扇区判断、非零矢量作用时间怎么算？死区补偿？母线电压利用率？

- **候选人回答**：省略反 Park 变换，在 αβ 坐标系直接合成所需磁场矢量；通过磁编码器反馈判断下一最佳力矩矢量方向，分解为该扇区非零矢量 + 零矢量按不同作用时间组合。**承认这部分直接用了 AI 生成的代码，但原理了解**。未做死区补偿，母线电压利用率不知道。
- **面试官批注**：⚠️ 大红旗。AI 生成代码 + "省略反 Park"说法存疑（Id/Iq 如何闭环、Vd/Vq 是否被用上，见追问 A）。SVPWM 核心公式必须能现场推导。

**题 4（L3 三闭环）** 力矩/速度/位置三闭环各自频率？为什么电流环必须最快？限幅饱和怎么处理（anti-windup）？

- **候选人回答**：电流环 10k，速度环约 200，位置环 10。电流环是最内环、控制核心，要求最快。只做了积分限幅，另有一个"速度为 0 清除前面积累积分"的操作。
- **面试官批注**：频率量级合理；anti-windup 处理较朴素，可追问"清除积分"的触发条件与实现。

### 追问（已答 2026-08-04）

**追问 A（SVPWM 验伪）**：扇区 1（0°~60°）内写出非零矢量 U₄(100)、U₆(110) 作用时间 T₁、T₂ 公式（用 Vα、Vβ 表示）；"省略反 Park"下 Id/Iq 如何闭环？Vd/Vq 是否被用上？

- **候选人回答**：不确定 α/β 代表的意义；用 Uref/Udc 表达：`T1 = √3·Uref·sin(π/3−θ)·T/Udc`，`T2 = √3·Uref·sin(θ)·T/Udc`，`T0=T7=½(T−T1−T2)`，T 为 PWM 周期（10kHz）。**Vd/Vq 在 SVPWM 中未被用上**；"Id/Iq 转为 Iα/Iβ，在 αβ 坐标系实现 SVPWM"。
- **面试官批注**：❌ 公式背对了，但信号流方向搞反——SVPWM 输入是**电压矢量 Vα/Vβ**，不是电流。正向是 Iαβ→Park→Id/Iq（测量），反向是 Vd/Vq→反Park→Vαβ（输出）。"Id/Iq 转为 Iα/Iβ 用于 SVPWM"概念错误。若真不用 Vd/Vq，电流环 PID 的输出去哪了？暴露：FOC 闭环信号流未吃透，极可能是 AI 代码套壳。αβ 物理意义不清（α=定子固定坐标实轴，β=虚轴）是硬伤。

**追问 B（实时性矛盾）**：AS5600（I2C）读一次角度几十 µs，10kHz（100µs）窗口内还要跑两台电机的采样 + 电流环 + SVPWM，时序预算怎么排？AS5600 实际走 I2C/ABZ/PWM？读一次花多少 µs？

- **候选人回答**：AS5600 走 I2C，实际读取约 **700µs**，"所以更新数据比控制快很多"。
- **面试官批注**：❌ 说反了。700µs 读取 vs 100µs 控制周期，是**慢 7 倍**。10kHz 电流环每 100µs 需要电角度，700µs 才刷新一次角度 → 电流环 Park 用的是陈旧角度（约 7 个控制周期共用同一角度）。且 700µs 本身也远超 AS5600 正常 I2C 读取（400kHz 下约 50~100µs），要么配置/时钟有问题，要么记忆不实。"角度-电流环同步"关系没理清，实时性描述站不住。

**追问 C（双核数据竞态）**：跨核共享的全局变量是否有互斥量/临界区保护？任务更新 32 位变量中间过程另一核读到一半怎么办？"电机优先级最高"在双核调度器下的说法是否成立？

- **候选人回答**：全局数据有互斥锁 + 临界区保护，更新时短暂开临界区防被打断，更新完关闭。双核与单核调度器区别"不清楚"。
- **面试官批注**：⚠️ 有保护意识加分，但临界区语义没讲透。**关键坑：ESP32 双核上标准 FreeRTOS 临界区（关中断）只关本核中断，拦不住另一核**；ESP-IDF 的 `portENTER_CRITICAL` 实际靠**自旋锁（spinlock）**。双核各自独立调度，优先级只在本核生效——"电机任务优先级最高"并不能阻止另一核任务影响它，靠的是核隔离。需补：原子操作 / spinlock / ESP-IDF portMUX。

## 第 2 轮：FreeRTOS + Car_Panel CAN（已答 2026-08-04）

**题 5（FreeRTOS 队列原理）**：队列入队完整路径？中断写队列（`xQueueSendFromISR`）与任务写队列的区别？队列满了会怎样？

- **候选人回答**：不理解"入队路径"指什么；知道带 ISR 后缀的 API 能在比 RTOS 可屏蔽优先级低的中断中使用、且不阻塞；经验中中断里一般不直接写队列只做标志，退出中断后由定时器队列任务发送。队列满会丢数据，为不丢数据可将未成功入队的数据"直接发送到队头"。
- **面试官批注**：⚠️ 核心机制未答出：任务写队列（阻塞时）→ 数据暂存不了则把任务从 ready 移入 blocked 链表 → 调度/上下文切换 → 有空间后拷贝。ISR 版：不阻塞、拷贝数据、置 `pxHigherPriorityTaskWoken`、退出中断后触发一次调度。❌ "满了发送到队头"是**自定义危险操作**——满时覆盖的是最旧数据（丢帧！），与简历"零丢帧"宣称自相矛盾，必被追问。

**题 6（信号量 vs 互斥量）**：互斥量与二值信号量本质区别？为什么互斥量能解决优先级反转而二值信号量不能？选型场景举例。

- **候选人回答**：都是通知信号量；互斥量同一时间仅一个持有者、仅持有者可释放；二值信号量任何对象都可释放。二值信号量用于同步（ISR 通知任务），互斥量用于独占资源（多设备共用 I2C/串口，防止数据被打断）。
- **面试官批注**：✅ 方向基本对（所有权、仅持有者可释放、同步 vs 互斥）。❌ 没讲清**优先级继承机制**：高优先级任务等待低优先级任务持有的互斥量时，低优先级任务被临时提升到高优先级任务的优先级，从而不被中等优先级任务抢占——这才是"能解决反转"的本质。也没描述优先级反转现象本身。

**题 7（CAN 双队列架构）**：Car_Panel 的"邮箱"指 CAN 硬件 FIFO 还是自封软件队列？"满回灌"机制怎么工作？500kbps、10ms/10ms 周期跑多少报文？CAN 负载率算过吗？

- **候选人回答**：系统分**动力域（裸机）与显示域（FreeRTOS）**——双 MCU。显示域用 RTOS 自带队列，动力域裸机用自写队列。"满回灌"=队列已满、数据放入失败时调用"发送到队头"函数。**报文数量没确定过，负载率没算过**。
- **面试官批注**：⚠️ 架构终于说清（双 MCU 双域），但：① 负载率没算过是硬伤——写"500kbps/10ms 零丢帧"却不了解总线占用，面试官可当场让你粗算；② "满时发到队头"到底覆盖谁？若覆盖最旧数据则与"零丢帧"矛盾；③ "邮箱"指 STM32 bxCAN 硬件 TX mailbox（3 个）还是软件队列，未区分。

**题 8（8 任务架构）**：8 个任务是哪 8 个？优先级怎么排？"无优先级反转"靠什么保证（互斥量+优先级继承 / 临界区）？举一个任务间通信的具体例子。

- **候选人回答**：**"应该是 7 个"**：CAN TX、CAN RX、UART TX、UART RX、LVGL display、heartbeat、key scan。优先级：CAN 5（最高）、UART 4、LVGL 3、key scan 2、heartbeat 1。靠合理定优先级 + 互斥锁。举例：CAN RX 从动力域接收数据解码 → 更新全局电机变量，LVGL 根据新变量刷新显示，两者间设互斥锁防止优先级反转与并发修改。
- **面试官批注**：⚠️ ① 简历写 **8 任务**、回答 7 个，数字对不上，不严谨（面试官会抓）；② 优先级排序合理；③ 互斥锁例子方向对但机制浅——FreeRTOS 互斥量自带优先级继承才能防反转，需讲清"低优先级持锁、高优先级等待、继承优先级"的完整链路；④ 中断与任务间通信的例子（如 key scan 是否走中断）没展开。

## 第 3 轮：实习经历拷问（已答 2026-08-04）

**题 9（Bug 根因分析）**：挑一个 bug 讲完整链路（现象→排查→根因→修复→验证）+ 工具 + 二分定位。

- **候选人回答**（两个案例）：
  - **电机堵转（E430 刀盘堵转）**：后台取日志 → 定位问题时间 → 取对应时间 DRC（含感知结果 + 机器全部数据）→ 上位机单独拉出刀盘目标/实际速度、目标/实际电流 → 发现某时刻刀盘电流突增 → 对照感知结果发现一团黑色区域，机器一经过刀盘电流就上升 → 与测试沟通确认是**水坑** → 结论：规控未识别水坑避障，刀盘割水阻力增大触发堵转。
  - **通信异常**：机器返厂后无法操控，上位机只有感知结果、主板数据不上传 → 先万用表测充电口（先例：充电口短路烧主板）→ 正常 → 拆机 → 示波器看 UI 板与主板通信 → 抓到主板发出波形异常（只有一半）→ 移交硬件 → 定位 **ESD 器件烧毁**。
- **面试官批注**：✅ **全轮最佳**。日志-时间-数据关联 + 上位机多物理量分析 + 结合感知结果 + 跨测试沟通，方法论完整；第二个案例有先例复用 + 分层排查 + 工具使用（万用表/示波器）。建议打磨成 STAR 逐字稿面试背诵。

**题 10（I2C 多设备）**：AHT20 与 MLX90642 地址冲突？上拉电阻？MLX90642 帧数据量？透传协议帧格式？

- **候选人回答**：不冲突，**走不同 I2C 总线**；要上拉，**4.7k**；MLX90642 一帧 **768×2 = 1536 字节**（24×32 像素 × 16bit）；测试阶段协议**只用了帧头帧尾**；**有做分包处理**（2026-08-04 补充确认）。
- **面试官批注**：⚠️ 基本概念对（分总线避免冲突、4.7k 标准上拉、1536B 计算正确）。分包已做，但 **协议无校验仍是硬伤**：仅帧头帧尾 + 分包，无 CRC/长度/序号，丢字节错位仍无法检测，量产设备必被挑战。建议补：CRC16、长度字段、重新同步机制。追问点：分包长度多少？每包怎么定界？I2C 时钟频率、该波特率下传完 1536B 耗时？

**题 11（IMU 移植验证）**：寄存器/量程/dps/滤波怎么定？验证标准？

- **候选人回答**：量程与配置**参考之前工程**（要求完全适配）；验证：① 自测打印六轴原始数据 + Pitch/Roll/Yaw，符合规律；② 交给后续测试专门验证；③ **（2026-08-04 补充）做了新旧两款 IMU 同环境对比测试：同时打印两者 Pitch/Roll/Yaw 与原始数据，交给算法评估精度能否满足要求**。
- **面试官批注**：⚠️ 诚实降级（复制配置非重新标定），但**新旧 IMU 同环境对比 + 交算法评估**已补强证据链，比"大概符合规律"有力得多。仍建议准备量化：静止零偏数值、转动极性、数据率、新旧输出差异量级。面试若问"精度满足要求的判定标准"，需能说出结论。

**题 12（蜂鸣器勿扰）**：Flash 标志位写入/读取时机？擦写寿命？算法板与主板切换时序？

- **候选人回答**：mute 标志更新条件：音量 0 或使能位 0；mute 变化时写 Flash；开机发声前读 Flash。用户不频繁开关，不考虑擦写寿命。**难点**：嵌入式不直接收 app 消息，只收算法板指令，但算法板正常关机前会发"使能 + 音量100"，即使 app 已开静音 → 会把 mute 标志重新置位回去，无法写入。**解决**：与算法组协调，算法出特调版本——开启静音后持续发"失能标志"直到彻底关机，嵌入式据此写 Flash 标记静音已开启。发现算法板行为与描述不符是**通过串口打印调试**定位的。
- **面试官批注**：✅ 真实跨组协作案例，有含金量（发现对方未声明行为、协议对齐、串口定位）。⚠️ 表达较"意识流"，建议整理成 STAR：现象（勿扰下开关机仍有声）→ 分析（mute 被关机前指令重置）→ 排查（串口打印发现算法板关机前仍发使能+音量100）→ 解决（协调算法特调持续发失能标志）→ 结果。可追问：Flash 写中途掉电的数据完整性、写失败回退。

**题 12 · STAR 优化稿（2026-08-04，面试口述版，1 分钟内）**

> **背景/任务**：割草机器人蜂鸣器由算法板下发指令控制，主板不主动发声。需求是"勿扰模式下整机全程静音，包括开关机提示音"。
>

> **结果**：实现勿扰模式下开关机全程静音；发现并修正了与算法板之间的协议理解偏差，沉淀跨组板间通信联调经验。

## 第 4 轮 · 第 1 部分：C 语言细节（已答 2026-08-04）

**题 14（数组 vs 指针）**：`char a[10]; char *p = a;` 的 sizeof？数组名与指针区别？何时退化？

- **候选人回答**：a 为 10B，p 为 4B。sizeof 数组=整个数组大小，sizeof 指针=指针大小。"数组相当于一个 const pointer"（"使用数组第一个元素的时候"——句子未说完）。
- **面试官批注**：✅ 数值对。⚠️ "数组相当于 const pointer"表述**不严谨且自相矛盾**——若真是指针常量，sizeof(a) 应是指针大小（4）而非 10。正确表述：`a` 的类型是 `char[10]`（sizeof 取整段）；作为函数参数/表达式使用时**退化为指向首元素的指针**；`&a` 的类型是 `char(*)[10]`。面试官必追问"那为什么 sizeof(a)=10"。

**题 15（结构体对齐）**：`struct { char a; uint32_t b; uint16_t c; }` sizeof？为什么对齐？重排省多少？位域？

- **候选人回答**：12B；按最大 4 字节对齐；提高访问速率；"重排省一个字节"；位域对齐不清楚。
- **面试官批注**：✅ sizeof=12 对（1+3pad+4+2+2pad）。❌ **重排省字节算错**：`char,uint16_t,uint32_t` 重排后 8B，省 **4B** 不是 1B。位域需补：按位连续存放，跨字节边界与类型/字节序相关，不同编译器行为可能不同。

**题 16（宏陷阱）**：`SQUARE(a+1)`？怎么改？宏 vs inline？

- **候选人回答**：a+1*a+1 = 2a+1；没括号保证优先级；改 `((x)*(x))`；宏难调试、易优先级问题；inline 直接展开、以函数方式运行、不易触发优先级问题；"对应的坑不太了解"。
- **面试官批注**：✅ 主因对、修法对。❌ 缺宏最大坑之一：**参数多次求值**（`SQUARE(i++)` 会 ++ 两次，副作用）；宏**无类型检查**。static inline 有类型检查、参数只求值一次。面试官爱举 `SQUARE(i++)` 让你算。

**题 17（volatile / const）**：volatile 必用场景？三种 const 指针组合？volatile const 组合？

- **候选人回答**："跨文件调用、中断里调用、需要防止编译器优化"；const int *p 与 int const *p 一样（指向的值不能变）；int *const p（指针不能变，指向值可变）；场景没想到。
- **面试官批注**：⚠️ const 指针组合答对。❌ volatile 场景答偏："跨文件调用"与 volatile 无关（那是 extern）；volatile 三大场景：① 硬件寄存器映射；② ISR 与主程序共享变量；③ RTOS 任务间共享变量。❌ 没想出场景——嵌入式标准答案：`const volatile uint32_t *REG = (uint32_t*)0x40000000;`（const 防误写、volatile 防被优化掉）。

**题 18（链表）**：单链表反转 + 删除已知节点。

- **候选人回答**：反转（迭代三指针 prev/curr/nexttemp）代码完全正确。删除已知节点描述："创建临时节点…让前一个节点的下一节点指向临时节点的下一节点…free"——❌ 未体现 O(1) 值拷贝技巧。
- **面试官批注**：✅ 反转满分。❌ 删除题：题设只给 `p`（非尾、无前驱），O(1) 标准解是**值拷贝 + 删后继**：`p->val = p->next->val; p->next = p->next->next;` 再 free 后继。你的描述需要前驱节点，不符合题设 O(1)。若删尾节点则必须遍历找前驱。这是手撕高频变体，务必记住值拷贝技巧。

## 第 4 轮 · 第 2 部分：STM32 启动/中断（部分已答 2026-08-04）

**题 19（STM32 启动过程）**：上电后 CPU 从哪里执行？向量表第一项？SP 谁设？Reset_Handler 做什么？复位到 main 之间？

- **候选人回答**：上电后 CPU 一般从 flash 开始执行；向量表第一项是主堆栈 MSP，**"第一步就是将 msp 存入 pc"**；Reset_Handler 中：① 将初值从 flash 拷贝到 .data、.bss 清零；② 初始化时钟；③ 初始化 C 库；④ 进入 __main；⑤ 进入 main。
- **面试官批注**：⚠️ 框架对，但两个关键细节错：❌ **"MSP 存入 PC"概念反了**——向量表第一项（偏移 0）是**初始 MSP 值**，复位后由硬件自动装载到 SP；向量表**第二项（偏移 4）是 Reset_Handler 入口地址**，装载到 PC。❌ **.data 拷贝/.bss 清零不是 Reset_Handler 直接做的**，而是 __main（C 启动代码/SCatterload）完成；标准顺序：复位 → 取 MSP、取 Reset_Handler 地址 → SystemInit（时钟）→ __main（拷贝 .data、清 .bss、初始化 C 库）→ main。题 19 为简历"熟悉启动过程"直接背书，务必记准。

**题 20（中断）**：ISR vs 普通函数？ISR 为什么不能做耗时/不可重入操作？临界区怎么实现？关中断代价？NVIC 优先级？

- **候选人回答**：中断能打断正在运行的函数；① 耗时、② **不可重入**；临界区通过**提高 BASEPRI 值**实现关中断，关的是 FreeRTOSConfig 中配置的可屏蔽中断优先级以下的中断，**更高优先级中断仍能正常进入**；关太久影响其他程序运行、尤其在 RTOS 中严重影响实时性；抢占优先级高的能抢占低的，同优先级下子优先级高的先执行。
- **面试官批注**：✅ 答得专业——"ISR 不可重入"（printf 被中断打断会乱）和 **BASEPRI 屏蔽 + configMAX_SYSCALL_INTERRUPT_PRIORITY 保留高优先级中断** 是 FreeRTOS 面试加分点。⚠️ 子优先级表述需精确：同抢占优先级下子优先级决定**排队响应顺序**，不用于抢占；Cortex-M 优先级**数值越小优先级越高**。

**题 21（FreeRTOS 互斥量优先级继承原理）**：数据结构差异？优先级继承谁继承谁、何时继承/恢复？多把锁？

- **候选人回答**：互斥量有持有者和递归量；优先级继承=高优先级获取低优先级持有的锁时，低优先级临时提高到与高优先级相同；继承发生在 lock 时（进入临界区时）；获取完锁后恢复；"多把互斥量时不清楚"。
- **面试官批注**：⚠️ 继承时机答对（take/lock 提升、give/释放后恢复）✅。需精确三点：① **数据结构**：互斥量比二值信号量多**持有者字段（pxMutexHolder 指向持有任务 TCB）**；"递归量"是另一类（递归互斥量，带 uxRecursiveCallCount），别混。② **源码位置**：继承发生在 take 失败进阻塞时——`xQueueSemaphoreTake`/`xQueueGenericReceive` 检查持有者优先级并 `vTaskPrioritySet` 提升；give（`xQueueGenericSend`）时若提升过则恢复为 TCB 记录的 `uxBasePriority`。③ **多把锁**：TCB 记录提升后的最高优先级，释放第一把锁不立即恢复，全部释放后才回到基础优先级。关键区分：**二值信号量无持有者、无优先级继承**——用它保护资源时反转无解。
