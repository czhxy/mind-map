# 阶段一：长度与拷贝

## 1. 手写 `my_strlen` ★☆☆

**考察**：指针遍历、`const`、返回类型为什么是 `size_t`

### 要求

实现 `my_strlen`，功能与标准库 `strlen` 一致：返回字符串长度，不含结尾 `'\0'`。

```c
size_t my_strlen(const char *s);
```

### 提示

- 参数为什么是 `const char *`？——不修改入参，让编译器帮你检查。
- 除了逐字节计数，能不能用「指针相减」一次算出长度？
- `size_t` 是无符号类型，想清楚这对第 33 题的坑有什么影响。

<details>
<summary>参考答案 + 测试用例</summary>

```c
#include <stdio.h>
#include <string.h>
#include <stddef.h>

/* 指针差值版：编译器更容易优化成单条指令，也是标准库常见写法 */
size_t my_strlen(const char *s)
{
    const char *p = s;
    while (*p != '\0') {
        p++;
    }
    return (size_t)(p - s);
}

/* 递归版（仅用于理解，嵌入式里会爆栈，别用） */
size_t my_strlen_rec(const char *s)
{
    return (*s == '\0') ? 0 : 1 + my_strlen_rec(s + 1);
}

int main(void)
{
    CHECK(my_strlen("") == 0);
    CHECK(my_strlen("a") == 1);
    CHECK(my_strlen("hello") == 5);
    CHECK(my_strlen("hello") == strlen("hello"));
    CHECK(my_strlen_rec("hello") == 5);

    /* 中间有 '\0' 的数组：strlen 到第一个 '\0' 就停 */
    char buf[8] = { 'a', 'b', '\0', 'c', 'd', 'e', 'f', 'g' };
    CHECK(my_strlen(buf) == 2);

    /* 中文是按字节算的，一个 UTF-8 汉字 3 字节 */
    CHECK(my_strlen("中文") == 6);

    REPORT();
    return 0;
}
```

**要点**
- 返回 `size_t` 而不是 `int`：长度理论上可以超过 `INT_MAX`。
- 不能写成 `while (*p++)`，那样会多走一格（把 `'\0'` 也算了进去）。
- 递归版每次调用都要压栈，`my_strlen_rec` 对长字符串会栈溢出。

</details>

## 2. 手写 `my_strcpy` ★☆☆

**考察**：`while` 赋值表达式的惯用写法、返回目标指针的作用

### 要求

```c
char *my_strcpy(char *dst, const char *src);
```

返回到 `dst` 起始位置，而不是结尾——这样才能支持链式调用：

```c
strcpy(strcat(a, b), c);
```
如果 `strcpy` 返回的是结尾指针，上面这个链式调用就错了。

### 提示

标准库的经典两行写法利用了「赋值表达式的值就是被赋的值」这个特性。

<details>
<summary>参考答案 + 测试用例</summary>

```c
#include <stdio.h>
#include <string.h>

char *my_strcpy(char *dst, const char *src)
{
    char *ret = dst;                       /* 先存下来，最后返回 */
    while ((*dst++ = *src++) != '\0') {
        ;                                  /* 空循环体 */
    }
    return ret;
}

/* 拆开写的等价版本，逻辑更直观 */
char *my_strcpy_v2(char *dst, const char *src)
{
    char *ret = dst;
    while (*src != '\0') {
        *dst++ = *src++;
    }
    *dst = '\0';                           /* 别忘了补结尾 */
    return ret;
}

int main(void)
{
    char buf[16];

    CHECK(strcmp(my_strcpy(buf, "hello"), "hello") == 0);
    CHECK(buf[5] == '\0');
    CHECK(my_strcpy(buf, "") != NULL && buf[0] == '\0');
    CHECK(strcmp(my_strcpy(buf, "hello"), buf) == 0);   /* 返回的是起始位置 */

    /* 链式调用：返回值是目标串起始位置 */
    char a[32] = "foo";
    CHECK(strcmp(strcat(a, "bar"), "foobar") == 0);

    REPORT();
    return 0;
}
```

**要点**
- `*dst++ = *src++` 的执行顺序：先取值、再自增，赋值表达式的值是「写入的那个字符」。
- 返回 `dst` 的**起始**地址，`ret` 必须在循环前保存。
- 这个函数**没有任何长度检查**——`src` 比 `dst` 长就溢出，这就是它在嵌入式里被嫌弃的原因。

</details>

## 3. 手写 `my_strncpy` ★★☆

**考察**：本题是整份练习里最容易踩坑的函数，务必吃透

### 要求

```c
char *my_strncpy(char *dst, const char *src, size_t n);
```

标准库 `strncpy` 的语义**不是**「安全版 strcpy」，而是：

1. 最多从 `src` 拷 `n` 个字符；
2. 如果 `src` 不足 `n` 个字节，**剩下的全部用 `'\0'` 填满**；
3. **如果 `src` 长度 ≥ `n`，则一个 `'\0'` 都不写**。

请在实现中还原这套行为，并在测试里验证第 3 条。

### 提示

循环条件要同时判断 `n > 0` 和 `*src != '\0'`，之后再单独补 `'\0'`。

<details>
<summary>参考答案 + 测试用例</summary>

```c
#include <stdio.h>
#include <string.h>

char *my_strncpy(char *dst, const char *src, size_t n)
{
    char *ret = dst;

    /* 第 1 步：拷贝，直到 src 结束或已拷满 n 个 */
    while (n > 0 && *src != '\0') {
        *dst++ = *src++;
        n--;
    }
    /* 第 2 步：src 比 n 短，剩余位置全部填 '\0' */
    while (n > 0) {
        *dst++ = '\0';
        n--;
    }
    /* 注意：若第 1 步是因为 n==0 退出的，这里什么都不做 —— 目标串无结尾符 */
    return ret;
}

int main(void)
{
    char buf[16];

    /* case 1: src 比 n 短 —— 后面补齐 '\0' */
    memset(buf, 'X', sizeof(buf));
    my_strncpy(buf, "hi", 6);
    CHECK(memcmp(buf, "hi\0\0\0\0", 6) == 0);
    CHECK(buf[6] == 'X');              /* 第 7 个字节不动 */

    /* case 2: src 正好 n 长 —— 不补 '\0' */
    memset(buf, 'X', sizeof(buf));
    my_strncpy(buf, "hello", 5);
    CHECK(memcmp(buf, "hello", 5) == 0);
    CHECK(buf[5] == 'X');              /* ★ 坑：没有结尾符！ */

    /* case 3: src 比 n 长 —— 截断，且仍不补 '\0' */
    memset(buf, 'X', sizeof(buf));
    my_strncpy(buf, "hello world", 5);
    CHECK(memcmp(buf, "hello", 5) == 0);
    CHECK(buf[5] == 'X');              /* ★ 同样没有结尾符 */

    /* case 4: n == 0 —— 什么都不做 */
    memset(buf, 'X', sizeof(buf));
    my_strncpy(buf, "hello", 0);
    CHECK(buf[0] == 'X');

    /* 对照组：和标准库行为一致。
       ★ 注意上面这行 strncpy 会触发 -Wstringop-truncation 警告：
         "output truncated copying 5 bytes from a string of length 11"
         这正是本题要讲的坑，编译器在提醒你"没写结尾符"。警告是预期的，不用改。 */
    char a[16], b[16];
    memset(a, 'X', sizeof(a)); memset(b, 'X', sizeof(b));
    my_strncpy(a, "hello world", 5);
    strncpy(b, "hello world", 5);
    CHECK(memcmp(a, b, 16) == 0);

    REPORT();
    return 0;
}
```

**要点**
- **只有 `src` 短于 `n` 时才保证有 `'\0'`**。所以直接用 `strncpy` 之后必须自己补：
  ```c
  strncpy(dst, src, sizeof(dst));
  dst[sizeof(dst) - 1] = '\0';       /* 必须加这一行 */
  ```
- 还有一个性能坑：`src` 很短时它会把整个缓冲区填满 `'\0'`，对大缓冲区是白干的活。
  嵌入式里嫌费时间，通常会自己写个只拷不填的版本。
- 因为上面两个原因，`strncpy` 在嵌入式安全编码规范里常被**禁用**（MISRA 也是这个态度）。

</details>

## 4. 手写 `my_strcat` 与 `my_strncat` ★★☆

**考察**：定位串尾、`strncat` 的空间需求

### 要求

```c
char *my_strcat(char *dst, const char *src);
char *my_strncat(char *dst, const char *src, size_t n);
```

`strncat` 的语义和 `strncpy` **不一样**，它是安全的：最多追加 `n` 个字符，**且一定补 `'\0'`**。

### 提示

- `dst` 必须以 `'\0'` 结尾才能用（否则找不到串尾）。
- 想清楚 `strncat` 最坏情况需要给 `dst` 留多少空间。

<details>
<summary>参考答案 + 测试用例</summary>

```c
#include <stdio.h>
#include <string.h>

char *my_strcat(char *dst, const char *src)
{
    char *ret = dst;
    while (*dst != '\0') {      /* 先走到 dst 的结尾 */
        dst++;
    }
    while ((*dst++ = *src++) != '\0') {   /* 再从结尾往后拷 */
        ;
    }
    return ret;
}

char *my_strncat(char *dst, const char *src, size_t n)
{
    char *ret = dst;
    while (*dst != '\0') {
        dst++;
    }
    while (n > 0 && *src != '\0') {
        *dst++ = *src++;
        n--;
    }
    *dst = '\0';                /* ★ 一定补结尾，这是与 strncpy 的关键区别 */
    return ret;
}

int main(void)
{
    char buf[32];

    strcpy(buf, "foo");
    CHECK(strcmp(my_strcat(buf, "bar"), "foobar") == 0);

    strcpy(buf, "");
    CHECK(strcmp(my_strcat(buf, "abc"), "abc") == 0);

    strcpy(buf, "abc");
    CHECK(strcmp(my_strcat(buf, ""), "abc") == 0);   /* 追加空串 */

    /* strncat 追加 n 个 */
    strcpy(buf, "foo");
    CHECK(strcmp(my_strncat(buf, "barbaz", 3), "foobar") == 0);
    CHECK(buf[6] == '\0');

    /* src 比 n 短，只追加实际长度 */
    strcpy(buf, "foo");
    CHECK(strcmp(my_strncat(buf, "b", 10), "foob") == 0);
    CHECK(buf[4] == '\0');

    /* ★ 空间需求：strlen("foo") + n + 1 = 3 + 5 + 1 = 9 */
    char small[9];
    strcpy(small, "foo");
    my_strncat(small, "12345678", 5);      /* 最多用满 small[8] 的 '\0' */
    CHECK(strcmp(small, "foo12345") == 0);

    REPORT();
    return 0;
}
```

**要点**
- `strncat` 最坏需要 `strlen(dst) + n + 1` 字节。只按 `n` 申请缓冲是常见溢出源。
- 和 `strncpy` 对比记忆：
  | | 截断时补 `'\0'` 吗 | 短于 n 时填满吗 |
  |---|---|---|
  | `strncpy` | **不补** | 填满 |
  | `strncat` | **补** | 不填 |
- `strcat` 每次都要从头找串尾，循环里反复 `strcat` 拼串是 O(n²)，拼接大量数据时自己维护一个写指针。

</details>

## 5. 实现安全拷贝 `my_strlcpy` + 截断检测 ★★☆

**考察**：为什么要自己造轮子、返回值语义

### 要求

`strlcpy` 不在 C 标准里（BSD 有，glibc 没有），嵌入式安全编码里常自己实现一份。

```c
/* 返回 (size_t)-1 表示成功；否则返回被截断的字符数（>0） */
size_t my_strlcpy(char *dst, const char *src, size_t size);
```

**推荐语义**（这次不照抄 BSD 的返回值，用更适合嵌入式报错的设计）：

- `size == 0`：不做任何写入，返回源串长度 + 1（表示空间不够）；
- 正常：最多写 `size - 1` 个字符，**必定补 `'\0'`**；
- 如果发生截断，返回「被丢弃的字符数 + 1」，调用方据此上报错误。

### 提示

先算 `strlen(src)`，再决定拷几个字节，比边拷边判断更好写。

<details>
<summary>参考答案 + 测试用例</summary>

```c
#include <stdio.h>
#include <string.h>
#include <stddef.h>

size_t my_strlcpy(char *dst, const char *src, size_t size)
{
    size_t srclen = strlen(src);

    if (size == 0) {
        return srclen + 1;              /* 一个字节都没写 */
    }

    if (srclen >= size) {
        /* 装不下：拷 size-1 个字符 + '\0'，返回丢弃的字符数 + 1 */
        memcpy(dst, src, size - 1);
        dst[size - 1] = '\0';
        return srclen - (size - 1) + 1;
    }

    memcpy(dst, src, srclen + 1);       /* 连 '\0' 一起拷 */
    return 0;                           /* 0 表示完全放下、无截断 */
}

int main(void)
{
    char buf[8];

    /* 正常放下，返回 0 */
    CHECK(my_strlcpy(buf, "hi", sizeof(buf)) == 0);
    CHECK(strcmp(buf, "hi") == 0);

    /* 边界：正好放下 "1234567"（7 字符 + '\0' = 8） */
    CHECK(my_strlcpy(buf, "1234567", sizeof(buf)) == 0);
    CHECK(strcmp(buf, "1234567") == 0);

    /* 截断：需要 8+1=9 字节，只剩 7 字符可写，丢 1 个字符 → 返回 1+1=2 */
    CHECK(my_strlcpy(buf, "12345678", sizeof(buf)) == 2);
    CHECK(strcmp(buf, "1234567") == 0);
    CHECK(buf[7] == '\0');              /* ★ 保证有结尾符 */

    /* 极端截断：size=1 时只能写个 '\0' */
    char one[1];
    CHECK(my_strlcpy(one, "abc", 1) == 4);   /* 3 - 0 + 1 */
    CHECK(one[0] == '\0');

    /* size == 0 不写 */
    CHECK(my_strlcpy(buf, "abc", 0) == 4);
    CHECK(buf[7] == '\0');              /* 内容未被破坏 */

    /* 空串 */
    CHECK(my_strlcpy(buf, "", sizeof(buf)) == 0);
    CHECK(buf[0] == '\0');

    REPORT();
    return 0;
}
```

**要点**
- 唯一**保证**补 `'\0'` 的拷贝函数，所以它是嵌入式里替代 `strcpy`/`strncpy` 的首选。
- 返回值设计成「能报错」而不是照抄 BSD，因为嵌入式里静默截断很危险——比如 MQTT topic 被截断会导致发错主题。
- 若想完全兼容 BSD 语义，改成 `return srclen;`，调用方用 `ret >= size` 判断截断。

</details>

## 6. 手写 `my_strcmp` 与 `my_strncmp` ★★☆

**考察**：比较的返回值语义、`unsigned char` 转换的原因

### 要求

```c
int my_strcmp(const char *s1, const char *s2);
int my_strncmp(const char *s1, const char *s2, size_t n);
```

返回：`<0` 表示 `s1 < s2`，`0` 表示相等，`>0` 表示 `s1 > s2`。
**不要求**返回具体的字符差值，只要求符号正确。

### 提示

- 为什么用 `unsigned char` 而不是 `char`？想想中文字节（≥ 0x80）在 `char` 带符号时会被当成负数。
- 循环终止条件要同时考虑「字符不相等」和「遇到结尾符」。

<details>
<summary>参考答案 + 测试用例</summary>

```c
#include <stdio.h>
#include <string.h>

int my_strcmp(const char *s1, const char *s2)
{
    while (*s1 != '\0' && *s1 == *s2) {
        s1++;
        s2++;
    }
    /* ★ 必须转成 unsigned char：否则 ARM 上 char 默认带符号，
       0x80 及以上的字节会被当成负值，导致 "中" > "a" 这类比较出错 */
    return (int)(unsigned char)*s1 - (int)(unsigned char)*s2;
}

int my_strncmp(const char *s1, const char *s2, size_t n)
{
    while (n > 0 && *s1 != '\0' && *s1 == *s2) {
        s1++;
        s2++;
        n--;
    }
    if (n == 0) {
        return 0;                       /* 前 n 个字符全相等 */
    }
    return (int)(unsigned char)*s1 - (int)(unsigned char)*s2;
}

int main(void)
{
    CHECK(my_strcmp("", "") == 0);
    CHECK(my_strcmp("abc", "abc") == 0);
    CHECK(my_strcmp("abc", "abd") < 0);
    CHECK(my_strcmp("abd", "abc") > 0);
    CHECK(my_strcmp("abc", "ab") > 0);      /* 前缀更短则更小 */
    CHECK(my_strcmp("ab", "abc") < 0);
    CHECK(my_strcmp("a", "") > 0);

    /* 符号必须和标准库一致 */
    const char *cases[][2] = {
        { "", "" }, { "a", "b" }, { "b", "a" }, { "abc", "ab" },
        { "Z", "a" }, { "hello", "hello world" }, { "\x80", "a" },
    };
    for (size_t i = 0; i < sizeof(cases) / sizeof(cases[0]); i++) {
        int mine = my_strcmp(cases[i][0], cases[i][1]);
        int std  = strcmp(cases[i][0], cases[i][1]);
        CHECK((mine == 0) == (std == 0));
        CHECK((mine < 0) == (std < 0));
        CHECK((mine > 0) == (std > 0));
    }

    /* ---- strncmp ---- */
    CHECK(my_strncmp("abc", "abd", 2) == 0);   /* 只比前 2 个，相等 */
    CHECK(my_strncmp("abc", "abd", 3) < 0);
    CHECK(my_strncmp("abc", "abc", 100) == 0); /* n 超过长度，比到 '\0' 为止 */
    CHECK(my_strncmp("abc", "abd", 0) == 0);   /* n == 0 恒相等 */
    CHECK(my_strncmp("ab", "abc", 3) < 0);

    REPORT();
    return 0;
}
```

**要点**
- `(unsigned char)` 转换是**必须**的，不是可选的风格问题。`strcmp` 的标准定义明确要求按 `unsigned char` 比较。
- `strncmp` 遇到 `'\0'` 会提前结束，不需要真的比满 `n` 个字符。
- 用它做前缀判断很方便：`strncmp(s, "AT+", 3) == 0`（第 26 题会用到）。

</details>

## 7. 手写 `my_strchr` 与 `my_strrchr` ★☆☆

**考察**：查找 `'\0'` 的特殊语义、指针返回值的意义

### 要求

```c
char  *my_strchr(const char *s, int c);
char  *my_strrchr(const char *s, int c);
```

**注意一个反直觉的规范**：`strchr(s, '\0')` 返回的是**指向串尾 `'\0'` 的指针**，不是 `NULL`。原因是 `strchr(s, '\0')` 总是"能找到"。请实现这个行为。

### 提示

参数是 `int c` 而不是 `char`，因为标准库是这么定义的，传入的 `int` 会被转成 `char` 再比较。

<details>
<summary>参考答案 + 测试用例</summary>

```c
#include <stdio.h>
#include <string.h>

char *my_strchr(const char *s, int c)
{
    char ch = (char)c;
    while (*s != '\0') {
        if (*s == ch) {
            return (char *)s;           /* 丢掉 const，标准库签名如此 */
        }
        s++;
    }
    /* ★ 查 '\0' 时返回结尾位置，而不是 NULL */
    return (ch == '\0') ? (char *)s : NULL;
}

char *my_strrchr(const char *s, int c)
{
    const char *last = NULL;
    char ch = (char)c;

    /* do-while：保证连结尾的 '\0' 也会被检查一次 */
    do {
        if (*s == ch) {
            last = s;
        }
    } while (*s++ != '\0');

    return (char *)last;
}

int main(void)
{
    const char *s = "hello world";

    CHECK(my_strchr(s, 'o') == s + 4);
    CHECK(my_strrchr(s, 'o') == s + 7);
    CHECK(my_strchr(s, 'z') == NULL);
    CHECK(my_strrchr(s, 'z') == NULL);
    CHECK(my_strchr(s, 'h') == s);
    CHECK(my_strchr(s, '\0') == s + 11);    /* ★ 返回串尾，不是 NULL */
    CHECK(my_strrchr(s, '\0') == s + 11);

    /* 和标准库对齐 */
    CHECK(my_strchr(s, '\0') == strchr(s, '\0'));
    CHECK(my_strchr("aaa", 'a') == strchr("aaa", 'a'));
    CHECK(my_strrchr("aaa", 'a') == strrchr("aaa", 'a'));

    /* 常见用法：定位 '.' 取扩展名 */
    char path[] = "config.bin";
    char *dot = my_strrchr(path, '.');
    CHECK(dot != NULL && strcmp(dot, ".bin") == 0);

    /* strrchr 找路径最后一个 '/' */
    char p2[] = "/etc/net/cfg.ini";
    char *slash = my_strrchr(p2, '/');
    CHECK(strcmp(slash, "/cfg.ini") == 0);

    REPORT();
    return 0;
}
```

**要点**
- `strchr` 查 `'\0'` 返回串尾这个特性，实际用得上的场景是：
  `char *end = strchr(s, '\0');` 拿到串尾指针，然后从后面往回填字符（避免每次 `strcat` 都重新扫一遍）。
- `strrchr` 里的 `do-while` 是必须的：如果写成 `while (*s)`，就永远检查不到结尾的 `'\0'`。
- 返回 `char *` 但入参是 `const char *`，所以实现里需要 `(char *)` 强转——这是标准库的历史遗留，C++ 里因此专门重载了 const 版本。

</details>

## 8. 手写 `my_strstr`（朴素实现）★★☆

**考察**：双层循环、空模式串的约定、时间复杂度

### 要求

在 `haystack` 中查找 `needle` 首次出现的位置，返回指向该位置的指针；找不到返回 `NULL`。

**约定**：`needle` 为空串时返回 `haystack`（标准库行为）。

### 提示

外层遍历每个可能的起点，内层逐个字符比对。注意内层比较失败的判断方式——是比到 `needle` 结束（成功），还是比到中途不等（失败）。

<details>
<summary>参考答案 + 测试用例</summary>

```c
#include <stdio.h>
#include <string.h>

char *my_strstr(const char *haystack, const char *needle)
{
    if (*needle == '\0') {
        return (char *)haystack;        /* 空模式串：约定返回原串 */
    }

    for (; *haystack != '\0'; haystack++) {
        const char *h = haystack;
        const char *n = needle;

        while (*h != '\0' && *n != '\0' && *h == *n) {
            h++;
            n++;
        }
        if (*n == '\0') {
            return (char *)haystack;    /* needle 走到结尾 → 匹配成功 */
        }
        /* 注意：这里不需要单独判断失败，内层退出后继续下一轮即可 */
    }
    return NULL;
}

int main(void)
{
    CHECK(my_strstr("hello world", "world") != NULL);
    CHECK(strcmp(my_strstr("hello world", "world"), "world") == 0);
    CHECK(my_strstr("hello world", "hello") != NULL);
    CHECK(my_strstr("hello world", "o w") != NULL);
    CHECK(my_strstr("hello", "z") == NULL);
    CHECK(my_strstr("hello", "hello!") == NULL);   /* 模式串比原串长 */
    CHECK(my_strstr("", "a") == NULL);
    CHECK(my_strstr("hello", "") != NULL);         /* 空模式串 */

    /* 部分匹配后失配，经典场景：指针必须回退重新比 */
    CHECK(my_strstr("aabababc", "ababc") != NULL); /* 坑：aa 开头的误匹配 */
    CHECK(strcmp(my_strstr("aabababc", "ababc"), "ababc") == 0);
    CHECK(my_strstr("aaaaab", "aab") != NULL);
    CHECK(my_strstr("abcabcabc", "abcabc") != NULL);

    /* 与标准库对齐 */
    const char *hs[] = { "hello world", "", "aaa", "abab", "x" };
    const char *ns[] = { "o", "world", "", "a", "ab", "b", "z", "abab", "x" };
    for (size_t i = 0; i < sizeof(hs) / sizeof(hs[0]); i++) {
        for (size_t j = 0; j < sizeof(ns) / sizeof(ns[0]); j++) {
            CHECK(my_strstr(hs[i], ns[j]) == strstr(hs[i], ns[j]));
        }
    }

    REPORT();
    return 0;
}
```

**要点**
- 时间复杂度 **O((n-m+1) × m)**，最坏情况（`"aaaaaab"` 找 `"aab"`）每次都白比一遍。
  每失配一次就回退一个字符重新来，这就是 KMP 要解决的问题（下一题）。
- 内层退出后判断 `*n == '\0'` 而不是 `*h == '\0'`——这两个含义完全不同，写反了会漏掉「模式串正好到原串结尾」的情况。
- 实际项目里如果只是找一次短模式串，朴素算法够用且代码小；要频繁查找才值得上 KMP/BM。

</details>

## 9. KMP 算法（进阶选做）★★★

**考察**：`next` 数组的构造、失配后指针不回退

### 要求

用 KMP 实现子串查找，返回下标（找不到返回 `-1`）：

```c
int kmp_search(const char *text, const char *pat);
```

KMP 的核心是**预处理模式串**，得到一个 `next` 数组，失配时根据它决定模式串指针回退到哪，而**文本指针永不回退**。

### 提示

定义 `next[i]` = 子串 `pat[0..i]` 的**最长相等前后缀**长度。

例：`pat = "ababaca"`

| i | pat[0..i] | 最长相等前后缀 | next[i] |
|---|---|---|---|
| 0 | `a` | 无（规定） | 0 |
| 1 | `ab` | 无 | 0 |
| 2 | `aba` | `a` | 1 |
| 3 | `abab` | `ab` | 2 |
| 4 | `ababa` | `aba` | 3 |
| 5 | `ababac` | 无 | 0 |
| 6 | `ababaca` | `a` | 1 |

失配时的处理：`j = next[j-1]`，直到 `j == 0` 或字符匹配。

<details>
<summary>参考答案（附朴素对照与正确性验证）</summary>

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

/* 构造 next 数组：next[i] = pat[0..i] 的最长相等前后缀长度 */
static void kmp_build_next(const char *pat, int len, int *next)
{
    next[0] = 0;
    int j = 0;                          /* j: 当前已匹配的前缀长度 */

    for (int i = 1; i < len; ) {
        if (pat[i] == pat[j]) {
            next[i] = ++j;              /* 匹配成功，前后缀加长 */
            i++;
        } else if (j > 0) {
            j = next[j - 1];            /* ★ 失配：回退到次长前后缀，i 不动 */
        } else {
            next[i] = 0;                /* j 已到 0，只能置 0 */
            i++;
        }
    }
}

int kmp_search(const char *text, const char *pat)
{
    int n = (int)strlen(text);
    int m = (int)strlen(pat);

    if (m == 0) return 0;               /* 空模式串约定返回 0 */
    if (n < m)  return -1;

    int *next = (int *)malloc(sizeof(int) * (size_t)m);
    if (next == NULL) return -1;
    kmp_build_next(pat, m, next);

    int j = 0;                          /* j: 模式串已匹配长度 */
    int ans = -1;
    for (int i = 0; i < n; ) {
        if (text[i] == pat[j]) {
            i++;
            j++;
            if (j == m) {               /* 匹配完成，返回首次出现位置 */
                ans = i - m;
                break;
            }
        } else if (j > 0) {
            j = next[j - 1];            /* ★ text 指针 i 不回退 */
        } else {
            i++;
        }
    }

    free(next);
    return ans;
}

/* 对照用朴素实现，验证 KMP 结果 */
static int naive_search(const char *text, const char *pat)
{
    int n = (int)strlen(text), m = (int)strlen(pat);
    if (m == 0) return 0;
    for (int i = 0; i + m <= n; i++) {
        if (memcmp(text + i, pat, (size_t)m) == 0) return i;
    }
    return -1;
}

int main(void)
{
    CHECK(kmp_search("ababaca", "ababaca") == 0);
    CHECK(kmp_search("", "") == 0);
    CHECK(kmp_search("abc", "") == 0);
    CHECK(kmp_search("", "a") == -1);
    CHECK(kmp_search("hello world", "world") == 6);
    CHECK(kmp_search("hello world", "o w") == 4);
    CHECK(kmp_search("hello", "z") == -1);
    CHECK(kmp_search("aaaaaab", "aab") == 4);      /* 朴素算法的最坏情况 */
    CHECK(kmp_search("aabababc", "ababc") == 3);   /* "aab|ababc" → 下标 3 */
    CHECK(kmp_search("abcabcabcd", "abcabcd") == 3);

    /* next 数组构造是否正确 */
    int next[8];
    kmp_build_next("ababaca", 7, next);
    int expect[7] = { 0, 0, 1, 2, 3, 0, 1 };
    for (int i = 0; i < 7; i++) {
        CHECK(next[i] == expect[i]);
    }

    /* 随机对照验证 */
    srand(12345);
    char text[64], pat[8];
    for (int t = 0; t < 2000; t++) {
        int nl = 1 + rand() % 20, ml = 1 + rand() % 5;
        for (int i = 0; i < nl; i++) text[i] = (char)('a' + rand() % 3);
        text[nl] = '\0';
        for (int i = 0; i < ml; i++) pat[i] = (char)('a' + rand() % 3);
        pat[ml] = '\0';
        CHECK(kmp_search(text, pat) == naive_search(text, pat));
    }

    REPORT();
    return 0;
}
```

**要点**
- 关键只有一句：**失配时 `i` 不回退，只动 `j`**。这就是 KMP 把最坏复杂度从 O(n·m) 降到 O(n+m) 的原因。
- 嵌入式里用 KMP 要权衡：需要 `malloc(m * sizeof(int))` 的额外空间，MCU 上通常改成**定长数组**（如模式串最长 16 字节就开 `int next[16]`），避免动态分配。
- 面试如果要求"不许用额外空间"，那就退化成朴素的双层循环（第 8 题），或者用 BM 的坏字符规则做简化版。

</details>

## 10. 统计子串出现次数 ★☆☆

**考察**：复用 `strstr`、重叠与不重叠的语义差别

### 要求

```c
/* 统计不重叠出现次数： "aaa" 里找 "aa" → 1 次（不是 2 次） */
int count_substr(const char *s, const char *sub);

/* 统计重叠出现次数： "aaa" 里找 "aa" → 2 次 */
int count_substr_overlap(const char *s, const char *sub);
```

### 提示

不重叠版每次找到后指针前进 `strlen(sub)`；重叠版每次只前进 1。

<details>
<summary>参考答案 + 测试用例</summary>

```c
#include <stdio.h>
#include <string.h>

/* 不重叠：找到后跳过整个 sub */
int count_substr(const char *s, const char *sub)
{
    size_t n = strlen(sub);
    int cnt = 0;

    if (n == 0) {
        return 0;                       /* 空模式串约定不计 */
    }
    while ((s = strstr(s, sub)) != NULL) {
        cnt++;
        s += n;
    }
    return cnt;
}

/* 重叠：找到后只前进 1 个字符 */
int count_substr_overlap(const char *s, const char *sub)
{
    size_t n = strlen(sub);
    int cnt = 0;

    if (n == 0) {
        return 0;
    }
    while ((s = strstr(s, sub)) != NULL) {
        cnt++;
        s += 1;                         /* ★ 只前进一步 */
    }
    return cnt;
}

int main(void)
{
    CHECK(count_substr("aaaa", "aa") == 2);           /* (aa)(aa) */
    CHECK(count_substr_overlap("aaaa", "aa") == 3);   /* aa,aa,aa */
    CHECK(count_substr("abcabcabc", "abc") == 3);
    CHECK(count_substr("hello", "z") == 0);
    CHECK(count_substr("hello", "hello") == 1);
    CHECK(count_substr("hello", "") == 0);
    CHECK(count_substr("", "a") == 0);

    CHECK(count_substr_overlap("aaa", "aa") == 2);
    CHECK(count_substr_overlap("ababab", "aba") == 2); /* aba, aba（重叠 b） */

    REPORT();
    return 0;
}
```

**要点**
- 两种语义**没有对错**，看业务需求：
  - 统计关键词出现次数（日志分析）→ 不重叠；
  - 基因序列 / 模式匹配 → 可能要求重叠。
- 空 `sub` 必须单独拦截，否则 `strstr` 会返回非 `NULL` 导致死循环。

</details>

## 11. 大小写转换与原地反转 ★☆☆

**考察**：`tolower`/`toupper` 的参数陷阱、双指针

### 要求

```c
void my_strupr(char *s);                       /* 原地转大写 */
void my_strlwr(char *s);                       /* 原地转小写 */
void my_strrev(char *s);                       /* 原地反转（就地，不用额外数组） */
```

### 提示

- `toupper`/`tolower` 的入参必须是 `unsigned char` 转换后的值，直接传 `char` 在中文/高位字节上会越界。
- `my_strrev` 用首尾双指针交换，循环条件 `while (left < right)`。

<details>
<summary>参考答案 + 测试用例</summary>

```c
#include <stdio.h>
#include <string.h>
#include <ctype.h>

void my_strupr(char *s)
{
    for (; *s != '\0'; s++) {
        /* ★ 必须转 unsigned char：当 char 带符号时，
           (char)0x80 会变成负数，传给 toupper 是未定义行为 */
        *s = (char)toupper((unsigned char)*s);
    }
}

void my_strlwr(char *s)
{
    for (; *s != '\0'; s++) {
        *s = (char)tolower((unsigned char)*s);
    }
}

void my_strrev(char *s)
{
    if (s == NULL) return;
    size_t len = strlen(s);
    if (len < 2) return;

    char *left  = s;
    char *right = s + len - 1;

    while (left < right) {
        char t = *left;
        *left++  = *right;
        *right-- = t;
    }
}

int main(void)
{
    char buf[32];

    strcpy(buf, "Hello, World 123!");
    my_strupr(buf);
    CHECK(strcmp(buf, "HELLO, WORLD 123!") == 0);

    my_strlwr(buf);
    CHECK(strcmp(buf, "hello, world 123!") == 0);

    strcpy(buf, "");
    my_strupr(buf); my_strlwr(buf);
    CHECK(buf[0] == '\0');              /* 空串不崩 */

    /* 反转 */
    strcpy(buf, "hello");
    my_strrev(buf);
    CHECK(strcmp(buf, "olleh") == 0);

    strcpy(buf, "a");
    my_strrev(buf);
    CHECK(strcmp(buf, "a") == 0);

    strcpy(buf, "");
    my_strrev(buf);
    CHECK(strcmp(buf, "") == 0);

    strcpy(buf, "ab");
    my_strrev(buf);
    CHECK(strcmp(buf, "ba") == 0);

    /* 也可用于数字转字符串的逆序（第 18 题会用到这个技巧） */
    strcpy(buf, "12345");
    my_strrev(buf);
    CHECK(strcmp(buf, "54321") == 0);

    REPORT();
    return 0;
}
```

**要点**
- `toupper((unsigned char)*s)` 里的转换是**强制要求**的（`ctype.h` 的函数全部接受 `unsigned char` 范围或 `EOF`）。这一点在 C 标准的 7.4 节有明确说明，也是静态检查工具必报的项。
- `*left++ = *right--` 这种写法要注意：`*left++` 是「先用 `left` 的值解引用，再把 `left` 加 1」，所以不会互相干扰。
- 反转的另一个用途：`itoa` 里先低位到高位生成数字，再反转得到正确顺序。

</details>

> 这一阶段的函数操作的是**内存字节**，不关心 `'\0'`。嵌入式里寄存器批量初始化、DMA 缓冲区搬运、结构体拷贝全靠它们。

## 12. 手写 `my_memset` ★☆☆

**考察**：为什么参数是 `int` 但内部用 `unsigned char`、字对齐优化

### 要求

```c
void *my_memset(void *dst, int c, size_t n);
```

把 `dst` 开始的 `n` 个字节都设为 `(unsigned char)c`，返回 `dst`。

### 提示

- 参数 `c` 虽然是 `int`，但只有**最低字节**有用。`memset(p, 0x1234, n)` 会把每字节设成 `0x34`。
- `memset` 的经典误用是「初始化非字节类型数组」——见下方要点。

<details>
<summary>参考答案 + 测试用例</summary>

```c
#include <stdio.h>
#include <string.h>
#include <stdint.h>

void *my_memset(void *dst, int c, size_t n)
{
    unsigned char *p = (unsigned char *)dst;
    unsigned char byte = (unsigned char)c;   /* ★ 只取最低字节 */

    while (n > 0) {
        *p++ = byte;
        n--;
    }
    return dst;
}

int main(void)
{
    uint8_t buf[16];

    memset(buf, 0xAA, sizeof(buf));
    CHECK(my_memset(buf, 0x00, sizeof(buf)) == buf);
    for (size_t i = 0; i < sizeof(buf); i++) CHECK(buf[i] == 0x00);

    my_memset(buf, 0xFF, 4);
    CHECK(buf[0] == 0xFF && buf[3] == 0xFF && buf[4] == 0x00);

    /* n == 0 不写任何字节 */
    memset(buf, 0x55, sizeof(buf));
    my_memset(buf, 0x00, 0);
    CHECK(buf[0] == 0x55);

    /* ★ 传入超出一个字节的值，只取最低字节 */
    my_memset(buf, 0x1234, 1);
    CHECK(buf[0] == 0x34);

    my_memset(buf, -1, 1);              /* -1 的最低字节是 0xFF */
    CHECK(buf[0] == 0xFF);

    /* ★ 经典坑：用 memset 给 int 数组「置 1」得不到 1 */
    int arr[4];
    memset(arr, 1, sizeof(arr));        /* 每字节 0x01 → 0x01010101 = 16843009 */
    CHECK(arr[0] == 0x01010101);

    /* 和标准库对齐 */
    uint8_t a[8], b[8];
    memset(a, 0x77, sizeof(a)); memset(b, 0x77, sizeof(b));
    my_memset(a, 0x3C, 5);
    memset(b, 0x3C, 5);
    CHECK(memcmp(a, b, sizeof(a)) == 0);

    REPORT();
    return 0;
}
```

**要点**
- **只能用于按字节赋相同值**。以下都是错的：
  ```c
  int arr[10];
  memset(arr, 1, sizeof(arr));      /* 期望每元素 1，实际每元素 0x01010101 */
  memset(arr, 0, sizeof(arr));      /* 这个是对的：全 0 字节 == 全 0 值 */
  ```
  所以 `memset(x, 0, ...)` 通用，`memset` 非 0 值只对 `char`/`uint8_t` 数组成立。
- 别用 `memset` 初始化浮点数组为 0.0 之外的值（`1.0f` 的字节模式不是 `0x01`）。
- **性能优化**（嵌入式常见考点）：逐字节写在大缓冲上慢，可以先把目标对齐到 4/8 字节边界，再用 `uint32_t*`/`uint64_t*` 批量写。前提是访问未对齐地址不会 HardFault（Cortex-M0/M3 对未对齐访问会 fault，M4/M7 支持）。所以**必须先处理首尾的零头字节**再走对齐快路径。

</details>

## 13. 手写 `my_memcpy` ★★☆

**考察**：与 `strcpy` 的本质差异、`restrict`/重叠的未定义行为

### 要求

```c
void *my_memcpy(void *dst, const void *src, size_t n);
```

拷 `n` 个字节，**不关心内容里有没有 `'\0'`**。

### 提示

- 两个指针都是 `void *`，必须先转成 `unsigned char *` 才能做算术（`void *` 加减在标准 C 里是非法的，GCC 扩展才允许）。
- 想一想：`dst` 和 `src` 有重叠时这个实现会出什么错？

<details>
<summary>参考答案 + 测试用例</summary>

```c
#include <stdio.h>
#include <string.h>
#include <stdint.h>

void *my_memcpy(void *dst, const void *src, size_t n)
{
    unsigned char *d = (unsigned char *)dst;
    const unsigned char *s = (const unsigned char *)src;

    while (n > 0) {
        *d++ = *s++;
        n--;
    }
    return dst;
}

int main(void)
{
    uint8_t src[8] = { 0x00, 0x11, 0x22, 0x00, 0x44, 0x00, 0x66, 0x77 };
    uint8_t dst[8];

    my_memcpy(dst, src, sizeof(src));
    CHECK(memcmp(dst, src, sizeof(src)) == 0);

    /* ★ 与 strcpy 的关键差异：中间的 0x00 不会被当结尾 */
    CHECK(dst[3] == 0x00);
    CHECK(dst[5] == 0x00);

    /* n == 0 不写 */
    memset(dst, 0xEE, sizeof(dst));
    my_memcpy(dst, src, 0);
    CHECK(dst[0] == 0xEE);

    /* 拷结构体（嵌入式里传配置/寄存器组常用） */
    struct cfg { uint32_t baud; uint8_t addr; uint32_t mask; };
    struct cfg c1 = { 115200, 0x12, 0xDEADBEEF };
    struct cfg c2;
    my_memcpy(&c2, &c1, sizeof(c1));
    CHECK(c2.baud == 115200 && c2.addr == 0x12 && c2.mask == 0xDEADBEEF);
    /* ★ 注意 baud 必须用 uint32_t：115200 超出 uint16_t 的范围（最大 65535），
       写成 uint16_t 会被静默截断成 49664，串口波特率就错了 */

    /* 拷部分字节 */
    my_memcpy(dst + 2, src + 1, 3);
    CHECK(dst[2] == 0x11 && dst[3] == 0x22 && dst[4] == 0x00);

    REPORT();
    return 0;
}
```

**要点**
- `memcpy` vs `strcpy` 对比：

  | | 终止条件 | 对 `0x00` 的处理 | 适用场景 |
  |---|---|---|---|
  | `strcpy` | 遇 `'\0'` 停 | 视为结束，不拷 | 文本字符串 |
  | `memcpy` | 固定 `n` 字节 | 当普通数据拷 | 二进制帧、结构体、寄存器 |

  解析协议帧**必须**用 `memcpy`。用 `strcpy` 遇到数据里的 `0x00` 会提前截断。

- 标准要求 `memcpy` 的源和目标**不得重叠**，重叠属未定义行为。优化过的 `memcpy`（按字批量拷）重叠时结果更不可预测，所以这类 bug 在 PC 上可能"看着没事"，换 MCU 就崩。
- 对结构体做 `memcpy` 只在**同类型**之间安全。不同编译器/不同对齐设置下结构体可能含填充字节，直接拷到网络报文里会带脏数据（要自己逐字段序列化）。

</details>

## 14. 手写 `my_memmove` ★★☆

**考察**：重叠内存的方向判断，本题是笔试题高频题

### 要求

```c
void *my_memmove(void *dst, const void *src, size_t n);
```

功能同 `memcpy`，但**允许源和目标重叠**，结果必须正确（如同先拷到临时缓冲区再拷回来）。

### 提示

分两种情况：

- 目标在源后面且区间重叠（`dst > src && dst < src + n`）：**从后往前**拷，否则前面的数据会被覆盖；
- 其他情况：从前往后拷。

画一下图：
```
低地址 →  高地址
src:  [A B C D E F]
dst:        [A B C D E F]      ← dst 在后，重叠，必须从后往前
             ↑ dst[0] 会覆盖 src[2]，之后 src[2] 的原值就丢了
```

<details>
<summary>参考答案 + 测试用例</summary>

```c
#include <stdio.h>
#include <string.h>

void *my_memmove(void *dst, const void *src, size_t n)
{
    unsigned char *d = (unsigned char *)dst;
    const unsigned char *s = (const unsigned char *)src;

    if (d == s || n == 0) {
        return dst;                     /* 同一地址或空操作 */
    }

    if (d < s || d >= s + n) {
        /* 目标在源前面，或两者不重叠 → 从低地址往高地址拷 */
        while (n > 0) {
            *d++ = *s++;
            n--;
        }
    } else {
        /* 目标在源后面且重叠 → 从高地址往低地址拷（先拷尾巴） */
        d += n;
        s += n;
        while (n > 0) {
            *--d = *--s;
            n--;                        /* ★ 千万别漏这一句 */
        }
    }
    return dst;
}

int main(void)
{
    char buf[32];

    /* case 1：不重叠，等同于 memcpy */
    strcpy(buf, "hello");
    my_memmove(buf + 10, buf, 6);
    CHECK(strcmp(buf, "hello") == 0);
    CHECK(strcmp(buf + 10, "hello") == 0);

    /* ---- case 2：dst 在 src 后面且重叠（向后移动） ---- */
    strcpy(buf, "abcdef");
    my_memmove(buf + 2, buf, 5);        /* 期望 "ababcde" */
    CHECK(memcmp(buf, "ababcde", 7) == 0);

    /* ★ 对照组：这里如果用 memcpy 做同样的事，结果未定义。
       下面这行就是错误示范，故意注释掉——在 MinGW 上实测会直接段错误：
         strcpy(buf, "abcdef");
         memcpy(buf + 2, buf, 5);       // ❌ UB，可能得到 "abababa"，也可能直接崩
       所以工程规则只有一条：指针可能重叠，就一律 memmove。 */
    strcpy(buf, "abcdef");
    if (0) {
        memcpy(buf + 2, buf, 5);        /* 永不执行，仅作位置提示 */
    }
    CHECK(memcmp(buf, "abcdef", 7) == 0);

    /* case 3：dst 在 src 前面且重叠（向前移动） */
    strcpy(buf, "abcdef");
    my_memmove(buf, buf + 2, 4);        /* 期望 "cdefef" */
    CHECK(memcmp(buf, "cdefef", 6) == 0);

    /* case 4：dst == src */
    strcpy(buf, "hello");
    my_memmove(buf, buf, 5);
    CHECK(strcmp(buf, "hello") == 0);

    /* case 5：n == 0 */
    strcpy(buf, "hello");
    my_memmove(buf, buf + 1, 0);
    CHECK(strcmp(buf, "hello") == 0);

    /* 与标准库对齐：整个数组都清零，避免 memcmp 比到未初始化的字节 */
    char a[32] = { 0 }, b[32] = { 0 };
    const char *init = "0123456789";
    strcpy(a, init); strcpy(b, init);
    my_memmove(a + 3, a, 7);
    memmove(b + 3, b, 7);
    CHECK(memcmp(a, b, sizeof(a)) == 0);
    CHECK(strcmp(a, b) == 0);
    CHECK(a[3] == '0' && a[9] == '6');   /* "012" + "0123456" + "9" */

    REPORT();
    return 0;
}
```

**要点**
- **后向循环里最容易漏 `n--`**：`while (n > 0) { *--d = *--s; }` 看起来"每次 `--d` 都在推进，
  没问题"，实际上 `n` 永远不变 → 死循环，指针一路往低地址走，直到踩到不可访问的页才崩。
  崩溃现场离真正的原因很远，所以这个 bug 极难查。写这种循环时**一定要显式确认循环变量在变**。
- 判断重叠**必须用地址比较**，不能靠"看起来像"。条件 `d > s && d < s + n` 是最容易记错的一处。
- 顺序记忆口诀：**目标在后面，就从后面拷**。
- 实际工程中还有一个常被忽略的替代方案：如果只是搬动同一个缓冲区里的数据来"删除/插入"内容（比如从接收缓冲里抠掉一段），`memmove` 正是标准做法，不要手写循环。

</details>

## 15. 手写 `my_memcmp` ★★☆

**考察**：与 `strcmp` 的差异、返回值为字节差值的含义

### 要求

```c
int my_memcmp(const void *s1, const void *s2, size_t n);
```

比较前 `n` 个字节，返回 `<0 / 0 / >0`。

### 提示

和 `strcmp` 的唯一区别：**遇到 `0x00` 不停**，一定比满 `n` 个字节。

<details>
<summary>参考答案 + 测试用例</summary>

```c
#include <stdio.h>
#include <string.h>
#include <stdint.h>

int my_memcmp(const void *s1, const void *s2, size_t n)
{
    const unsigned char *p1 = (const unsigned char *)s1;
    const unsigned char *p2 = (const unsigned char *)s2;

    while (n > 0) {
        if (*p1 != *p2) {
            return (int)*p1 - (int)*p2;   /* 已转 unsigned，不会出负数歧义 */
        }
        p1++;
        p2++;
        n--;
    }
    return 0;
}

int main(void)
{
    uint8_t a[8] = { 0x01, 0x02, 0x00, 0x04, 0x00, 0x00, 0x00, 0x00 };
    uint8_t b[8] = { 0x01, 0x02, 0x00, 0x05, 0x00, 0x00, 0x00, 0x00 };

    CHECK(my_memcmp(a, b, 3) == 0);        /* 只比前 3 字节，相等 */
    CHECK(my_memcmp(a, b, 4) < 0);         /* 第 4 字节 0x04 < 0x05 → 返回负 */
    CHECK(my_memcmp(a, a, 8) == 0);
    CHECK(my_memcmp(a, b, 0) == 0);        /* n == 0 恒相等 */

    /* ★ 与 strcmp 的关键差异：0x00 不当终止符 */
    uint8_t x[3] = { 'a', 0x00, 'z' };
    uint8_t y[3] = { 'a', 0x00, 'a' };
    CHECK(strcmp((char *)x, (char *)y) == 0);        /* strcmp 在第 2 字节就停了 */
    CHECK(my_memcmp(x, y, 3) > 0);                   /* memcmp 比到了 'z' vs 'a' */

    /* 典型用法：比对两个协议帧/两个校验值 */
    uint8_t rxFcs[2] = { 0xA5, 0x3C };
    uint8_t calFcs[2] = { 0xA5, 0x3C };
    CHECK(my_memcmp(rxFcs, calFcs, 2) == 0);

    /* 和标准库对齐 */
    CHECK((my_memcmp(a, b, 4) > 0) == (memcmp(a, b, 4) > 0));
    CHECK((my_memcmp(a, b, 5) > 0) == (memcmp(a, b, 5) > 0));

    REPORT();
    return 0;
}
```

**要点**
- 返回值是**第一个不同字节的差值**，不是 `-1/1`。所以只能判断符号，不能依赖具体数值：
  ```c
  if (memcmp(a, b, n) == 0) { /* 相等，唯一可靠的用法 */ }
  ```
- `memcmp` 不保证"字典序"，只保证"字节序"。所以拿它给字符串排序，结果和 `strcmp` 不同（比如 `"ab"` vs `"abc"`：`memcmp(..., 3)` 会读到 `'\0'` 和 `'c'`，得到 `"ab" < "abc"`，和 `strcmp` 一致；但 `"ab\0x"` vs `"ab\0y"` 两者结论不同）。
- 结构体直接用 `memcmp` 比较**不可靠**——填充字节是未初始化的随机值。要比较结构体，逐字段比。

</details>

## 16. 手写 `my_strtok_r` ★★★

**考察**：为什么 `strtok` 在嵌入式里不能用、可重入与状态保存

### 要求

```c
/* str: 首次传待分割串，之后传 NULL 继续取下一个 token
 * save: 调用方提供的状态指针（可重入的关键）
 * 返回 token 指针，没有更多 token 时返回 NULL
 */
char *my_strtok_r(char *str, const char *delim, char **save);
```

### 提示

三步走：跳过前导分隔符 → 记录 token 起点 → 向后找到分隔符（替换成 `'\0'` 并更新 `save`）。

**关键点**：`strtok` 用的是函数内的 `static` 变量保存进度，所以：
1. 不可重入（中断里调用会破坏主循环的进度）；
2. 不能嵌套使用（解析两层结构时会互相干扰）；
3. 会**修改原字符串**（把分隔符改写成 `'\0'`）。

`strtok_r` 把状态放在调用方的 `save` 变量里，解决前两个问题。

<details>
<summary>参考答案 + 测试用例</summary>

```c
#include <stdio.h>
#include <string.h>

char *my_strtok_r(char *str, const char *delim, char **save)
{
    char *start;

    if (str == NULL) {
        str = *save;                    /* 继续上次的位置 */
    }
    if (str == NULL) {
        return NULL;                    /* 已经取完了 */
    }

    /* 第 1 步：跳过前导分隔符 */
    while (*str != '\0' && strchr(delim, *str) != NULL) {
        str++;
    }
    if (*str == '\0') {                 /* 剩下的全是分隔符 */
        *save = NULL;
        return NULL;
    }

    /* 第 2 步：token 起点 */
    start = str;

    /* 第 3 步：找 token 结尾 */
    while (*str != '\0' && strchr(delim, *str) == NULL) {
        str++;
    }
    if (*str == '\0') {
        *save = NULL;                   /* 这是最后一个 token */
    } else {
        *str = '\0';                    /* ★ 就地切断原串 */
        *save = str + 1;
    }
    return start;
}

/* 对比：标准库 strtok 的用法（仅演示，别在嵌入式里用） */
static void demo_strtok(char *line)
{
    char *tok = strtok(line, " ,");
    while (tok != NULL) {
        printf("    [strtok] %s\n", tok);
        tok = strtok(NULL, " ,");
    }
}

int main(void)
{
    char buf[64];
    char *save = NULL;

    /* 基本分割 */
    strcpy(buf, "SET,LED,1");
    CHECK(strcmp(my_strtok_r(buf, ",", &save), "SET") == 0);
    CHECK(strcmp(my_strtok_r(NULL, ",", &save), "LED") == 0);
    CHECK(strcmp(my_strtok_r(NULL, ",", &save), "1") == 0);
    CHECK(my_strtok_r(NULL, ",", &save) == NULL);       /* 取完返回 NULL */

    /* 连续分隔符被当作一个（跳过前导 + 空 token 不返回） */
    strcpy(buf, "  a,,b , c  ");
    save = NULL;
    CHECK(strcmp(my_strtok_r(buf, " ,", &save), "a") == 0);
    CHECK(strcmp(my_strtok_r(NULL, " ,", &save), "b") == 0);
    CHECK(strcmp(my_strtok_r(NULL, " ,", &save), "c") == 0);
    CHECK(my_strtok_r(NULL, " ,", &save) == NULL);

    /* 全是分隔符 */
    strcpy(buf, "   ,,,  ");
    save = NULL;
    CHECK(my_strtok_r(buf, " ,", &save) == NULL);

    /* 空串 */
    strcpy(buf, "");
    save = NULL;
    CHECK(my_strtok_r(buf, " ,", &save) == NULL);

    /* 原串被就地破坏 —— 这是所有 strtok 系的固有行为，要清楚 */
    strcpy(buf, "a,b");
    save = NULL;
    my_strtok_r(buf, ",", &save);
    CHECK(buf[1] == '\0');              /* ★ ',' 已被改写成 '\0' */

    /* ★ 嵌套解析：strtok 会互相干扰，strtok_r 不会 */
    char outer[64], inner[64];
    strcpy(outer, "cfg;baud=115200;addr=0x12");
    char *osave = NULL;
    CHECK(strcmp(my_strtok_r(outer, ";", &osave), "cfg") == 0);
    char *kv = my_strtok_r(NULL, ";", &osave);          /* "baud=115200" */
    CHECK(kv != NULL);
    strcpy(inner, kv);
    char *isave = NULL;
    CHECK(strcmp(my_strtok_r(inner, "=", &isave), "baud") == 0);
    CHECK(strcmp(my_strtok_r(NULL, "=", &isave), "115200") == 0);
    /* 内层跑完之后，外层还能继续 —— 用 static 的 strtok 就废了 */
    CHECK(strcmp(my_strtok_r(NULL, ";", &osave), "addr=0x12") == 0);

    printf("  --- 标准库 strtok 对照 ---\n");
    strcpy(buf, "SET,LED,1");
    demo_strtok(buf);

    REPORT();
    return 0;
}
```

**要点**
- 三个致命问题一句话总结：**改原串、不可重入、不可嵌套**。所以 MISRA C 直接禁止 `strtok`。
- 若输入的串是只读的（比如来自 `const char *`），`strtok` 系都不能用——要么先 `strcpy` 到可写缓冲，要么自己写一个不修改原串的版本（返回 `(start, len)` 而不是切断字符串）：
  ```c
  typedef struct { const char *start; size_t len; } slice_t;
  ```
  这是嵌入式解析里更推荐的写法，因为不需要可写副本、也不破坏原始报文（便于日志留存/重传）。
- 分隔符集合用 `strchr(delim, *str)` 实现，比手写循环遍历 `delim` 更简洁。

</details>

# 阶段四：转换与格式化

## 17. 健壮的 `my_atoi`（带错误检测）★★☆

**考察**：前导空白、正负号、溢出检测、`strtol` 的 `endptr` 机制

### 要求

```c
/* 成功返回解析出的值，*err 置 0
 * 失败（格式非法 / 溢出）返回 INT_MAX 或 INT_MIN，*err 置非 0 */
int my_atoi(const char *s, int *err);
```

必须处理：

1. 前导空白（空格、`\t`）
2. 可选的正负号
3. 没有任何数字 → 报错（标准 `atoi` 会静默返回 0，这是 bug 温床）
4. 数字后有多余字符 → 这里按「宽松」处理，只取前面的数字部分（和 `atoi` 一致），但在 `err` 里标记

### 提示

- 先把累加值放在 `long` 里，最后再判断是否超出 `INT_MAX`/`INT_MIN`。
- 每步乘 10 之前先判断会不会溢出：`val > (LONG_MAX - d) / 10`。

<details>
<summary>参考答案 + 测试用例</summary>

```c
#include <stdio.h>
#include <ctype.h>
#include <limits.h>

/* err: 可选，传 NULL 表示不关心错误 */
int my_atoi(const char *s, int *err)
{
    long long val = 0;                  /* ★ 不能用 long：32 位平台上 long 也是 32 位 */
    int neg = 0, overflow = 0;

    if (err) *err = 0;
    if (s == NULL) {
        if (err) *err = 1;
        return 0;
    }

    /* 1. 跳过前导空白 */
    while (isspace((unsigned char)*s)) {
        s++;
    }
    /* 2. 正负号 */
    if (*s == '+' || *s == '-') {
        neg = (*s == '-');
        s++;
    }
    /* 3. 必须紧跟至少一个数字 */
    if (!isdigit((unsigned char)*s)) {
        if (err) *err = 2;              /* 格式非法 */
        return 0;
    }
    /* 4. 逐位累加。用 int64 中转，超过 int 上限就停止增长并标记溢出 */
    while (isdigit((unsigned char)*s)) {
        if (!overflow) {
            val = val * 10 + (*s - '0');
            /* 负数比正数能多表示一个值，所以界限是 INT_MAX + 1 */
            if (val > (long long)INT_MAX + 1) {
                overflow = 1;
            }
        }
        s++;
    }

    if (overflow) {
        if (err) *err = 3;              /* 溢出 */
        return neg ? INT_MIN : INT_MAX;
    }

    val = neg ? -val : val;
    if (val > INT_MAX) { if (err) *err = 3; return INT_MAX; }
    if (val < INT_MIN) { if (err) *err = 3; return INT_MIN; }

    /* 5. 尾部还有非数字字符？宽松接受但标记一下 */
    while (isspace((unsigned char)*s)) {
        s++;
    }
    if (*s != '\0' && err) {
        *err = 4;                       /* 有剩余垃圾字符 */
    }
    return (int)val;
}

int main(void)
{
    int err;

    CHECK(my_atoi("123", &err) == 123 && err == 0);
    CHECK(my_atoi("0", &err) == 0 && err == 0);
    CHECK(my_atoi("  42", &err) == 42 && err == 0);
    CHECK(my_atoi("\t\n 7", &err) == 7 && err == 0);
    CHECK(my_atoi("+99", &err) == 99 && err == 0);
    CHECK(my_atoi("-99", &err) == -99 && err == 0);
    CHECK(my_atoi("-0", &err) == 0 && err == 0);

    /* 非数字开头 → 报错（atoi 会静默返回 0，无法区分） */
    CHECK(my_atoi("abc", &err) == 0 && err == 2);
    CHECK(my_atoi("", &err) == 0 && err == 2);
    CHECK(my_atoi("+", &err) == 0 && err == 2);
    CHECK(my_atoi("-x", &err) == 0 && err == 2);
    CHECK(my_atoi(NULL, &err) == 0 && err == 1);

    /* 尾部有垃圾 */
    CHECK(my_atoi("123abc", &err) == 123 && err == 4);
    CHECK(my_atoi("123  ", &err) == 123 && err == 0);   /* 尾部空白不算垃圾 */

    /* 溢出 */
    CHECK(my_atoi("2147483647", &err) == INT_MAX && err == 0);
    CHECK(my_atoi("2147483648", &err) == INT_MAX && err == 3);
    CHECK(my_atoi("-2147483648", &err) == INT_MIN && err == 0);  /* ★ INT_MIN 边界 */
    CHECK(my_atoi("-2147483649", &err) == INT_MIN && err == 3);
    CHECK(my_atoi("99999999999999999999", &err) == INT_MAX && err == 3);
    CHECK(my_atoi("-99999999999999999999", &err) == INT_MIN && err == 3);

    /* 和标准库对比（合法输入必须一致） */
    const char *cases[] = { "0", "1", "-1", "42", "  -7", "+123",
                            "2147483647", "-2147483648", "007" };
    for (size_t i = 0; i < sizeof(cases) / sizeof(cases[0]); i++) {
        CHECK(my_atoi(cases[i], &err) == atoi(cases[i]));
    }

    REPORT();
    return 0;
}
```

**要点**
- `atoi` 的三大缺陷：**无法报错**、**溢出行为未定义**、**无法知道解析到哪**。
  所以工程代码一律用 `strtol`：
  ```c
  char *end;
  long v = strtol(s, &end, 10);
  if (end == s)          { /* 一个数字都没有 */ }
  if (*end != '\0')      { /* 尾部有垃圾 */ }
  if (errno == ERANGE)   { /* 溢出 */ }
  ```
  本题手写就是在还原 `strtol` 的这套机制。
- 用 `int64_t`（或 `long long`）中转，**不能用 `long`**：Windows/MinGW 和 32 位 ARM 上 `long` 也是 32 位，
  用 `long` 中转时 `"−2147483648"` 会在累加过程中就被误判成溢出（`LONG_MAX` 只有 `2147483647`）。
- 嵌入式里如果只是解析固定格式的短数字（如 AT 指令返回的 `25`），直接手写 3~5 行循环更省 Flash，不必引入 `strtol`。

</details>

## 18. 手写 `my_itoa` ★★☆

**考察**：`INT_MIN` 的取负陷阱、进制转换、不用 `printf` 的输出

### 要求

```c
/* 把 value 按 base（2~16）转成字符串写入 buf（调用方保证足够大，33 字节足够）
 * 返回 buf */
char *my_itoa(int value, char *buf, int base);
```

输出小写字母。

### 提示

- **经典陷阱**：`value = INT_MIN` 时 `-value` 会溢出（`INT_MIN` 的绝对值比 `INT_MAX` 大 1）。
  常用技巧：`unsigned int u = (unsigned int)(-(value + 1)) + 1u;`
- 生成的数字是**低位在前**，最后要反转（或倒着写进 buf）。

<details>
<summary>参考答案 + 测试用例</summary>

```c
#include <stdio.h>
#include <string.h>
#include <limits.h>

char *my_itoa(int value, char *buf, int base)
{
    static const char digits[] = "0123456789abcdef";
    char tmp[40];
    int i = 0, neg = 0;
    unsigned int uval;

    if (base < 2 || base > 16) {
        buf[0] = '\0';
        return buf;
    }

    if (value < 0 && base == 10) {
        neg = 1;
        /* ★ 避开 INT_MIN 取负溢出的标准技巧 */
        uval = (unsigned int)(-(value + 1)) + 1u;
    } else {
        uval = (unsigned int)value;     /* 非 10 进制时按位模式解释（同标准库） */
    }

    /* 低位到高位生成，存到临时数组（倒序） */
    do {
        tmp[i++] = digits[uval % (unsigned int)base];
        uval /= (unsigned int)base;
    } while (uval != 0);
    /* 注意这里是 do-while：value == 0 时也要输出 '0' */

    int j = 0;
    if (neg) {
        buf[j++] = '-';
    }
    while (i > 0) {
        buf[j++] = tmp[--i];            /* 倒序写回 → 高位在前 */
    }
    buf[j] = '\0';
    return buf;
}

int main(void)
{
    char buf[40];

    /* 十进制 */
    CHECK(strcmp(my_itoa(0, buf, 10), "0") == 0);
    CHECK(strcmp(my_itoa(1, buf, 10), "1") == 0);
    CHECK(strcmp(my_itoa(-1, buf, 10), "-1") == 0);
    CHECK(strcmp(my_itoa(12345, buf, 10), "12345") == 0);
    CHECK(strcmp(my_itoa(-12345, buf, 10), "-12345") == 0);
    CHECK(strcmp(my_itoa(INT_MAX, buf, 10), "2147483647") == 0);
    CHECK(strcmp(my_itoa(INT_MIN, buf, 10), "-2147483648") == 0);   /* ★ 关键用例 */

    /* 十六进制（嵌入式调试最常用） */
    CHECK(strcmp(my_itoa(0, buf, 16), "0") == 0);
    CHECK(strcmp(my_itoa(255, buf, 16), "ff") == 0);
    CHECK(strcmp(my_itoa(0xDEADBEEF, buf, 16), "deadbeef") == 0);
    CHECK(strcmp(my_itoa(-1, buf, 16), "ffffffff") == 0);           /* 位模式 */

    /* 二进制 */
    CHECK(strcmp(my_itoa(5, buf, 2), "101") == 0);
    CHECK(strcmp(my_itoa(0, buf, 2), "0") == 0);

    /* 8 进制 */
    CHECK(strcmp(my_itoa(64, buf, 8), "100") == 0);

    /* 非法进制 */
    CHECK(my_itoa(1, buf, 1)[0] == '\0');
    CHECK(my_itoa(1, buf, 17)[0] == '\0');

    /* 和标准库 sprintf 对照 */
    for (int v = -1000; v <= 1000; v += 7) {
        char ref[40];
        sprintf(ref, "%d", v);
        CHECK(strcmp(my_itoa(v, buf, 10), ref) == 0);
    }

    REPORT();
    return 0;
}
```

**要点**
- `INT_MIN` 必须专门测试。很多实现写成 `if (value < 0) { neg = 1; value = -value; }`，遇到 `INT_MIN` 直接 UB。
- 非十进制时按 `unsigned int` 解释（`-1` → `ffffffff`），这与 `printf("%x", -1)` 一致。
- 用 `do-while` 而不是 `while`：否则 `value == 0` 会输出空串。
- **嵌入式优化**：`% 10` 和 `/ 10` 要调用除法子程序，Cortex-M0/M3 没有硬件除法指令，一个 32 位除法要几十个周期。频繁刷屏（如 OLED 显示电压）时改成：
  - 减 10 的幂求商（查表 + 循环减）；
  - 或者预先定标（如电压单位用 0.001V 表示）避免除法。
- 也可以用「除 100 一次取两位」的查表法把除法次数减半。

</details>

## 19. 十六进制字符串 → 字节数组 ★★☆

**考察**：`(unsigned char)` 判高位、半字节校验、容忍多种分隔符

### 要求

```c
/* 解析 "A1B2C3" 或 "A1:B2:C3" 或 "A1 B2 C3" 到 out
 * 成功返回解析出的字节数；失败（非法字符、半字节、空间不足）返回 -1 */
int hexstr_to_bytes(const char *hex, uint8_t *out, size_t out_max);
```

### 提示

- 用「半个字节」状态机：字符串里每 2 个十六进制字符构成 1 字节。
- 别用 `if (c >= 'A')` 这种写法判断，先用一个 `hex_val()` 辅助函数把字符映射成 0~15，返回 -1 表示非法。

<details>
<summary>参考答案 + 测试用例</summary>

```c
#include <stdio.h>
#include <string.h>
#include <stdint.h>

/* 单字符 → 半字节，非法返回 -1 */
static int hex_val(int c)
{
    if (c >= '0' && c <= '9') return c - '0';
    if (c >= 'a' && c <= 'f') return c - 'a' + 10;
    if (c >= 'A' && c <= 'F') return c - 'A' + 10;
    return -1;
}

static int is_hex_sep(int c)
{
    return (c == ' ' || c == ':' || c == '-' || c == ',');
}

int hexstr_to_bytes(const char *hex, uint8_t *out, size_t out_max)
{
    size_t n = 0;
    int hi = -1;                        /* -1 表示"期待高位"，否则存着高位等低位 */

    if (hex == NULL || out == NULL) {
        return -1;
    }

    for (; *hex != '\0'; hex++) {
        /* ★ 关键：先转成 unsigned char 再判断。
           char 带符号时，字节 >= 0x80 会变成负数，直接传给 hex_val 逻辑就错 */
        int c = (unsigned char)*hex;

        if (is_hex_sep(c)) {
            continue;
        }
        int v = hex_val(c);
        if (v < 0) {
            return -1;                  /* 出现非法字符 */
        }
        if (hi < 0) {
            hi = v;                     /* 收到半个字节，等下一个 */
            continue;
        }
        if (n >= out_max) {
            return -1;                  /* 输出缓冲不够 */
        }
        out[n++] = (uint8_t)((hi << 4) | v);
        hi = -1;
    }

    if (hi >= 0) {
        return -1;                      /* ★ 末尾只剩半个字节，格式非法 */
    }
    return (int)n;
}

static void dump(const uint8_t *p, size_t n)
{
    for (size_t i = 0; i < n; i++) printf("%02X ", p[i]);
    printf("\n");
}

int main(void)
{
    uint8_t out[16];

    CHECK(hexstr_to_bytes("A1B2C3", out, sizeof(out)) == 3);
    CHECK(out[0] == 0xA1 && out[1] == 0xB2 && out[2] == 0xC3);

    CHECK(hexstr_to_bytes("a1b2c3", out, sizeof(out)) == 3);       /* 小写也认 */
    CHECK(out[0] == 0xA1);

    CHECK(hexstr_to_bytes("A1:B2:C3", out, sizeof(out)) == 3);     /* MAC 风格 */
    CHECK(hexstr_to_bytes("A1 B2 C3", out, sizeof(out)) == 3);     /* 空格分隔 */
    CHECK(hexstr_to_bytes("A1-B2-C3", out, sizeof(out)) == 3);
    CHECK(hexstr_to_bytes("A1 B2-C3,B4", out, sizeof(out)) == 4);  /* 混合分隔 */
    CHECK(hexstr_to_bytes("  A1  B2  ", out, sizeof(out)) == 2);   /* 前后多余空格 */

    /* 单字节 / 空串 */
    CHECK(hexstr_to_bytes("00", out, sizeof(out)) == 1 && out[0] == 0x00);
    CHECK(hexstr_to_bytes("FF", out, sizeof(out)) == 1 && out[0] == 0xFF);
    CHECK(hexstr_to_bytes("", out, sizeof(out)) == 0);

    /* 错误情况 */
    CHECK(hexstr_to_bytes("A1G2", out, sizeof(out)) == -1);        /* 非法字符 */
    CHECK(hexstr_to_bytes("A1B", out, sizeof(out)) == -1);         /* 半字节 */
    CHECK(hexstr_to_bytes("A", out, sizeof(out)) == -1);
    CHECK(hexstr_to_bytes("A1B2C3", out, 2) == -1);                /* 空间不足 */
    CHECK(hexstr_to_bytes("A1B2C3", out, 3) == 3);                 /* 刚好放下 */
    CHECK(hexstr_to_bytes(NULL, out, sizeof(out)) == -1);

    printf("  A1 B2 C3 → "); dump(out, 3);

    REPORT();
    return 0;
}
```

**要点**
- `int c = (unsigned char)*hex;` 这一步是必须的。直接 `hex_val(*hex)` 时，若 `char` 带符号，`0x80` 以上的字符会变成负的 `int`，虽然这里的比较用的是字面量 `'0'` 等（都是正数），恰好不出错——但养成习惯：**凡是对字节做范围判断，先转 `unsigned char`**。
- 「半字节」错误必须检出。`"A1B"` 如果静默忽略末尾的 `B`，就会变成不报错的静默 bug。
- 分隔符容忍设计是为了同一份代码能同时吃 `"AA:BB:CC"`（MAC）、`"AA BB CC"`（日志）、`"AABBCC"`（紧凑报文）三种格式。

</details>

## 20. 字节数组 → 十六进制字符串 ★☆☆

**考察**：长度计算、`snprintf` 返回值语义、缓冲区边界

### 要求

```c
/* 把 data 转成 hex 字符串写入 out（自动补 '\0'）
 * upper: 非 0 用大写，sep: 分隔符字符，0 表示不加分隔符
 * 返回写入的字符数（不含 '\0'）；空间不足时截断并返回已写入长度 */
size_t bytes_to_hexstr(const uint8_t *data, size_t len, char *out,
                       size_t out_size, int upper, char sep);
```

### 提示

每个字节固定占 2 字符，若 `sep != 0` 则相邻字节之间加 1 个分隔符。
先算所需总长度，再决定是否要截断——不要边写边担心越界。

<details>
<summary>参考答案 + 测试用例</summary>

```c
#include <stdio.h>
#include <string.h>
#include <stdint.h>

size_t bytes_to_hexstr(const uint8_t *data, size_t len, char *out,
                       size_t out_size, int upper, char sep)
{
    static const char lower[] = "0123456789abcdef";
    static const char upper_tab[] = "0123456789ABCDEF";
    const char *tab = upper ? upper_tab : lower;
    size_t w = 0;

    if (out == NULL || out_size == 0) {
        return 0;
    }
    if (data == NULL) {
        out[0] = '\0';
        return 0;
    }

    for (size_t i = 0; i < len; i++) {
        /* 本字节需要 2 个字符，非最后一个字节且要分隔符时再多 1 个 */
        size_t need = 2 + ((sep != '\0' && i + 1 < len) ? 1u : 0u);

        if (w + need + 1 > out_size) {   /* +1 留给 '\0' */
            break;                       /* 装不下就停，保证不越界 */
        }
        out[w++] = tab[data[i] >> 4];    /* 高 4 位 */
        out[w++] = tab[data[i] & 0x0F];  /* 低 4 位 */
        if (sep != '\0' && i + 1 < len) {
            out[w++] = sep;
        }
    }
    out[w] = '\0';
    return w;
}

int main(void)
{
    uint8_t data[] = { 0xA1, 0x0B, 0xFF, 0x00 };
    char buf[64];

    CHECK(bytes_to_hexstr(data, 4, buf, sizeof(buf), 0, '\0') == 8);
    CHECK(strcmp(buf, "a10bff00") == 0);

    CHECK(bytes_to_hexstr(data, 4, buf, sizeof(buf), 1, '\0') == 8);
    CHECK(strcmp(buf, "A10BFF00") == 0);

    CHECK(bytes_to_hexstr(data, 4, buf, sizeof(buf), 1, ':') == 11);
    CHECK(strcmp(buf, "A1:0B:FF:00") == 0);

    CHECK(bytes_to_hexstr(data, 4, buf, sizeof(buf), 0, ' ') == 11);
    CHECK(strcmp(buf, "a1 0b ff 00") == 0);

    /* 边界：0 字节和单个字节 */
    CHECK(bytes_to_hexstr(data, 0, buf, sizeof(buf), 0, ':') == 0);
    CHECK(strcmp(buf, "") == 0);
    CHECK(bytes_to_hexstr(data, 1, buf, sizeof(buf), 0, ':') == 2);
    CHECK(strcmp(buf, "a1") == 0);      /* 单字节不加尾分隔符 */

    /* ★ 缓冲区刚好放下 "a1b2"（4 字符 + '\0' = 5） */
    uint8_t two[] = { 0xA1, 0xB2 };
    CHECK(bytes_to_hexstr(two, 2, buf, 5, 0, '\0') == 4);
    CHECK(strcmp(buf, "a1b2") == 0);

    /* 差一个字节 → 截断到 "a1"，不越界 */
    char tiny[3];
    CHECK(bytes_to_hexstr(two, 2, tiny, sizeof(tiny), 0, '\0') == 2);
    CHECK(strcmp(tiny, "a1") == 0);

    /* out_size == 1 只能写 '\0' */
    char one[1];
    CHECK(bytes_to_hexstr(two, 2, one, 1, 0, '\0') == 0);
    CHECK(one[0] == '\0');

    /* 往返一致性：把第 19 题的 hexstr_to_bytes 粘到本文件顶部，就可以跑这组对照
     *   bytes_to_hexstr(data, 4, buf, sizeof(buf), 0, '\0');   // "a10bff00"
     *   hexstr_to_bytes(buf, back, sizeof(back)) == 4           // 还原成原 4 字节
     *   memcmp(back, data, 4) == 0
     */

    REPORT();
    return 0;
}
```

**要点**
- **统一写法**：边界检查放在循环里、写之前，而不是"先写完再检查"。上面用 `w + need + 1 > out_size` 一次性判断，包含了结尾 `'\0'` 的位置。
- 这里用 `tab[data[i] >> 4]` 查表，比 `snprintf(buf, 3, "%02X", byte)` 快得多，而且不需要 `stdio`（很多 MCU 工程为了省 Flash 不含 `printf`）。
- 需要**定长输出**时（比如上报固定 2×N 字节的 hex），不要用这个"能写多少写多少"的语义，而应先判断 `out_size >= 2*len + 1`，不够就直接报错返回 0——否则上报的报文字段长度会变，对端解析错位。
- 与第 19 题配对，构成 hex 编解码的一对。

</details>

## 21. 定点小数格式化（不依赖浮点）★★☆

**考察**：为什么嵌入式要避开 `float`、`%0*u` 的用法

### 要求

MCU 上（尤其 Cortex-M0）没有 FPU，用 `float` 会引入 `libm`，吃几 KB Flash 且在中断里很慢。
所以测量值常用**定点整数**表示：电压 `12345` 表示 `12.345 V`，即实际值 = `value / scale`。

```c
/* value/scale → 字符串，小数保留 decimals 位
 * 例：format_fixed(12345, 1000, 3, buf, ...) → "12.345"
 * 返回写入的字符数 */
int format_fixed(int32_t value, uint32_t scale, int decimals,
                 char *buf, size_t size);
```

### 提示

- 整数部分 = `value / scale`，小数部分 = `value % scale`。
- 小数部分要按 `decimals` 位**重新定标**：`fp * 10^decimals / scale`。
- 用 `%0*u` 让小数部分自动补前导零（`0.05` 不能输出成 `0.5`）。

<details>
<summary>参考答案 + 测试用例</summary>

```c
#include <stdio.h>
#include <stdint.h>
#include <stdlib.h>

int format_fixed(int32_t value, uint32_t scale, int decimals,
                 char *buf, size_t size)
{
    int v, neg;
    uint32_t a, ip, fp, p = 1;

    if (buf == NULL || size == 0 || scale == 0) {
        if (buf && size) buf[0] = '\0';
        return 0;
    }
    if (decimals < 0) decimals = 0;
    if (decimals > 9) decimals = 9;     /* 防止 p 溢出 */

    neg = (value < 0);
    /* ★ 用 int64_t 中转，避免 INT32_MIN 取负溢出 */
    a = neg ? (uint32_t)(-(int64_t)value) : (uint32_t)value;

    ip = a / scale;                     /* 整数部分 */
    fp = a % scale;                     /* 小数余数 */

    if (decimals == 0) {
        return snprintf(buf, size, "%s%u", neg ? "-" : "", (unsigned)ip);
    }

    for (int i = 0; i < decimals; i++) {
        p *= 10u;
    }
    /* 小数余数重新定标到 decimals 位 */
    fp = (uint32_t)(((uint64_t)fp * p) / scale);

    /* ★ %0*u：宽度由参数 decimals 给出，不足补 0 */
    v = snprintf(buf, size, "%s%u.%0*u",
                 neg ? "-" : "", (unsigned)ip, decimals, (unsigned)fp);
    return (v < 0) ? 0 : v;
}

int main(void)
{
    char buf[32];

    CHECK(strcmp((format_fixed(12345, 1000, 3, buf, sizeof(buf)), buf), "12.345") == 0);
    CHECK(strcmp((format_fixed(0, 1000, 3, buf, sizeof(buf)), buf), "0.000") == 0);
    CHECK(strcmp((format_fixed(1000, 1000, 3, buf, sizeof(buf)), buf), "1.000") == 0);
    CHECK(strcmp((format_fixed(500, 1000, 3, buf, sizeof(buf)), buf), "0.500") == 0);
    CHECK(strcmp((format_fixed(-12345, 1000, 3, buf, sizeof(buf)), buf), "-12.345") == 0);
    CHECK(strcmp((format_fixed(-1, 1000, 3, buf, sizeof(buf)), buf), "-0.001") == 0);

    /* ★ 前导零：0.005 不能输出成 0.5 */
    CHECK(strcmp((format_fixed(5, 1000, 3, buf, sizeof(buf)), buf), "0.005") == 0);
    CHECK(strcmp((format_fixed(50, 1000, 3, buf, sizeof(buf)), buf), "0.050") == 0);

    /* 保留 2 位：会做四舍五入吗？这里是截断，注意语义 */
    CHECK(strcmp((format_fixed(12345, 1000, 2, buf, sizeof(buf)), buf), "12.34") == 0);
    CHECK(strcmp((format_fixed(12399, 1000, 2, buf, sizeof(buf)), buf), "12.39") == 0);

    /* decimals == 0，不带小数点 */
    CHECK(strcmp((format_fixed(12345, 1000, 0, buf, sizeof(buf)), buf), "12") == 0);
    CHECK(strcmp((format_fixed(-12345, 1000, 0, buf, sizeof(buf)), buf), "-12") == 0);

    /* 不同 scale */
    CHECK(strcmp((format_fixed(2500, 100, 2, buf, sizeof(buf)), buf), "25.00") == 0);  /* 百分比 */
    CHECK(strcmp((format_fixed(-40, 10, 1, buf, sizeof(buf)), buf), "-4.0") == 0);     /* 温度 */

    /* 极端值 */
    CHECK(strcmp((format_fixed(INT32_MIN, 1000, 3, buf, sizeof(buf)), buf),
                 "-2147483.648") == 0);

    /* ★ 缓冲不足：snprintf 截断，返回值仍是"本该写入的长度"(5)，
       buf 里只放得下 3 个字符 + '\0' → "0.0"
       调用方必须用 返回值 >= size 来判断是否截断（同第 22 题的道理） */
    char tiny[4];
    CHECK(format_fixed(5, 1000, 3, tiny, sizeof(tiny)) == 5);
    CHECK(strcmp(tiny, "0.0") == 0);

    CHECK(strcmp((format_fixed(1, 0, 3, buf, sizeof(buf)), buf), "") == 0);  /* scale=0 */

    /* 如需"四舍五入"，先把半个最低位加到 value 上再格式化。
       保留 2 位时，最低位单位是 scale/100 = 10，所以加 10/2 = 5 */
    int32_t half = 1000 / (2 * 100);            /* = 5 */
    CHECK(strcmp((format_fixed(12345 + half, 1000, 2, buf, sizeof(buf)), buf), "12.35") == 0);
    /* 不补半个单位就是截断 */
    CHECK(strcmp((format_fixed(12345, 1000, 2, buf, sizeof(buf)), buf), "12.34") == 0);

    REPORT();
    return 0;
}
```

**要点**
- **截断 vs 四舍五入**是接口语义的一部分，必须写清楚。要四舍五入就在调用前加
  `scale / (2 * 10^decimals)`（保留 2 位时就是加 `scale/200`）。这个"预加半个单位"的做法
  完全不碰浮点，比 `+ 0.5f` 更省资源也更可控。
- `%0*u` 的宽度由 `int` 参数给，很容易忘掉那个 `*`，写成 `%0u` 就变成正常输出、前导零丢失。
- 更省资源的做法（省掉 `%` 和除法）：既然 `p` 和 `scale` 都是已知常量，直接写成 `fp * 10 / scale` 让编译器在编译期优化；或者干脆用「打印到固定宽度字符数组」的整数算法，完全不碰 `snprintf`。
- 这也是**为什么浮点能不用就不用**：`snprintf("%f")` 会拖进完整的浮点格式化实现，在 Flash 只有 64KB 的 MCU 上是不可接受的体积开销。

</details>

## 22. 安全日志拼接（`vsnprintf` 封装）★★★

**考察**：`vsnprintf` 返回值的正确解读、变参函数、`va_list` 的传递

### 要求

实现一个"可累积拼接"的日志缓冲区，多次调用追加内容，任何一次装不下就停止并上报错误。

```c
typedef struct {
    char  *buf;
    size_t size;    /* buf 总容量 */
    size_t used;    /* 已写入长度，不含 '\0' */
} logbuf_t;

void logbuf_init(logbuf_t *lb, char *buf, size_t size);
int  logbuf_appendf(logbuf_t *lb, const char *fmt, ...);   /* 成功 0，截断 -1 */
```

### 提示

`snprintf` / `vsnprintf` 的返回值是「**假如空间无限大，本该写入多少字符**」，不是「实际写入了多少」。
所以 `ret >= size` 就说明被截断了——这是最关键的一点。

<details>
<summary>参考答案 + 测试用例</summary>

```c
#include <stdio.h>
#include <string.h>
#include <stdarg.h>

typedef struct {
    char  *buf;
    size_t size;
    size_t used;
} logbuf_t;

void logbuf_init(logbuf_t *lb, char *buf, size_t size)
{
    lb->buf  = buf;
    lb->size = size;
    lb->used = 0;
    if (size > 0) {
        buf[0] = '\0';
    }
}

int logbuf_appendf(logbuf_t *lb, const char *fmt, ...)
{
    va_list ap;
    int n;

    if (lb->buf == NULL || lb->used >= lb->size) {
        return -1;
    }

    va_start(ap, fmt);
    /* 可写空间 = size - used，含结尾 '\0' 的位置 */
    n = vsnprintf(lb->buf + lb->used, lb->size - lb->used, fmt, ap);
    va_end(ap);

    if (n < 0) {
        return -1;                      /* 格式化出错 */
    }
    if ((size_t)n >= lb->size - lb->used) {
        /* ★ 被截断了：n 是"本该写入"的长度。
           此时缓冲里已有 size-1 个字符 + '\0'，把 used 顶到末尾，
           否则下次调用会从中间插入，字符串被撕裂 */
        lb->used = lb->size - 1;
        return -1;
    }

    lb->used += (size_t)n;
    return 0;
}

int main(void)
{
    char mem[64];
    logbuf_t lb;

    logbuf_init(&lb, mem, sizeof(mem));
    CHECK(lb.used == 0 && mem[0] == '\0');

    CHECK(logbuf_appendf(&lb, "[%lu] ", 12345u) == 0);
    CHECK(strcmp(mem, "[12345] ") == 0);
    CHECK(lb.used == 8);

    CHECK(logbuf_appendf(&lb, "temp=%d.%d ", 25, 6) == 0);
    CHECK(strcmp(mem, "[12345] temp=25.6 ") == 0);

    CHECK(logbuf_appendf(&lb, "vcc=%umV", 3300) == 0);
    CHECK(strcmp(mem, "[12345] temp=25.6 vcc=3300mV") == 0);
    CHECK(lb.used == strlen(mem));

    /* ★ 截断检测：64 字节缓冲，追加一段超长内容 */
    logbuf_init(&lb, mem, sizeof(mem));
    logbuf_appendf(&lb, "%s", "AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA"
                             "BBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBB");
    CHECK(lb.used == sizeof(mem) - 1);              /* 顶到末尾 */
    CHECK(strlen(mem) == sizeof(mem) - 1);
    CHECK(mem[sizeof(mem) - 1] == '\0');            /* 仍然有结尾符 */

    /* 截断后再追加，不会破坏已有内容、也不会越界 */
    CHECK(logbuf_appendf(&lb, "more") == -1);
    CHECK(strlen(mem) == sizeof(mem) - 1);

    /* 恰好填满：写 63 个字符 + '\0' */
    logbuf_init(&lb, mem, sizeof(mem));
    CHECK(logbuf_appendf(&lb, "%063d", 0) == 0);    /* 63 个 '0' */
    CHECK(lb.used == 63);
    CHECK(strlen(mem) == 63);
    CHECK(logbuf_appendf(&lb, "x") == -1);          /* 再写一个就装不下 */

    /* 差一个字符就装不下的情况必须报错，而不是静默截断 */
    logbuf_init(&lb, mem, 5);
    CHECK(logbuf_appendf(&lb, "abcd") == 0);        /* 4 + '\0' = 5，刚好 */
    CHECK(strcmp(mem, "abcd") == 0);

    logbuf_init(&lb, mem, 5);
    CHECK(logbuf_appendf(&lb, "abcde") == -1);      /* 5 + '\0' = 6 > 5，截断 */
    CHECK(strcmp(mem, "abcd") == 0);                /* 写入的是截断后的 "abcd" */

    /* 边界：size == 1 */
    char one[1];
    logbuf_init(&lb, one, 1);
    CHECK(logbuf_appendf(&lb, "x") == -1);
    CHECK(one[0] == '\0');

    REPORT();
    return 0;
}
```

**要点**
- **`snprintf` 返回值语义是本节唯一的重点**，也是实际项目里最高频的 bug：
  ```c
  /* 错误写法：以为返回值是实际写入长度 */
  len += snprintf(buf + len, size - len, "%s", s);   /* 一旦截断，len 超过 size！ */

  /* 正确写法 */
  int n = snprintf(buf + len, size - len, "%s", s);
  if (n < 0 || (size_t)n >= size - len) { /* 截断，处理错误 */ }
  else { len += (size_t)n; }
  ```
  错误写法在截断后 `len > size`，下一次循环的 `size - len` 变成一个巨大的 `size_t`（下溢），直接越界写爆栈。这是 CVE 级别的经典漏洞模式。
- 截断后必须把 `used` 顶到 `size - 1`，保证 `buf` 依然是一个合法的、长度正确的字符串。
- `va_list` 只能被消费一次，所以封装层次里如果用 `vprintf` 系列必须一次到位；要多次使用得 `va_copy`。
- 变参函数**不能**把 `va_list` 直接转成 `...` 往下传，所以内部一定用 `vsnprintf` 而不是 `snprintf`。

</details>

## 23. 串口命令行解析（argc / argv 风格）★★☆

**考察**：`strtok_r` 实战、处理 `\r\n`、参数个数上限

### 场景

串口收到一行命令（以 `\n` 结尾），格式为「命令 + 空格分隔的参数」，需要拆成 `argc`/`argv` 形式方便分发：

```
"SET LED 1\r\n"     → argc=3, argv = {"SET", "LED", "1"}
"GET?\r\n"          → argc=1, argv = {"GET?"}
"   \r\n"           → argc=0（空行）
"SET    LED    1"   → argc=3（多个空格当一个）
```

### 要求

```c
/* line: 可修改的一行（原地修改，会被写入 '\0'）
 * argv: 输出数组，容量 max_arg
 * 返回 argc */
int parse_cmd(char *line, char *argv[], int max_arg);
```

还需把 `argv[argc]` 置 `NULL`（如果空间够），兼容 `execv` 风格。

### 提示

- 先掐掉行尾的 `\r\n` 和尾部空格。
- 用第 16 题的 `my_strtok_r`，分隔符是 `" \t"`。

<details>
<summary>参考答案 + 测试用例</summary>

```c
#include <stdio.h>
#include <string.h>

/* —— 本文件依赖第 16 题的 my_strtok_r，把实现粘过来 —— */
char *my_strtok_r(char *str, const char *delim, char **save)
{
    char *start;
    if (str == NULL) str = *save;
    if (str == NULL) return NULL;

    while (*str != '\0' && strchr(delim, *str) != NULL) str++;
    if (*str == '\0') { *save = NULL; return NULL; }

    start = str;
    while (*str != '\0' && strchr(delim, *str) == NULL) str++;
    if (*str == '\0') {
        *save = NULL;
    } else {
        *str = '\0';
        *save = str + 1;
    }
    return start;
}

int parse_cmd(char *line, char *argv[], int max_arg)
{
    char *save = NULL, *tok;
    int argc = 0;
    char *p;

    if (line == NULL || argv == NULL || max_arg <= 0) {
        return 0;
    }

    /* 1. 掐掉行尾的 '\r'、'\n'、空格、'\t' */
    p = line;
    while (*p != '\0') p++;              /* 走到结尾 */
    while (p > line && (p[-1] == '\r' || p[-1] == '\n' ||
                        p[-1] == ' '  || p[-1] == '\t')) {
        *--p = '\0';
    }

    /* 2. 分割（my_strtok_r 会自动跳过连续分隔符和首部空白） */
    for (tok = my_strtok_r(line, " \t", &save);
         tok != NULL && argc < max_arg - 1;      /* -1 给 NULL 哨兵留位 */
         tok = my_strtok_r(NULL, " \t", &save)) {
        argv[argc++] = tok;
    }

    /* 3. 参数超限：剩下的 token 直接丢弃，但要让调用方知道（这里返回已达上限） */
    argv[argc] = NULL;                   /* execv 风格的哨兵 */
    return argc;
}

int main(void)
{
    char line[64];
    char *argv[8];
    int argc;

    /* 普通命令 */
    strcpy(line, "SET LED 1\r\n");
    argc = parse_cmd(line, argv, 8);
    CHECK(argc == 3);
    CHECK(strcmp(argv[0], "SET") == 0);
    CHECK(strcmp(argv[1], "LED") == 0);
    CHECK(strcmp(argv[2], "1") == 0);
    CHECK(argv[3] == NULL);

    /* 单个 token */
    strcpy(line, "GET?\r\n");
    argc = parse_cmd(line, argv, 8);
    CHECK(argc == 1 && strcmp(argv[0], "GET?") == 0);

    /* 多个空格 / 制表符 */
    strcpy(line, "SET\t\t  LED    1");
    argc = parse_cmd(line, argv, 8);
    CHECK(argc == 3 && strcmp(argv[2], "1") == 0);

    /* 空行 / 全是空白 */
    strcpy(line, "\r\n");
    CHECK(parse_cmd(line, argv, 8) == 0);
    strcpy(line, "    \r\n");
    CHECK(parse_cmd(line, argv, 8) == 0);
    strcpy(line, "");
    CHECK(parse_cmd(line, argv, 8) == 0);

    /* 没有 \r\n（比如从 Flash 读出来的配置行） */
    strcpy(line, "SAVE");
    argc = parse_cmd(line, argv, 8);
    CHECK(argc == 1 && strcmp(argv[0], "SAVE") == 0);

    /* 中间带空参数的场景：此处被"连续分隔符合并"语义吞掉了，需明确这是预期行为 */
    strcpy(line, "SET LED \"a b\"");
    argc = parse_cmd(line, argv, 8);
    CHECK(argc == 4);                    /* 引号未做特殊处理 */

    /* ★ 参数超过 argv 容量：不越界 */
    strcpy(line, "a b c d e f g h i j");
    argc = parse_cmd(line, argv, 4);
    CHECK(argc == 3);                    /* 3 个参数 + NULL 哨兵 */
    CHECK(argv[3] == NULL);

    /* 原串被修改（这是使用 strtok 系的代价） */
    strcpy(line, "SET LED 1");
    parse_cmd(line, argv, 8);
    CHECK(line[3] == '\0');              /* 第一个空格变成了 '\0' */

    REPORT();
    return 0;
}
```

**要点**
- **必须先去掉 `\r\n`**。串口工具默认发 `"cmd\r\n"`，如果不去掉，最后一个参数会变成 `"1\r\n"`，
  后面 `atoi("1\r\n")` 虽然能出 1（因为 `\r` 不是数字就停了），但 `strcmp(argv[2], "1")` 会失败。
  这类 bug 极其常见且难查。
- 如果命令行的响应格式不确定（TFTP、Linux 命令行），`"a b"` 引号分组是标准需求；本实现没做，
  需要扩展到"遇到引号不切分"的状态机。要清楚这是**已知的简化**，不是 bug。
- **不返回能否放下所有参数**是个隐患。工程上建议返回 `argc` 的同时用一个 `int *overflow` 出参
  告诉调用方"还有参数被丢了"，否则用户输入 20 个参数会被静默忽略。
- 如果这行命令来自中断（ISR），**不能在 ISR 里调用 `parse_cmd`**——它耗时长（`strlen` + 多次 `strchr`），
  正确做法是 ISR 只做「收字节进环形缓冲」，主循环里再解析（第 31 题）。

</details>

## 24. AT 指令响应解析 ★★☆

**考察**：`strstr` 定位 + `strtol` 取值 + `endptr` 校验

### 场景

解析模组返回的 AT 响应，提取其中的数值：

```
"+CSQ: 25,99"                  → rssi=25, ber=99
"+CSQ: 18"                     → rssi=18, ber 保持默认（-1 表示缺省）
"+CREG: 0,1"                   → ...
"ERROR" / "无匹配" / ""        → 返回错误码
```

### 要求

```c
/* 成功返回 0，失败返回负的错误码 */
int parse_csq(const char *resp, int *rssi, int *ber);

/* 进阶：解析任意 "PREFIX: v1,v2,..." 形式的响应
 * values: 输出数组，max: 容量，返回解析出的数值个数，失败返回 -1 */
int parse_at_values(const char *resp, const char *prefix,
                    int *values, int max);
```

### 提示

- `strstr` 找前缀，找不到要区分「响应里有 ERROR」和「根本没这个前缀」。
- 用 `strtol` + `endptr` 而不是 `atoi`：`endptr == p` 表示这个位置没有数字。

<details>
<summary>参考答案 + 测试用例</summary>

```c
#include <stdio.h>
#include <string.h>
#include <stdlib.h>

int parse_csq(const char *resp, int *rssi, int *ber)
{
    const char *p;
    char *end;
    long v;

    if (resp == NULL || rssi == NULL || ber == NULL) {
        return -1;
    }
    if (strstr(resp, "ERROR") != NULL) {
        return -2;                       /* 模组明确报错 */
    }

    p = strstr(resp, "+CSQ:");
    if (p == NULL) {
        return -3;                       /* 没有这个字段 */
    }
    p += 5;                              /* 跳过 "+CSQ:" */

    /* 第 1 个数值 */
    v = strtol(p, &end, 10);
    if (end == p) {
        return -4;                       /* 没有数字 */
    }
    *rssi = (int)v;
    p = end;

    /* 第 2 个数值（可选） */
    while (*p == ' ') p++;
    if (*p != ',') {
        *ber = -1;                       /* 缺省：单字段响应 */
        return 0;
    }
    p++;                                 /* 跳过 ',' */
    while (*p == ' ') p++;
    v = strtol(p, &end, 10);
    if (end == p) {
        *ber = -1;                       /* 有逗号但没数字，容忍 */
        return 0;
    }
    *ber = (int)v;
    return 0;
}

/* 通用版：解析 "PREFIX: v1,v2,..." ，返回值个数，-1 表示未匹配 */
int parse_at_values(const char *resp, const char *prefix,
                    int *values, int max)
{
    const char *p;
    char *end;
    int n = 0;

    if (resp == NULL || prefix == NULL || values == NULL || max <= 0) {
        return -1;
    }
    p = strstr(resp, prefix);
    if (p == NULL) {
        return -1;
    }
    p += strlen(prefix);

    while (n < max) {
        while (*p == ' ' || *p == '\t') p++;
        if (*p == '\0' || *p == '\r' || *p == '\n') {
            break;                       /* 到了行尾 */
        }
        long v = strtol(p, &end, 10);
        if (end == p) {
            break;                       /* 不是数字了（遇到字母等） */
        }
        values[n++] = (int)v;
        p = end;
        if (*p == ',') {
            p++;                         /* 继续下一个 */
        } else {
            break;                       /* 没有更多分隔的数值 */
        }
    }
    return (n > 0) ? n : -1;
}

int main(void)
{
    int rssi, ber, vals[8];

    CHECK(parse_csq("+CSQ: 25,99", &rssi, &ber) == 0);
    CHECK(rssi == 25 && ber == 99);

    /* 前面有回显，后面有 OK */
    CHECK(parse_csq("AT+CSQ\r\r\n+CSQ: 18,0\r\n\r\nOK\r\n", &rssi, &ber) == 0);
    CHECK(rssi == 18 && ber == 0);

    /* 单字段响应，ber 缺省为 -1 */
    CHECK(parse_csq("+CSQ: 18", &rssi, &ber) == 0);
    CHECK(rssi == 18 && ber == -1);

    /* 空格容忍（有些模组会输出 "+CSQ:  18 , 5"） */
    CHECK(parse_csq("+CSQ:  18 , 5", &rssi, &ber) == 0);
    CHECK(rssi == 18 && ber == 5);

    /* 负数 */
    CHECK(parse_csq("+CSQ: -3,99", &rssi, &ber) == 0);
    CHECK(rssi == -3 && ber == 99);

    /* 错误情况 */
    CHECK(parse_csq("ERROR", &rssi, &ber) == -2);
    CHECK(parse_csq("+CREG: 1,1", &rssi, &ber) == -3);
    CHECK(parse_csq("", &rssi, &ber) == -3);
    CHECK(parse_csq("+CSQ: abc", &rssi, &ber) == -4);
    CHECK(parse_csq("+CSQ:", &rssi, &ber) == -4);
    CHECK(parse_csq(NULL, &rssi, &ber) == -1);

    /* 通用解析 */
    CHECK(parse_at_values("+CSQ: 25,99", "+CSQ:", vals, 8) == 2);
    CHECK(vals[0] == 25 && vals[1] == 99);

    CHECK(parse_at_values("+CREG: 0,1", "+CREG:", vals, 8) == 2);
    CHECK(parse_at_values("+CGATT: 1", "+CGATT:", vals, 8) == 1);
    CHECK(parse_at_values("+CIPSTA: \"192.168.1.5\"", "+CIPSTA:", vals, 8) == -1);
    CHECK(parse_at_values("+CSQ: 1,2,3,4,5", "+CSQ:", vals, 3) == 3);   /* 容量限制 */
    CHECK(parse_at_values("OK", "+CSQ:", vals, 8) == -1);

    REPORT();
    return 0;
}
```

**要点**
- **为什么一定要用 `strtol` 而不是 `atoi`**：这段代码要区分三件事——
  "字段不存在"、"字段存在但内容不是数字"、"字段存在且解析成功"。
  `atoi` 对前两种都返回 0，无法区分，会导致把 `+CSQ: abc` 当成 `rssi = 0` 上报。
- `strstr` 找前缀有**误匹配风险**：`strstr(resp, "+CSQ:")` 在响应 `"AT+CSQ: ..."` 里也会命中。
  更严格的做法是要求前缀出现在**行首或 `\n` 之后**：
  ```c
  /* 检查 p 前面是不是行首 */
  if (p != resp && p[-1] != '\n') { /* 不是行首，可能是回显，跳过继续找 */ }
  ```
  本例简化处理了，实际项目中要按模组行为决定。
- AT 响应的行尾是 `\r\n`，`strtol` 会自动在 `\r` 处停下（不是数字），所以不需要预先剥离。
- 解析 AT 时请牢记：`+CSQ` 和 `+CSQ:` 是两个不同前缀，用 `"+CSQ:"` 能避免匹配到 `+CSQN` 之类。

</details>

## 25. `str_trim` 原地去首尾空白 ★☆☆

**考察**：原地修改 + `memmove` 搬移、返回值设计

### 要求

```c
/* 去掉首尾的空白（' \t\r\n'），原地修改
 * 返回 s 本身（内容已左移） */
char *str_trim(char *s);
```

### 提示

- 找到第一个非空白位置 `start` 和最后一个非空白位置 `end`。
- 把 `[start, end]` 搬到 `s` 开头，用 `memmove`（源目标重叠）。
- 全空白串要处理成空串。

<details>
<summary>参考答案 + 测试用例</summary>

```c
#include <stdio.h>
#include <string.h>
#include <ctype.h>

char *str_trim(char *s)
{
    char *start, *end;

    if (s == NULL) {
        return s;
    }

    /* 1. 跳到第一个非空白 */
    start = s;
    while (*start != '\0' && isspace((unsigned char)*start)) {
        start++;
    }

    /* 2. 全是空白 → 变成空串 */
    if (*start == '\0') {
        s[0] = '\0';
        return s;
    }

    /* 3. 从结尾往回找最后一个非空白 */
    end = start + strlen(start) - 1;
    while (end > start && isspace((unsigned char)*end)) {
        end--;
    }
    /* 此时 [start, end] 是有效内容 */

    /* 4. 左移到 s 开头（可能重叠，必须用 memmove） */
    size_t len = (size_t)(end - start) + 1;
    if (start != s) {
        memmove(s, start, len);
    }
    s[len] = '\0';
    return s;
}

int main(void)
{
    char buf[64];

    /* 基本场景 */
    strcpy(buf, "  hello  ");
    CHECK(strcmp(str_trim(buf), "hello") == 0);

    strcpy(buf, "hello");
    CHECK(strcmp(str_trim(buf), "hello") == 0);

    strcpy(buf, "hello\r\n");
    CHECK(strcmp(str_trim(buf), "hello") == 0);     /* 串口/AT 场景的核心用途 */

    strcpy(buf, "\t\r\n hello world \t\r\n");
    CHECK(strcmp(str_trim(buf), "hello world") == 0);

    /* 中间空白要保留 */
    strcpy(buf, "  a  b  ");
    CHECK(strcmp(str_trim(buf), "a  b") == 0);

    /* 边界 */
    strcpy(buf, "");
    CHECK(strcmp(str_trim(buf), "") == 0);

    strcpy(buf, "   ");
    CHECK(strcmp(str_trim(buf), "") == 0);

    strcpy(buf, "\r\n");
    CHECK(strcmp(str_trim(buf), "") == 0);

    strcpy(buf, "a");
    CHECK(strcmp(str_trim(buf), "a") == 0);

    strcpy(buf, " a");
    CHECK(strcmp(str_trim(buf), "a") == 0);

    strcpy(buf, "a ");
    CHECK(strcmp(str_trim(buf), "a") == 0);

    /* 返回值就是 s 本身，方便链式使用 */
    strcpy(buf, "  x  ");
    CHECK(str_trim(buf) == buf);

    /* 典型组合：先 trim 再判空 */
    strcpy(buf, "   \r\n");
    CHECK(str_trim(buf)[0] == '\0');

    REPORT();
    return 0;
}
```

**要点**
- **必须用 `memmove` 而不是 `memcpy`**：`start > s` 时源和目标重叠，`memcpy` 是 UB。
- 全空白串最容易漏掉——不处理的话 `end = start + strlen(start) - 1` 会算出 `start - 1`，
  比较 `end > start` 失败（无符号/指针比较），后续 `len` 计算就错乱了。
- `isspace` 包含空格、`\t`、`\n`、`\v`、`\f`、`\r`。如果只想 trim 空格和 `\r\n`，自己写判断更明确：
  ```c
  static int is_trim_char(int c) { return c == ' ' || c == '\t' || c == '\r' || c == '\n'; }
  ```
- 另一个常见的接口设计是返回「新起点指针」而不搬运数据（零拷贝）：
  ```c
  char *trim_front(char *s);     /* 只返回 start，不动内存 */
  ```
  适合之后马上要解析、不需要保留原位置的场景。

</details>

## 26. `starts_with` / `ends_with` ★☆☆

**考察**：`strncmp` 的复用、后缀判断的下标计算

### 要求

```c
int str_starts_with(const char *s, const char *prefix);   /* 是返回 1，否 0 */
int str_ends_with(const char *s, const char *suffix);
```

### 提示

- 前缀用 `strncmp(s, prefix, strlen(prefix)) == 0`。
- 后缀要先比较长度，再用指针偏移到尾部比较。

<details>
<summary>参考答案 + 测试用例</summary>

```c
#include <stdio.h>
#include <string.h>

int str_starts_with(const char *s, const char *prefix)
{
    if (s == NULL || prefix == NULL) {
        return 0;
    }
    /* 空前缀：约定为"是"（便于拼接可选前缀的调用方） */
    return strncmp(s, prefix, strlen(prefix)) == 0;
}

int str_ends_with(const char *s, const char *suffix)
{
    size_t ls, lf;

    if (s == NULL || suffix == NULL) {
        return 0;
    }
    ls = strlen(s);
    lf = strlen(suffix);
    if (lf > ls) {
        return 0;                        /* ★ 后缀比原串长，不可能匹配 */
    }
    return strcmp(s + (ls - lf), suffix) == 0;
}

int main(void)
{
    /* 前缀 */
    CHECK(str_starts_with("AT+CSQ", "AT+") == 1);
    CHECK(str_starts_with("AT+CSQ", "AT") == 1);
    CHECK(str_starts_with("AT+CSQ", "AT+CSQ") == 1);
    CHECK(str_starts_with("AT+CSQ", "BT") == 0);
    CHECK(str_starts_with("AT", "AT+CSQ") == 0);     /* 比原串长 */
    CHECK(str_starts_with("AT+CSQ", "") == 1);       /* 空前缀 */
    CHECK(str_starts_with("", "") == 1);
    CHECK(str_starts_with("", "a") == 0);

    /* 后缀 */
    CHECK(str_ends_with("config.bin", ".bin") == 1);
    CHECK(str_ends_with("config.bin", ".txt") == 0);
    CHECK(str_ends_with("config.bin", "config.bin") == 1);
    CHECK(str_ends_with("config.bin", "n") == 1);
    CHECK(str_ends_with("ab", "abc") == 0);          /* ★ 后缀更长 */
    CHECK(str_ends_with("", "") == 1);
    CHECK(str_ends_with("abc", "") == 1);

    /* 实际用法：判断行结束符（串口按 CRLF 判断一行收完） */
    CHECK(str_ends_with("SET LED 1\r\n", "\r\n") == 1);
    CHECK(str_ends_with("SET LED 1\n", "\n") == 1);

    /* 实际用法：按扩展名分发文件类型 */
    const char *files[] = { "a.bin", "b.txt", "c.bin", "d" };
    int bin_cnt = 0;
    for (size_t i = 0; i < sizeof(files) / sizeof(files[0]); i++) {
        if (str_ends_with(files[i], ".bin")) bin_cnt++;
    }
    CHECK(bin_cnt == 2);

    REPORT();
    return 0;
}
```

**要点**
- `str_starts_with` 的 `strncmp` 写法天然安全：即使 `s` 比 `prefix` 短，`strncmp` 也会在 `\0` 处停下并返回非 0。
- `str_ends_with` 的**长度检查不能省**。少了它 `s + (ls - lf)` 会算出 `s` 之前的地址（无符号下溢），
  读出越界内存，是典型的隐蔽崩溃。
- 前缀/后缀判断在协议解析里非常高频：判断帧头 `str_starts_with(frame, "AA55")`、
  判断 AT 响应结尾 `str_ends_with(resp, "\r\nOK\r\n")`。
- 这两个函数用 `strncmp`/`strcmp` 而不是 `memcmp`，因为要按字符串语义（遇 `\0` 停）；只有确定知道长度时才用 `memcmp`。

</details>

## 27. IPv4 字符串解析 ★★☆

**考察**：`strtol` + `endptr` 严格校验、点号计数、范围检查

### 要求

```c
/* "192.168.1.1" → ip[4]
 * 成功返回 0，失败返回负错误码 */
int parse_ipv4(const char *str, uint8_t ip[4]);
```

**必须拒绝**（这些是 `atoi + strtok` 朴素写法会漏掉的）：

- 数字段数不对：`"1.2.3"`、`"1.2.3.4.5"`
- 超范围：`"256.1.1.1"`、`"1.1.1.-1"`
- 空段：`"1..2.3"`、`".1.2.3"`、`"1.2.3."`
- 含垃圾字符：`"1.2.3.4x"`、`"1.2.3.4 "`（严格模式）
- 前导零歧义：`"01.2.3.4"`（严格模式可选拒绝，防止被当成八进制）

### 提示

循环 4 次，每次用 `strtol` 读一个数并检查 `endptr`，然后必须看到 `.`（最后一次必须看到 `\0`）。

<details>
<summary>参考答案 + 测试用例</summary>

```c
#include <stdio.h>
#include <string.h>
#include <stdlib.h>
#include <stdint.h>

#define IP_OK          0
#define IP_ERR_NULL   -1
#define IP_ERR_FORMAT -2
#define IP_ERR_RANGE  -3

int parse_ipv4(const char *str, uint8_t ip[4])
{
    const char *p = str;

    if (str == NULL || ip == NULL) {
        return IP_ERR_NULL;
    }

    for (int i = 0; i < 4; i++) {
        char *end;
        long v;

        /* 空段检查：必须有数字开头 */
        if (*p == '\0' || *p == '.') {
            return IP_ERR_FORMAT;
        }
        /* 严格：不允许前导 0（"01" 在某些实现里被当八进制） */
        if (p[0] == '0' && p[1] >= '0' && p[1] <= '9') {
            return IP_ERR_FORMAT;
        }

        v = strtol(p, &end, 10);
        if (end == p) {
            return IP_ERR_FORMAT;        /* 没有数字 */
        }
        if (v < 0 || v > 255) {
            return IP_ERR_RANGE;
        }
        ip[i] = (uint8_t)v;
        p = end;

        if (i < 3) {
            if (*p != '.') {
                return IP_ERR_FORMAT;    /* 段之间必须是 '.' */
            }
            p++;
        }
    }

    if (*p != '\0') {
        return IP_ERR_FORMAT;            /* 第 4 段后面还有垃圾 */
    }
    return IP_OK;
}

static void print_ip(const uint8_t ip[4])
{
    printf("  → %u.%u.%u.%u\n", ip[0], ip[1], ip[2], ip[3]);
}

static char *fmt_ip(const uint8_t ip[4], char *buf, size_t n)
{
    snprintf(buf, n, "%u.%u.%u.%u", ip[0], ip[1], ip[2], ip[3]);
    return buf;
}

int main(void)
{
    uint8_t ip[4];
    char buf[20];

    /* 正常 */
    CHECK(parse_ipv4("192.168.1.1", ip) == IP_OK);
    CHECK((print_ip(ip), fmt_ip(ip, buf, sizeof(buf)), strcmp(buf, "192.168.1.1")) == 0);

    CHECK(parse_ipv4("0.0.0.0", ip) == IP_OK);
    CHECK(memcmp(ip, "\0\0\0\0", 4) == 0);

    CHECK(parse_ipv4("255.255.255.255", ip) == IP_OK);
    CHECK(ip[0] == 255 && ip[3] == 255);

    CHECK(parse_ipv4("10.0.0.1", ip) == IP_OK);
    CHECK(ip[0] == 10 && ip[1] == 0);

    /* ★ 段数不对 */
    CHECK(parse_ipv4("1.2.3", ip) == IP_ERR_FORMAT);
    CHECK(parse_ipv4("1.2.3.4.5", ip) == IP_ERR_FORMAT);
    CHECK(parse_ipv4("1.2", ip) == IP_ERR_FORMAT);
    CHECK(parse_ipv4("", ip) == IP_ERR_FORMAT);

    /* ★ 超范围 */
    CHECK(parse_ipv4("256.1.1.1", ip) == IP_ERR_RANGE);
    CHECK(parse_ipv4("1.1.1.256", ip) == IP_ERR_RANGE);
    CHECK(parse_ipv4("1.1.1.-1", ip) == IP_ERR_RANGE);   /* 负数 → 范围错 */
    CHECK(parse_ipv4("1.1.1.99999", ip) == IP_ERR_RANGE);

    /* ★ 空段 */
    CHECK(parse_ipv4("1..2.3", ip) == IP_ERR_FORMAT);
    CHECK(parse_ipv4(".1.2.3", ip) == IP_ERR_FORMAT);
    CHECK(parse_ipv4("1.2.3.", ip) == IP_ERR_FORMAT);

    /* ★ 垃圾字符 */
    CHECK(parse_ipv4("1.2.3.4x", ip) == IP_ERR_FORMAT);
    CHECK(parse_ipv4("1.2.3.4 ", ip) == IP_ERR_FORMAT);   /* 严格模式：尾部空格也算 */
    CHECK(parse_ipv4("1.2.3.x", ip) == IP_ERR_FORMAT);
    CHECK(parse_ipv4("1.2.3.4.5", ip) == IP_ERR_FORMAT);

    /* ★ 前导零 */
    CHECK(parse_ipv4("01.2.3.4", ip) == IP_ERR_FORMAT);
    CHECK(parse_ipv4("1.2.3.04", ip) == IP_ERR_FORMAT);
    CHECK(parse_ipv4("0.0.0.0", ip) == IP_OK);           /* 单个 0 允许 */

    /* NULL */
    CHECK(parse_ipv4(NULL, ip) == IP_ERR_NULL);
    CHECK(parse_ipv4("1.2.3.4", NULL) == IP_ERR_NULL);

    /* 往返一致性 */
    const char *cases[] = { "192.168.1.1", "10.20.30.40", "0.0.0.0", "255.255.255.255" };
    for (size_t i = 0; i < sizeof(cases) / sizeof(cases[0]); i++) {
        CHECK(parse_ipv4(cases[i], ip) == IP_OK);
        CHECK(strcmp(fmt_ip(ip, buf, sizeof(buf)), cases[i]) == 0);
    }

    REPORT();
    return 0;
}
```

**要点**
- 朴素写法 `strtok` + `atoi` 的四个漏洞，本题逐个堵上：
  | 漏洞 | 朴素写法结果 | 危害 |
  |---|---|---|
  | `"1.2.3"` | 静默通过，`ip[3]` 未初始化 | 用栈上垃圾值配置 IP |
  | `"1.2.3.4.5"` | 忽略 `.5` | 配置错误但不报错 |
  | `"256.1.1.1"` | 截断成 `0`（转 uint8_t） | IP 变成 `0.1.1.1`，静默错误 |
  | `"1.2.3.x"` | `atoi("x") == 0` | IP 变成 `1.2.3.0` |
- **前导零**必须警惕：`strtol(p, &end, 10)` 明确指定了 10 进制所以 `"01"` 也是 1，
  但如果错写成 `strtol(p, &end, 0)`（自动识别进制），`"010"` 就变成 8。
  同时 `"010"` 这种形式在许多系统上会被当成八进制，是安全审计关注点，所以这里直接拒绝。
- 返回**负错误码**而不是 `-1`，方便上层区分"格式错"和"范围错"并打印不同日志。
- 严格模式拒绝尾部空格。如果 AT 指令里带 `\r\n`，调用方**必须先 trim**（第 25 题）再调用本函数。

</details>

## 28. key=value 配置行解析 ★★☆

**考察**：`strchr` 定位分隔符、原地切割、`trim` 复用、注释处理

### 场景

解析从 Flash 读出的配置文件，或从串口下发的配置命令：

```
"baudrate=115200"          → key="baudrate", val="115200"
"ssid = MyWiFi"            → key="ssid", val="MyWiFi"（两侧空格要 trim）
"# 这是注释"                → 跳过
""                         → 跳过（返回空）
"name=ssid=test"           → key="name", val="ssid=test"（只按第一个 '=' 切）
```

### 要求

```c
/* line: 可修改的一行
 * 返回 1 表示解析出一个键值对，0 表示这行是空行/注释（调用方跳过）
 * 返回 -1 表示格式错误（没有 '='） */
int parse_kv(char *line, char **key, char **val);
```

### 提示

- 用 `strchr` 找**第一个** `'='`（不是 `strrchr`）。
- 切开之后对 `key`、`val` 各调一次 `str_trim`。
- 注释判断在 `trim` **之后**做（否则 `"   # xxx"` 会漏判）。

<details>
<summary>参考答案 + 测试用例</summary>

```c
#include <stdio.h>
#include <string.h>
#include <ctype.h>

/* —— 依赖第 25 题的 str_trim —— */
static char *str_trim(char *s)
{
    char *start, *end;
    if (s == NULL) return s;
    start = s;
    while (*start && isspace((unsigned char)*start)) start++;
    if (*start == '\0') { s[0] = '\0'; return s; }
    end = start + strlen(start) - 1;
    while (end > start && isspace((unsigned char)*end)) end--;
    size_t len = (size_t)(end - start) + 1;
    if (start != s) memmove(s, start, len);
    s[len] = '\0';
    return s;
}

int parse_kv(char *line, char **key, char **val)
{
    char *eq;

    if (line == NULL || key == NULL || val == NULL) {
        return -1;
    }

    /* 先 trim，之后才好判断注释和空行 */
    line = str_trim(line);

    if (line[0] == '\0') {
        return 0;                        /* 空行 */
    }
    if (line[0] == '#' || line[0] == ';') {
        return 0;                        /* 注释行 */
    }

    eq = strchr(line, '=');              /* ★ 第一个 '=' */
    if (eq == NULL) {
        return -1;                       /* 没有 '='，格式错误 */
    }

    *eq = '\0';                          /* 就地切成两段 */
    *key = str_trim(line);
    *val = str_trim(eq + 1);

    if ((*key)[0] == '\0') {
        return -1;                       /* "=value" 这种 key 为空的非法情况 */
    }
    return 1;
}

int main(void)
{
    char buf[128];
    char *key, *val;
    int r;

    strcpy(buf, "baudrate=115200");
    CHECK((r = parse_kv(buf, &key, &val)) == 1);
    CHECK(strcmp(key, "baudrate") == 0 && strcmp(val, "115200") == 0);

    /* 空格要 trim 掉 */
    strcpy(buf, "  ssid = MyWiFi  ");
    CHECK((r = parse_kv(buf, &key, &val)) == 1);
    CHECK(strcmp(key, "ssid") == 0 && strcmp(val, "MyWiFi") == 0);

    /* 值本身带空格（标题之类） */
    strcpy(buf, "title=Hello World");
    CHECK((r = parse_kv(buf, &key, &val)) == 1);
    CHECK(strcmp(val, "Hello World") == 0);

    /* ★ 只按第一个 '=' 切 */
    strcpy(buf, "name=ssid=test");
    CHECK((r = parse_kv(buf, &key, &val)) == 1);
    CHECK(strcmp(key, "name") == 0 && strcmp(val, "ssid=test") == 0);

    /* 空值 */
    strcpy(buf, "debug=");
    CHECK((r = parse_kv(buf, &key, &val)) == 1);
    CHECK(strcmp(key, "debug") == 0 && strcmp(val, "") == 0);

    /* 注释与空行 */
    strcpy(buf, "# 这是注释");
    CHECK(parse_kv(buf, &key, &val) == 0);
    strcpy(buf, "   # 前面有空格");
    CHECK(parse_kv(buf, &key, &val) == 0);
    strcpy(buf, "; 分号注释");
    CHECK(parse_kv(buf, &key, &val) == 0);
    strcpy(buf, "");
    CHECK(parse_kv(buf, &key, &val) == 0);
    strcpy(buf, "   \r\n");
    CHECK(parse_kv(buf, &key, &val) == 0);

    /* 格式错误 */
    strcpy(buf, "novalue");
    CHECK(parse_kv(buf, &key, &val) == -1);
    strcpy(buf, "=nokey");
    CHECK(parse_kv(buf, &key, &val) == -1);

    /* ★ 整体流程：逐行解析，喂给配置结构体 */
    char cfg[] = "# 网络配置\n"
                 "ssid=MyWiFi\n"
                 "\n"
                 "password = 12345678  \n"
                 "dhcp=1\n"
                 "badline\n";
    int kv_cnt = 0, bad_cnt = 0;
    char *p = cfg;
    while (*p != '\0') {
        char *nl = strchr(p, '\n');      /* 手写按行切分，避免依赖平台是否提供 strtok_r */
        if (nl != NULL) {
            *nl = '\0';
        }
        char *k, *v;
        int ret = parse_kv(p, &k, &v);
        if (ret == 1) {
            kv_cnt++;
            printf("  %-10s = [%s]\n", k, v);
        } else if (ret == -1) {
            bad_cnt++;
        }
        /* ret == 0 跳过 */
        if (nl == NULL) {
            break;
        }
        p = nl + 1;
    }
    CHECK(kv_cnt == 3);                 /* ssid / password / dhcp */
    CHECK(bad_cnt == 1);                /* badline */

    REPORT();
    return 0;
}
```

**要点**
- **注释判断必须在 trim 之后**。`"   # xxx"` 若不先 trim，`line[0]` 是空格，注释判断失效，
  接着 `strchr(line, '=')` 返回 `NULL`，这行合法的注释就被误报成"格式错误"。
- `strchr` 而非 `strrchr`：Windows INI 风格里值可能含 `=`（如 base64），只切第一个才对。
- 返回值用三态（1 有内容 / 0 该跳过 / -1 报错），调用方逻辑最简洁。对比只返回 0/1 的设计，
  后者无法区分"注释行"和"解析失败"，会导致配置文件里一行写错就整份解析失败。
- 密码这类敏感值不应打日志（上面示例为了演示打了，实际项目中要脱敏）:
  ```c
  if (strcmp(k, "password") == 0) { /* 打印 ****** */ }
  ```
- 解析完的值如果需要长期保存，**必须 `strdup` 或拷到自己缓冲区**——`line` 通常是个临时读缓冲，
  下一行读进来就被覆盖了。这是配置解析里最隐蔽的 bug 之一。

</details>

## 29. 校验和：累加和 / 异或 / 补码 ★☆☆

**考察**：按字节运算、验证函数与生成函数配对

### 要求

嵌入式报文里最常见的三种简单校验：

```c
uint8_t sum8(const uint8_t *data, size_t len);        /* 累加和（自然溢出） */
uint8_t xor8(const uint8_t *data, size_t len);        /* 异或校验 */
uint8_t sum8_neg(const uint8_t *data, size_t len);    /* 累加和的补码：sum8 取反加一 */
```

并实现对应的验证函数（`*_verify`），语义是「把校验字节也算进数据里，结果应为特定值」。

### 提示

- 补码校验的妙处：`sum8_neg(data)` 追加到报文末尾后，整帧（含校验字节）的 `sum8` 恰好为 `0`。
- 异或校验同理：整帧 `xor8` 为 `0`。

<details>
<summary>参考答案 + 测试用例</summary>

```c
#include <stdio.h>
#include <string.h>
#include <stdint.h>

uint8_t sum8(const uint8_t *data, size_t len)
{
    uint8_t s = 0;
    for (size_t i = 0; i < len; i++) {
        s = (uint8_t)(s + data[i]);      /* 自然溢出（回绕），这是预期行为 */
    }
    return s;
}

uint8_t xor8(const uint8_t *data, size_t len)
{
    uint8_t x = 0;
    for (size_t i = 0; i < len; i++) {
        x = (uint8_t)(x ^ data[i]);
    }
    return x;
}

uint8_t sum8_neg(const uint8_t *data, size_t len)
{
    /* 补码 = 取反加一，使整帧累加和为 0 */
    return (uint8_t)(0u - (unsigned)sum8(data, len));
}

/* 验证：data 中已包含末尾的校验字节 */
int sum8_verify(const uint8_t *frame, size_t len)
{
    return sum8(frame, len) == 0;
}

int xor8_verify(const uint8_t *frame, size_t len)
{
    return xor8(frame, len) == 0;
}

int main(void)
{
    uint8_t data[] = { 0xAA, 0x55, 0x01, 0x02, 0x03 };

    /* 手工验算：0xAA+0x55+0x01+0x02+0x03 = 0x105 → 低 8 位 0x05 */
    CHECK(sum8(data, sizeof(data)) == 0x05);

    /* 异或：0xAA^0x55 = 0xFF; ^0x01=0xFE; ^0x02=0xFC; ^0x03=0xFF */
    CHECK(xor8(data, sizeof(data)) == 0xFF);

    /* 补码 */
    CHECK(sum8_neg(data, sizeof(data)) == 0xFB);     /* 0x00 - 0x05 = 0xFB */

    /* ★ 核心性质：拼上校验字节后，整帧校验值为 0 */
    uint8_t frame[16];
    size_t n = sizeof(data);
    memcpy(frame, data, n);

    frame[n] = sum8_neg(data, n);
    CHECK(sum8_verify(frame, n + 1) == 1);

    frame[n] = xor8(data, n);
    CHECK(xor8_verify(frame, n + 1) == 1);

    /* 篡改任意一个字节，校验必须失败 */
    frame[n] = sum8_neg(data, n);
    frame[2] ^= 0x01;
    CHECK(sum8_verify(frame, n + 1) == 0);

    /* 边界 */
    CHECK(sum8(data, 0) == 0);
    CHECK(xor8(data, 0) == 0);
    CHECK(sum8_neg(data, 0) == 0);
    CHECK(sum8_verify(data, 0) == 1);                /* 空帧，sum 为 0 */

    /* 累加和会因进位丢失（0x100 → 0x00），这一对不同的数据校验值相同 */
    uint8_t a[] = { 0xFF, 0x01 };
    uint8_t b[] = { 0x00, 0x00 };
    CHECK(sum8(a, 2) == sum8(b, 2));                 /* 都是 0x00 → 弱校验 */

    /* 而异或校验对"等值改动"也不敏感 */
    uint8_t c1[] = { 0x01, 0x02 };
    uint8_t c2[] = { 0x02, 0x01 };
    CHECK(xor8(c1, 2) == xor8(c2, 2));               /* 顺序无关，都是 0x03 */

    /* 逐字节溢出回绕是正确的：300 * 0xFF = 76500 = 0x12AD4，低 8 位 0xD4 */
    uint8_t big[300];
    memset(big, 0xFF, sizeof(big));
    CHECK(sum8(big, sizeof(big)) == 0xD4);

    REPORT();
    return 0;
}
```

**要点**
- 三种校验的**能力差异**（面试常问）：

  | 校验 | 能检出 | 检不出 | 计算量 |
  |---|---|---|---|
  | 累加和 | 单字节错误 | 两个字节同时 +1/-1 的抵消；顺序变化 | 1 加法/字节 |
  | 异或 | 单字节错误 | 顺序变化；偶数次相同数据 | 1 异或/字节 |
  | 补码累加和 | 同上累加和 | 同上 | 1 加法 + 1 取负（整帧） |

- `sum8_verify(frame, len) == 0` 这个"整帧校验归零"的性质很好用：
  接收端只需一个循环、一个比较，不需要单独取出校验字节做减法。
- 这两种校验都**不能防篡改**，只用于发现传输误码。需要防篡改用 CRC16/CRC32，需要防伪造用 HMAC。
  别在安全相关的场景用 XOR 校验（这是常见的协议安全缺陷）。
- `sum8` 里 `(uint8_t)(s + data[i])` 的强转是必须的：`s + data[i]` 会按 `int` 运算，
  不强转的话赋值回 `uint8_t` 虽然也会截断（实现定义行为），但显式强转让意图更清楚、也避免静态检查告警。

</details>

## 30. 自定义协议帧解析（流式）★★★

**考察**：返回"已消耗长度"的设计、截断/半包处理、校验

### 场景

自定义协议帧格式：

```
+------+------+------+----------+-------+
| 0xAA | 0x55 | LEN  | DATA[LEN]|  SUM  |
+------+------+------+----------+-------+
  帧头   帧头   长度     N 字节     1 字节
```

其中 `SUM` = 从 `LEN` 到 `DATA` 末尾的累加和（补码形式，使校验成立）。

数据从串口一点点来，可能一次收到半帧，也可能一次收到两帧。解析函数必须能：
- 返回本次**消耗了多少字节**，让调用方从缓冲区里移除；
- 数据不够时返回"需要更多数据"，不动缓冲区。

### 要求

```c
#define FRAME_OK          0
#define FRAME_NEED_MORE   1     /* 数据不够，等下次 */
#define FRAME_ERR_HEAD   -1     /* 帧头不对 */
#define FRAME_ERR_SUM    -2     /* 校验错 */
#define FRAME_ERR_SPACE  -3     /* 输出缓冲不够 */

/* 返回 0 或正数：本次消耗的字节数（正的 NEED_MORE 也在这里统一处理，见下） */
int frame_parse(const uint8_t *buf, size_t buf_len,
                uint8_t *out, size_t out_max, size_t *out_len);
```

**返回约定**（重定义得更实用）：

- `> 0`：成功解析一帧，返回值 = 消耗的字节数，数据写入 `out`，长度写入 `*out_len`
- `0`：数据不足，需要更多（不动缓冲区）
- `< 0`：错误码；对于帧头不对，返回值 = 应丢弃的字节数（取负）

### 提示

- 先判长度够不够读到帧头（2 字节）→ 再判长度字段（1 字节）→ 再判整帧长度。
- 每一步都可能"数据不足"，不要在拿到完整帧前修改任何状态。
- 这个函数最好是**纯函数**（无内部状态），状态由调用方的缓冲区表示，方便测试。

<details>
<summary>参考答案 + 测试用例</summary>

```c
#include <stdio.h>
#include <string.h>
#include <stdint.h>

#define HEAD0  0xAAu
#define HEAD1  0x55u
#define FRAME_MAX_DATA 64

enum {
    FRAME_NEED_MORE  = 0,
    FRAME_ERR_HEAD   = -1,
    FRAME_ERR_SUM    = -2,
    FRAME_ERR_SPACE  = -3,
};

/* 从 begin 起到 end 前（含 LEN 和 DATA）的累加和补码 */
static uint8_t frame_sum(const uint8_t *p, size_t n)
{
    uint8_t s = 0;
    for (size_t i = 0; i < n; i++) {
        s = (uint8_t)(s + p[i]);
    }
    return (uint8_t)(0u - (unsigned)s);
}

int frame_parse(const uint8_t *buf, size_t buf_len,
                uint8_t *out, size_t out_max, size_t *out_len)
{
    size_t total, len;

    if (buf == NULL || out == NULL || out_len == NULL || out_max == 0) {
        return FRAME_ERR_SPACE;
    }

    /* step 1: 至少要有 2 字节才能看帧头 */
    if (buf_len < 1) {
        return FRAME_NEED_MORE;
    }
    if (buf[0] != HEAD0) {
        return -1;                       /* 丢 1 字节，让调用方顺着找下一个帧头 */
    }
    if (buf_len < 2) {
        return FRAME_NEED_MORE;          /* 第二个帧头字节还没到 */
    }
    if (buf[1] != HEAD1) {
        return -1;                       /* buf[1] 不是 0x55，丢掉 buf[0] 重来 */
    }

    /* step 2: 拿到长度字段 */
    if (buf_len < 3) {
        return FRAME_NEED_MORE;
    }
    len = buf[2];
    if (len > FRAME_MAX_DATA) {
        return -2;                       /* 长度非法：协议上限 64，直接丢帧头 */
    }

    /* step 3: 整帧长度 = 2 帧头 + 1 长度 + len 数据 + 1 校验 */
    total = 3 + len + 1;
    if (buf_len < total) {
        return FRAME_NEED_MORE;          /* ★ 半包：等下一次塞数据进来 */
    }

    /* step 4: 容量检查 */
    if (len > out_max) {
        return FRAME_ERR_SPACE;
    }

    /* step 5: 校验（覆盖 LEN + DATA） */
    if (frame_sum(buf + 2, 1 + len) != buf[3 + len]) {
        return FRAME_ERR_SUM;            /* 校验失败：整帧丢弃 */
    }

    /* step 6: 输出 */
    memcpy(out, buf + 3, len);
    *out_len = len;
    return (int)total;                   /* ★ 告诉调用方"消耗了这么多字节" */
}

/* —— 测试辅助：按协议打包一帧 —— */
static size_t frame_build(const uint8_t *data, size_t len, uint8_t *frame)
{
    frame[0] = HEAD0;
    frame[1] = HEAD1;
    frame[2] = (uint8_t)len;
    if (len > 0 && data != NULL) {
        memcpy(frame + 3, data, len);    /* 注意：memcpy 的 n 为 0 时传 NULL 严格说是 UB */
    }
    frame[3 + len] = frame_sum(frame + 2, 1 + len);
    return 3 + len + 1;
}

int main(void)
{
    uint8_t frame[128], out[128];
    size_t out_len, total;

    /* 正常一帧 */
    uint8_t payload[] = { 0x01, 0x02, 0x03 };
    total = frame_build(payload, 3, frame);
    CHECK(total == 7);
    CHECK(frame_parse(frame, total, out, sizeof(out), &out_len) == (int)total);
    CHECK(out_len == 3 && memcmp(out, payload, 3) == 0);

    /* 空数据帧（LEN = 0） */
    total = frame_build(payload, 0, frame);
    CHECK(total == 4);
    CHECK(frame_parse(frame, total, out, sizeof(out), &out_len) == 4);
    CHECK(out_len == 0);

    /* ★ 半包：数据不足时返回 NEED_MORE，不消耗、不输出 */
    uint8_t payload5[] = { 1, 2, 3, 4, 5 };
    total = frame_build(payload5, 5, frame);
    for (size_t i = 0; i < total; i++) {                 /* 逐字节喂 */
        int r = frame_parse(frame, i, out, sizeof(out), &out_len);
        CHECK(r == FRAME_NEED_MORE);
    }
    CHECK(frame_parse(frame, total, out, sizeof(out), &out_len) == (int)total);
    CHECK(out_len == 5);

    /* 只差 1 字节（缺校验字节） */
    CHECK(frame_parse(frame, total - 1, out, sizeof(out), &out_len) == FRAME_NEED_MORE);

    /* ★ 前面有垃圾数据：返回应丢弃的字节数 */
    uint8_t junk[8];
    junk[0] = 0x00;
    memcpy(junk + 1, frame, total);
    CHECK(frame_parse(junk, 1 + total, out, sizeof(out), &out_len) == -1);  /* 丢 1 字节 */
    /* 丢掉 1 字节后，从 junk+1 开始就是合法帧 */
    CHECK(frame_parse(junk + 1, total, out, sizeof(out), &out_len) == (int)total);

    /* 帧头第二个字节不对（比如 0xAA 后面跟了 0xAA，说明前面的 0xAA 是数据） */
    uint8_t bad[8] = { 0xAA, 0xAA, 0x55, 1, 0x00, 0x00, 0x00, 0x00 };
    CHECK(frame_parse(bad, sizeof(bad), out, sizeof(out), &out_len) == -1);

    /* ★ 校验错误 */
    total = frame_build(payload, 3, frame);
    frame[4] ^= 0x01;                                     /* 篡改数据 */
    CHECK(frame_parse(frame, total, out, sizeof(out), &out_len) == FRAME_ERR_SUM);

    /* ★ 长度超上限 */
    uint8_t over[8] = { 0xAA, 0x55, 200, 0x00, 0x00, 0x00, 0x00, 0x00 };
    CHECK(frame_parse(over, sizeof(over), out, sizeof(out), &out_len) == -2);

    /* 输出缓冲不足 */
    total = frame_build(payload5, 5, frame);
    CHECK(frame_parse(frame, total, out, 4, &out_len) == FRAME_ERR_SPACE);

    /* ★ 一次收到两帧：调用方循环调用，靠返回值推进 */
    uint8_t stream[256];
    size_t off = 0;
    off += frame_build(payload, 3, stream + off);
    off += frame_build(payload5, 5, stream + off);

    size_t pos = 0;
    int frames = 0;
    while (pos < off) {
        int r = frame_parse(stream + pos, off - pos, out, sizeof(out), &out_len);

        if (r > 0) {
            frames++;
            printf("  frame %d: len=%u\n", frames, (unsigned)out_len);
            pos += (size_t)r;                             /* 推进到下一帧 */
        } else if (r == FRAME_NEED_MORE) {
            break;                                        /* 数据用完了，等下次 */
        } else if (r == -1) {
            pos += 1;                                     /* 帧头错：只丢 1 字节 */
        } else {
            /* 校验错 / 长度非法：按长度字段算出整帧长度一起丢掉，
               注意要先做上限检查，防止伪造的 LEN 导致算出一个过大的偏移 */
            size_t len_field = (pos + 3 <= off) ? stream[pos + 2] : 0;
            if (len_field > FRAME_MAX_DATA) {
                pos += 3;                                 /* 长度非法，只丢帧头 */
            } else {
                pos += 3 + len_field + 1;
            }
        }
    }
    CHECK(frames == 2);

    /* ★ 带垃圾前缀的两帧也要能全部解出来 */
    uint8_t stream2[256];
    size_t off2 = 0;
    stream2[off2++] = 0x00;                               /* 垃圾 */
    stream2[off2++] = 0xAA;                               /* 假的帧头起始 */
    stream2[off2++] = 0x12;                               /* 后面不是 0x55 */
    off2 += frame_build(payload, 3, stream2 + off2);
    off2 += frame_build(payload5, 5, stream2 + off2);

    pos = 0;
    frames = 0;
    while (pos < off2) {
        int r = frame_parse(stream2 + pos, off2 - pos, out, sizeof(out), &out_len);
        if (r > 0) { frames++; pos += (size_t)r; }
        else if (r == FRAME_NEED_MORE) { break; }
        else if (r == -1) { pos += 1; }
        else {
            size_t lf = (pos + 3 <= off2) ? stream2[pos + 2] : 0;
            pos += (lf > FRAME_MAX_DATA) ? 3 : (3 + lf + 1);
        }
    }
    CHECK(frames == 2);                                   /* 垃圾被跳过，两帧都解出 */

    REPORT();
    return 0;
}
```

**要点**
- **核心设计：返回"消耗的字节数"**。这是流式解析器的标准套路——把缓冲区管理交给调用方，
  解析器保持无状态、可重入、易测试。比让解析器自己持有 `static` 缓冲区好维护得多。
- **半包处理是重点**：`buf_len < total` 时返回 `NEED_MORE`，且**绝不输出任何数据**。
  很多实现的 bug 是"先 memcpy 再判长度"，导致半包时输出了残缺数据。
- **帧头搜索策略**：帧头不对时只丢 **1 字节**（而不是丢整帧），因为 `0xAA 0xAA 0x55`
  这种情况说明第一个 `0xAA` 是数据、第二个才是帧头。丢整帧会漏掉后面这一帧。
- **长度字段必须先做上限检查**再用来算 `total`。否则一个伪造的 `LEN = 255` 会让 `total` 过大，
  或者更糟——如果 `LEN` 参与 `malloc`，就是整数溢出漏洞。
- 上面测试里的错误恢复循环写得比较绕（）是为了演示各种返回值的用法；
  实际项目建议把"丢弃策略"单独抽出来，用一个小的状态机枚举（`WAIT_HEAD0 / WAIT_HEAD1 / WAIT_LEN / WAIT_DATA / WAIT_SUM`）
  会更清晰，也更适合放到中断里驱动。

</details>

## 31. 环形缓冲区 + 按行取串 ★★★

**考察**：ISR 与主循环的并发、无锁单生产单消费、`volatile`

### 场景

串口中断收到一个字节就 `ring_put`，主循环有空就 `ring_get_line` 取出一整行命令。
这是嵌入式里最标准的串口收发模式，也是第 23 题 `parse_cmd` 的**正确调用姿势**。

### 要求

```c
#define RING_SIZE 256      /* 必须是 2 的幂 */

typedef struct {
    volatile uint16_t head;    /* 写入位置，只由 ISR 修改 */
    volatile uint16_t tail;    /* 读取位置，只由主循环修改 */
    uint8_t buf[RING_SIZE];
} ring_t;

void ring_init(ring_t *r);
int  ring_put(ring_t *r, uint8_t c);                 /* 满返回 -1，ISR 里调用 */
int  ring_get(ring_t *r, uint8_t *c);                /* 空返回 -1 */
uint16_t ring_used(const ring_t *r);
int  ring_get_line(ring_t *r, char *line, size_t max);   /* 取一整行 */
```

`ring_get_line` 语义：凑齐以 `'\n'` 结尾的一整行才返回 1 并消耗数据，否则返回 0 不动缓冲区。

### 提示

- **用一位冗余**区分"空"和"满"：最多存 `RING_SIZE - 1` 个字节，`head == tail` 为空。
- 用掩码 `& (RING_SIZE - 1)` 代替取模，速度快（配合 2 的幂长度才成立）。
- `head`/`tail` 必须 `volatile`，否则编译器可能把它们缓存到寄存器里导致死循环。
- 单生产者单消费者场景下**不需要加锁**——这是这个结构最大的价值。

<details>
<summary>参考答案 + 测试用例</summary>

```c
#include <stdio.h>
#include <string.h>
#include <stdint.h>

#define RING_SIZE 256      /* 必须是 2 的幂 */
#define RING_MASK (RING_SIZE - 1)

typedef struct {
    volatile uint16_t head;
    volatile uint16_t tail;
    uint8_t buf[RING_SIZE];
} ring_t;

void ring_init(ring_t *r)
{
    r->head = 0;
    r->tail = 0;
}

uint16_t ring_used(const ring_t *r)
{
    /* 无符号回绕相减，天然处理 head 越过数组末尾的情况 */
    return (uint16_t)((r->head - r->tail) & RING_MASK);
}

static uint16_t ring_free(const ring_t *r)
{
    return (uint16_t)(RING_MASK - ring_used(r));
}

/* ISR 中调用：满则丢弃并返回 -1 */
int ring_put(ring_t *r, uint8_t c)
{
    uint16_t next = (uint16_t)((r->head + 1) & RING_MASK);

    if (next == r->tail) {
        return -1;                       /* 满：保留一个空位，不覆盖未读数据 */
    }
    r->buf[r->head] = c;
    r->head = next;                      /* ★ 先写数据，再更新 head（内存屏障语义） */
    return 0;
}

int ring_get(ring_t *r, uint8_t *c)
{
    if (r->head == r->tail) {
        return -1;                       /* 空 */
    }
    *c = r->buf[r->tail];
    r->tail = (uint16_t)((r->tail + 1) & RING_MASK);
    return 0;
}

/* 窥视第 i 个待读字节（不移动 tail） */
static int ring_peek(const ring_t *r, uint16_t i, uint8_t *c)
{
    if (i >= ring_used(r)) {
        return -1;
    }
    *c = r->buf[(uint16_t)((r->tail + i) & RING_MASK)];
    return 0;
}

int ring_get_line(ring_t *r, char *line, size_t max)
{
    uint16_t used, i, nl_idx = 0;
    int has_nl = 0;
    uint8_t c;

    if (r == NULL || line == NULL || max == 0) {
        return -1;
    }

    used = ring_used(r);
    if (used == 0) {
        return 0;                        /* 没数据 */
    }

    /* 1. 先找 '\n'（只窥视，不消费） */
    for (i = 0; i < used; i++) {
        if (ring_peek(r, i, &c) != 0) {
            break;
        }
        if (c == '\n') {
            has_nl = 1;
            nl_idx = i;
            break;
        }
    }

    if (!has_nl) {
        /* 还没收到换行。若缓冲快满了，说明这行超长，强制截断防止死等 */
        if (ring_free(r) > 0) {
            return 0;                    /* 还有空间，继续等 */
        }
        nl_idx = (uint16_t)(used - 1);   /* ★ 溢出保护：强制按现有数据切一行 */
    }

    /* 2. 消费到 '\n'（或截断点），'\r' 丢掉 */
    size_t n = 0;
    for (i = 0; i <= nl_idx; i++) {
        if (ring_get(r, &c) != 0) {
            break;
        }
        if (c == '\n') {
            break;
        }
        if (c == '\r') {
            continue;                    /* 丢掉 CR，只保留内容 */
        }
        if (n + 1 < max) {               /* 留 '\0' 的位置 */
            line[n++] = (char)c;
        }
        /* 超长时继续消费、只是不写入 —— 避免污染下一行 */
    }
    line[n] = '\0';
    return 1;
}

int main(void)
{
    static ring_t r;                     /* 静态：避免大结构体占栈 */
    char line[64];
    uint8_t c;

    /* ---- 基本读写 ---- */
    ring_init(&r);
    CHECK(ring_used(&r) == 0);
    CHECK(ring_get(&r, &c) == -1);

    CHECK(ring_put(&r, 'A') == 0);
    CHECK(ring_put(&r, 'B') == 0);
    CHECK(ring_used(&r) == 2);
    CHECK(ring_get(&r, &c) == 0 && c == 'A');
    CHECK(ring_get(&r, &c) == 0 && c == 'B');
    CHECK(ring_get(&r, &c) == -1);
    CHECK(ring_used(&r) == 0);

    /* ---- ★ 容量边界：最多存 RING_SIZE-1 个 ---- */
    ring_init(&r);
    for (int i = 0; i < RING_SIZE - 1; i++) {
        CHECK(ring_put(&r, (uint8_t)i) == 0);
    }
    CHECK(ring_used(&r) == RING_SIZE - 1);
    CHECK(ring_put(&r, 0xFF) == -1);     /* 满 */
    CHECK(ring_get(&r, &c) == 0 && c == 0);
    CHECK(ring_put(&r, 0xEE) == 0);      /* 腾出一个位置后又能写 */

    /* ---- 回绕：head/tail 越过数组末尾 ---- */
    ring_init(&r);
    for (int round = 0; round < 10; round++) {
        for (int i = 0; i < 100; i++) {
            CHECK(ring_put(&r, (uint8_t)(round * 100 + i)) == 0);
        }
        for (int i = 0; i < 100; i++) {
            CHECK(ring_get(&r, &c) == 0);
            CHECK(c == (uint8_t)(round * 100 + i));
        }
        CHECK(ring_used(&r) == 0);
    }

    /* ---- 按行取串 ---- */
    ring_init(&r);
    const char *cmds = "SET LED 1\r\nGET TEMP\r\n";
    for (const char *p = cmds; *p; p++) {
        ring_put(&r, (uint8_t)*p);
    }
    CHECK(ring_get_line(&r, line, sizeof(line)) == 1);
    CHECK(strcmp(line, "SET LED 1") == 0);          /* ★ '\r\n' 已被剔除 */
    CHECK(ring_get_line(&r, line, sizeof(line)) == 1);
    CHECK(strcmp(line, "GET TEMP") == 0);
    CHECK(ring_get_line(&r, line, sizeof(line)) == 0);   /* 没有完整行了 */
    CHECK(ring_used(&r) == 0);

    /* ---- 只有半行：不返回，且不消费数据 ---- */
    ring_init(&r);
    const char *partial = "SET LE";
    for (const char *p = partial; *p; p++) {
        ring_put(&r, (uint8_t)*p);
    }
    CHECK(ring_get_line(&r, line, sizeof(line)) == 0);
    CHECK(ring_used(&r) == 6);                      /* ★ 数据一个都没丢 */

    /* 补齐剩下的部分，就能取到完整行了 */
    const char *rest = "D 1\r\n";
    for (const char *p = rest; *p; p++) {
        ring_put(&r, (uint8_t)*p);
    }
    CHECK(ring_get_line(&r, line, sizeof(line)) == 1);
    CHECK(strcmp(line, "SET LED 1") == 0);

    /* ---- 空行 ---- */
    ring_init(&r);
    ring_put(&r, '\r'); ring_put(&r, '\n');
    CHECK(ring_get_line(&r, line, sizeof(line)) == 1);
    CHECK(strcmp(line, "") == 0);

    /* ---- 只有 '\n' ---- */
    ring_init(&r);
    ring_put(&r, '\n');
    CHECK(ring_get_line(&r, line, sizeof(line)) == 1);
    CHECK(strcmp(line, "") == 0);

    /* ---- 输出缓冲不足：超长行被截断，且不污染下一行 ---- */
    ring_init(&r);
    const char *longln = "AAAAAAAAAABBBBBBBBBB\r\nNEXT\r\n";
    for (const char *p = longln; *p; p++) {
        ring_put(&r, (uint8_t)*p);
    }
    char small[8];
    CHECK(ring_get_line(&r, small, sizeof(small)) == 1);
    CHECK(strlen(small) == 7);                      /* 截断到 7 字符 */
    CHECK(ring_get_line(&r, line, sizeof(line)) == 1);
    CHECK(strcmp(line, "NEXT") == 0);               /* ★ 下一行是正确的 */

    /* ---- 一行多次调用，边界不错位 ---- */
    ring_init(&r);
    const char *multi = "A\nBB\nCCC\n";
    for (const char *p = multi; *p; p++) {
        ring_put(&r, (uint8_t)*p);
    }
    CHECK(ring_get_line(&r, line, sizeof(line)) == 1 && strcmp(line, "A") == 0);
    CHECK(ring_get_line(&r, line, sizeof(line)) == 1 && strcmp(line, "BB") == 0);
    CHECK(ring_get_line(&r, line, sizeof(line)) == 1 && strcmp(line, "CCC") == 0);
    CHECK(ring_get_line(&r, line, sizeof(line)) == 0);

    /* ---- 与 parse_cmd 串起来：完整链路 ---- */
    ring_init(&r);
    const char *stream = "SET LED 1\r\nMISSING_EQ\r\nGET?\r\n";
    for (const char *p = stream; *p; p++) {
        ring_put(&r, (uint8_t)*p);
    }
    int got = 0;
    while (ring_get_line(&r, line, sizeof(line)) == 1) {
        got++;
        printf("  [line] \"%s\"\n", line);
    }
    CHECK(got == 3);

    REPORT();
    return 0;
}
```

**要点**
- **为什么不需要加锁**：`head` 只有 ISR 写、`tail` 只有主循环写，中断嵌套时不会同时写同一个变量。
  这是**单生产者单消费者**（SPSC）环形缓冲的经典性质。一旦变成多生产者（比如两个中断都往里写），
  就必须加临界区保护了。
- **`volatile` 是必须的但不是万能的**：它只阻止编译器把变量缓存到寄存器。
  在 Cortex-M 上，单核且写操作本身是原子的（`uint16_t`/`uint8_t` 对齐写），所以够用。
  **但在多核（Cortex-M7 + M4 双核、或带 DMA 的场景）上，`volatile` 不足以保证顺序，
  必须加内存屏障**：
  ```c
  r->buf[r->head] = c;
  __DMB();                  /* 确保数据写入先于 head 更新被对方看到 */
  r->head = next;
  ```
- **保留一个空位**是最省事的"空/满"区分法。代价是可用容量是 `RING_SIZE - 1`。
  另一种做法是用一个 `volatile uint32_t count` 计数（但需要原子增减，反而更复杂），
  或者让 `head == tail` 且 `count` 字段配合。**嵌入式里最推荐"留一位"**。
- **掩码代替取模**：`(x + 1) & RING_MASK` 在 `RING_SIZE` 是 2 的幂时等价于 `% RING_SIZE`，
  但只需一条 `AND` 指令（M0 上的 `%` 要调用除法子程序，几十个周期）。所以 `RING_SIZE` 必须是 2 的幂。
- **`ring_get_line` 的"只窥视不消费"**也很关键：如果边找 `\n` 边 `ring_get`，找到半行时
  数据已经被取走了，只能自己再缓存——那就等于把这个环形缓冲的复杂度又搬到上层。
- 缓冲区大小取 **2 的幂**，并且不要开太大：如果串口一次来的最长命令是 128 字节，`RING_SIZE = 128`
  就够（可用 127）。开 4096 会白吃 RAM。

</details>

## 32. 改错：`strlen` 的返回值比较 ★☆☆

```c
/* 需求：判断 a 是否比 b 长 */
int is_longer(const char *a, const char *b)
{
    if (strlen(a) - strlen(b) > 0) {
        return 1;
    }
    return 0;
}
```

<details>
<summary>解析</summary>

**错误**：`strlen` 返回 `size_t`（无符号）。当 `a` 比 `b` 短时，
`strlen(a) - strlen(b)` 会回绕成一个**巨大的正整数**，所以 `> 0` **恒为真**，函数永远返回 1。

```c
/* 演示 */
strlen("ab") - strlen("abcdef")  // 2 - 6 → 0xFFFFFFFC，不等于 -4，而是 4294967292
```

这是 C 语言里最经典的 unsigned 陷阱之一。同类的还有：

```c
if (x - y < 0)              /* x, y 无符号时恒假 */
for (size_t i = n - 1; i >= 0; i--)   /* i 永远 >= 0，死循环 */
if (strlen(s) - 1 >= 0)     /* 恒真，且 strlen("") - 1 是巨大值 */
```

**正确写法**：

```c
int is_longer(const char *a, const char *b)
{
    return strlen(a) > strlen(b);
}
```

或显式转换（不推荐，容易再次出错）：

```c
if ((int)strlen(a) - (int)strlen(b) > 0)   /* 若长度差超过 INT_MAX 仍会出错 */
```

**根因**：C 的无符号运算规则——当 `int` 和无符号类型做运算时，
`int` 会先被转成无符号类型，**负数变成巨大正数**。所以只要表达式里出现 `size_t`，
就要警惕相减和比较。

在嵌入式里这个 bug 更隐蔽：`sizeof` 也返回 `size_t`，
`if (sizeof(buf) - len > 0)` 是同一个坑。

</details>

## 33. 改错：`strncpy` 之后直接用 ★★☆

```c
typedef struct {
    char name[8];
    uint32_t value;
} entry_t;

void entry_set_name(entry_t *e, const char *src)
{
    strncpy(e->name, src, sizeof(e->name));
}
```

<details>
<summary>解析</summary>

**错误**：`strncpy` 在 `strlen(src) >= sizeof(e->name)` 时**不写 `'\0'`**。
`entry_t.name` 后面紧挨着 `value`，于是：
1. 任何用 `%s` 打印 `e->name` 的地方会**越界读到 `value` 的字节**，直到碰上随机 0 才停；
2. 更糟的是某些实现会一路读到 unmapped 内存导致 HardFault。

而且 `entry_t` 在栈上或 `malloc` 出来的内存里，`name` 后面是 `value` 的填充字节，
这些字节内容不确定，所以 `strlen(e->name)` 结果也是随机的。

**正确写法**（两种）：

```c
/* 方案 A：拷完手动补 '\0'（简单，但多了次填充开销） */
void entry_set_name(entry_t *e, const char *src)
{
    strncpy(e->name, src, sizeof(e->name) - 1);
    e->name[sizeof(e->name) - 1] = '\0';
}
```

```c
/* 方案 B（推荐）：用第 5 题的 my_strlcpy */
void entry_set_name(entry_t *e, const char *src)
{
    my_strlcpy(e->name, src, sizeof(e->name));
}
```

**注意方案 A 里的 `sizeof(e->name) - 1`**：如果写成 `strncpy(e->name, src, sizeof(e->name))`
再补 `e->name[sizeof - 1] = '\0'`，虽然也能保证有 `'\0'`，但会**白白丢掉最后一个可用字节**
（本来能放 7 个字符 + `'\0'`，变成最多 7 个字符还是能放下，但若 `src` 正好 8 个字符则第 8 个被丢弃——正确）。

**顺带一提**：`sizeof(e->name)` 能正确取到 8，因为 `name` 是**数组不是指针**。
如果把参数写成 `void entry_set_name(entry_t *e, char name[])` 然后在里面 `sizeof(name)`，
那就是第 34 题的坑了。

</details>

## 34. 改错：数组参数退化成指针 ★☆☆

```c
void uart_send(char data[])
{
    /* 需求：把 data 里的每个字节发出去 */
    for (size_t i = 0; i < sizeof(data); i++) {
        UART_REG = data[i];
    }
}
```

<details>
<summary>解析</summary>

**错误**：`char data[]` 作为函数参数**等价于 `char *data`**（数组退化）。
所以 `sizeof(data)` 得到的是**指针的大小**（32 位 MCU 上是 4，64 位主机上是 8），
而不是数组长度。

后果：
- 在 64 位 PC 上会多发 8 个字节的栈垃圾；
- 在 32 位 MCU 上只发 4 个字节，剩下的数据丢了。

**正确写法**：长度必须显式传进来。

```c
void uart_send(const char *data, size_t len)
{
    for (size_t i = 0; i < len; i++) {
        UART_REG = (uint8_t)data[i];
    }
}
```

**相关知识点**（面试常问的对照）：

```c
char a[10];
char *p = a;

sizeof(a)    /* 10 —— 数组大小 */
sizeof(p)    /* 4 或 8 —— 指针大小 */
sizeof("abc")/* 4 —— 字符串字面量含 '\0' */
strlen("abc")/* 3 —— 不含 '\0' */

void f(char b[10]) { sizeof(b); }   /* 4 或 8，不是 10！ */
void g(char (&b)[10]);              /* C++ 引用传参才能保留大小，C 没有 */
```

**辅助记忆**：只有 `sizeof` 和 `&` 两个运算符作用在数组上时，数组**不**退化。

**工程建议**：C 里传数组一律「指针 + 长度」成对传，
或者定义一个带长度的视图结构体（避免参数写反）：

```c
typedef struct { const uint8_t *data; size_t len; } buf_t;
void uart_send(buf_t b);
```

</details>

## 35. 改错：修改字符串字面量 ★☆☆

```c
void to_upper_all(void)
{
    char *msg = "hello";
    for (char *p = msg; *p; p++) {
        *p = (char)toupper((unsigned char)*p);
    }
    printf("%s\n", msg);
}
```

<details>
<summary>解析</summary>

**错误**：`"hello"` 是**字符串字面量**，存放在只读数据段（`.rodata`，在 MCU 上通常在 Flash 里）。
向它写入是**未定义行为**：

- PC 上表现为段错误（Segmentation fault）；
- MCU 上写 Flash 会直接触发总线错误 → HardFault，或者**静默写入失败**（更隐蔽）。

**正确写法**：

```c
void to_upper_all(void)
{
    char msg[] = "hello";      /* ★ 数组：在栈上分配可写副本 */
    for (char *p = msg; *p; p++) {
        *p = (char)toupper((unsigned char)*p);
    }
    printf("%s\n", msg);
}
```

**另外两个错误**：

1. **`toupper` 的参数必须转 `unsigned char`**。当 `char` 带符号时，
   `*p` 若是 `0x80` 以上的字节会变成负的 `int`，传入 `toupper` 是 UB（`ctype.h` 的函数只接受
   `unsigned char` 范围的值或 `EOF`）。
2. `toupper` 返回 `int`，赋值回 `char` 时最好显式 `(char)` 转换，避免实现定义的截断告警。

**记忆口诀**：

| 写法 | 存储位置 | 可写 |
|---|---|---|
| `char *p = "abc";` | `.rodata` / Flash | ❌ 不可写 |
| `char a[] = "abc";` | 栈（或 `.data`，若是静态） | ✅ 可写 |
| `const char *p = "abc";` | `.rodata` | ❌ 不可写，且编译器会帮你拦 |

**嵌入式相关**：如果 MCU 把常量放在 Flash 且不支持"写 Flash"，
`char *p = "abc"` 这种方式还可能**白白占用宝贵的 RAM**——
因为某些链接脚本会把字面量放进 RAM 的可写段（`-fwritable-strings` 之类的旧行为）。
现在的编译器默认放只读段，所以 RAM 省了，但可写性也就没了。

**工程规范**：凡是**不打算修改**的字符串指针参数，一律加 `const`：

```c
void log_print(const char *msg);      /* 明确承诺不修改 */
```

这样调用方传字面量、传 `const` 变量都不会有告警，也避免自己在函数里手滑写入。

</details>

## 36. 改错：`strcpy` 处理重叠内存 ★★☆

```c
/* 需求：把 buf 里的内容整体后移 2 个字节 */
void shift_right(char *buf)
{
    strcpy(buf + 2, buf);
}

/* 需求：从 recv 缓冲里抠掉前缀 "AT+" */
void strip_prefix(char *recv)
{
    strcpy(recv, recv + 3);
}
```

<details>
<summary>解析</summary>

**第一个函数有 bug，第二个没有**——这是一个很好的辨析题。

**`shift_right` 的错误**：源和目标重叠，且**目标在高地址**。
`strcpy` 逐字节从低到高拷贝，第一次写 `buf[2] = buf[0]` 之后，
`buf[2]` 的原值就被覆盖了；接下来 `buf[3] = buf[1]`，然后
`buf[4] = buf[2]`——而此时的 `buf[2]` 已经是**被改过的值**了。

演示：

```
buf = "abcdef"
      ↑
strcpy(buf+2, buf);
  步 1: buf[2] = buf[0] → "ab" + "a" + "def" = "abade f"... 实际 "ababdef"
  步 2: buf[3] = buf[1] → "aba" + "b"  = "ababdef"
  步 3: buf[4] = buf[2] → buf[2] 现在是 'a'（不是原来的 'c'）→ "ababab"
  步 4: buf[5] = buf[3] → buf[3] 现在是 'b' → "ababab"
  结果: "ababab"，期望是 "ababcd"
```

**注意**：`strcpy` 的重叠行为是**未定义**的。
上面只是"常见的"错误结果。优化过的 `strcpy`（按字批量拷贝）可能给出完全不同的答案，
所以这个 bug 在 debug 版和 release 版表现不一致，极难定位。

**正确写法**：

```c
void shift_right(char *buf)
{
    memmove(buf + 2, buf, strlen(buf) + 1);   /* ★ 必须用 memmove */
}

void strip_prefix(char *recv)
{
    /* 这个方向其实"碰巧"安全：目标在低地址，从低往高拷不会踩到未读数据 */
    memmove(recv, recv + 3, strlen(recv + 3) + 1);
    /* 但依然推荐用 memmove —— 让"允许重叠"这个意图显式化 */
}
```

**为什么 `strip_prefix` 的原写法"碰巧"能工作**（但依然不该这么写）：

```
recv = "AT+SET"
strcpy(recv, recv + 3);
  步 1: recv[0] = recv[3] = 'S'   → "ST+SET"  （recv[3] 还没被覆盖，安全）
  步 2: recv[1] = recv[4] = 'E'   → "SE+SET"
  步 3: recv[2] = recv[5] = 'T'   → "SETSET"
  步 4: recv[3] = recv[6] = '\0'  → "SET"
```

写指针（下标 0）始终**落后于**读指针（下标 3），所以读到的都是尚未被覆盖的原始数据。

**统一规则**：

| 重叠场景 | 是否安全 | 用什么 |
|---|---|---|
| 源和目标都不重叠 | ✅ | `memcpy` / `strcpy` |
| 目标在**低**地址（向前搬） | 逐字节实现安全，但标准不保证 | 用 `memmove` |
| 目标在**高**地址（向后搬） | ❌ 必错 | 用 `memmove` |

**实操建议**：只要两个指针可能指向同一块内存，**一律用 `memmove`**。
`memmove` 的实现会先判断方向再决定拷贝顺序，多出来的判断开销可忽略。

</details>

## 37. 改错：中断里的 `strtok` ★★☆

```c
static char rx_line[64];
static uint8_t rx_len = 0;

/* 串口每收到一个字节调用一次 */
void USART1_IRQHandler(void)
{
    char c = USART1->DR;

    if (c == '\n') {
        char *tok = strtok(rx_line, " ,");
        while (tok != NULL) {
            handle_token(tok);
            tok = strtok(NULL, " ,");
        }
        rx_len = 0;
    } else {
        rx_line[rx_len++] = c;      /* ① */
    }
}
```

<details>
<summary>解析</summary>

**问题一（严重）：中断里用 `strtok`**。`strtok` 用函数内的 `static` 变量保存分割进度，
是**不可重入**的。如果主循环里别的地方也在用 `strtok`（很常见，比如解析配置文件），
两者会互相破坏对方的进度，表现为"解析结果随机错乱"，且只在特定时序下复现。

**问题二（严重）：`strtok` 会修改原串，还做着耗时的活**。
`rx_line` 在中断里被就地改写成多个 `'\0'`，如果主循环还想查看原始报文（打日志、重传），数据已经没了。

**问题三：中断里做了太多工作**。`strtok` 内部反复调用 `strchr` 遍历分隔符表，
`handle_token` 更是不知要跑多久。**中断服务程序应该尽可能短**，
否则会阻塞其他同优先级/低优先级中断、影响系统实时性。

**问题四：缓冲区溢出**。`rx_len++` 没有任何边界检查，如果对方一直发 `'\n'` 以外的数据，
`rx_len` 会跑到 64 以上，**写爆 `rx_line` 旁边的变量**。

**问题五：`rx_line` 没有 `'\0'` 结尾**。收到 `'\n'` 时 `rx_line[rx_len]` 从未被写成 `'\0'`，
`strtok` 会一直往后读，直到碰上内存里随机的 0——典型的越界读。

**正确写法**（就是第 31 题的结构）：

```c
static ring_t rx_ring;
static char rx_line[64];
static uint8_t rx_len = 0;

/* 中断里只做"收字节"，越短越好 */
void USART1_IRQHandler(void)
{
    uint8_t c = (uint8_t)USART1->DR;

    /* ★ 只入环形缓冲，不做任何解析（几微秒完成） */
    if (ring_put(&rx_ring, c) != 0) {
        rx_overflow_cnt++;          /* 溢出计数，便于诊断 */
    }
}

/* 主循环里解析 */
void app_poll(void)
{
    /* ★ 先凑齐一整行（ring_get_line 保证有 '\0'、处理了超长截断） */
    while (ring_get_line(&rx_ring, rx_line, sizeof(rx_line)) == 1) {

        char *save = NULL;
        char *tok = my_strtok_r(rx_line, " ,", &save);   /* ★ 可重入版本 */
        while (tok != NULL) {
            handle_token(tok);
            tok = my_strtok_r(NULL, " ,", &save);
        }
    }
}
```

**改动清单**：

| # | 问题 | 改法 |
|---|---|---|
| 1 | `strtok` 不可重入 | 换 `strtok_r`（第 16 题） |
| 2 | 中断里解析耗时 | 中断只 `ring_put`，解析挪到主循环 |
| 3 | 缓冲区溢出 | 用环形缓冲，满了丢数据 + 计数 |
| 4 | 缺 `'\0'` | `ring_get_line` 负责补 |
| 5 | 丢字节无感知 | 加溢出计数，便于现场诊断 |

**如果确实必须在中断里处理**（比如没有主循环的裸机小项目），至少要做到：

```c
void USART1_IRQHandler(void)
{
    static char c;

    c = (char)USART1->DR;
    if (c == '\n') {
        rx_line[rx_len] = '\0';                  /* ★ 补上结尾 */
        rx_pending = 1;                          /* ★ 只置标志，让主循环去解析 */
    } else if (rx_len < sizeof(rx_line) - 1) {   /* ★ 边界检查 */
        rx_line[rx_len++] = c;
    } else {
        rx_len = 0;                              /* 溢出：丢弃这一行 */
    }
}

void app_poll(void)
{
    if (rx_pending) {
        rx_pending = 0;
        /* 在这里解析 */
    }
}
```

`rx_pending` 需要声明为 `volatile`，且注意"读-改-写"的竞态
（主循环清标志的瞬间中断又置位，会丢一次事件——正确做法是用中断无关的临界区或者计数器）。

</details>

## 38. 改错：`snprintf` 截断判断 ★★★

```c
/* 需求：把 name 和 value 拼成一条 JSON，写入 buf
 * 返回实际写入的字符数 */
size_t build_json(char *buf, size_t size, const char *name, const char *value)
{
    size_t len = 0;

    len += snprintf(buf + len, size - len, "{\"name\":\"%s\",", name);
    len += snprintf(buf + len, size - len, "\"value\":\"%s\"}", value);

    return len;
}
```

<details>
<summary>解析</summary>

**这是一个真实存在于大量生产代码里的漏洞模式，后果是栈溢出。**

**错误 1：误解了 `snprintf` 的返回值。**
`snprintf` 返回的是「**假如空间无限大，本该写入多少个字符**」，而不是实际写入了多少。
所以一旦发生截断，返回值会**大于**缓冲区容量。

演示：`size = 10`，`name = "AAAAAAAAAA"`（10 个字符）

```
第一次 snprintf(buf, 10, "{\"name\":\"%s\",", ...)
  本该写 20 个字符，实际写 9 个 + '\0'
  返回值 = 20        ← 不是 9！

len += 20   →  len = 20

第二次 snprintf(buf + 20, size - len, ...)
  size - len = 10 - 20
  ★ size_t 无符号！10 - 20 = 18446744073709551606
  → 传入一个天文数字作为缓冲区大小
  → snprintf 认为"空间无限大"，放心地往 buf + 20 处写入
  → ★ 越界写，踩坏栈
```

`buf + 20` 已经跑到 `buf` 之外了，再加上一个巨大的 size，写入必然越界。
在嵌入式里这是"随机 HardFault"，在 PC 上这是可利用的栈溢出。

**错误 2：没有检查任何一次调用的结果。**
如果第一次就截断了，第二次不应该继续拼，而应该报错返回。

**错误 3：返回值语义混乱。**
注释说"返回实际写入的字符数"，但实现返回的是"本该写入的字符数"。
调用方若用这个值去做 `pos += ret` 之类的推进，就会跟着一起越界。

**正确写法**：

```c
/* 成功返回写入的字符数（不含 '\0'），截断或出错返回 (size_t)-1 */
size_t build_json(char *buf, size_t size, const char *name, const char *value)
{
    size_t len = 0;
    int n;

    if (buf == NULL || size == 0) {
        return (size_t)-1;
    }

    n = snprintf(buf, size, "{\"name\":\"%s\",", name);
    if (n < 0 || (size_t)n >= size) {
        buf[size - 1] = '\0';                    /* 保证是合法字符串 */
        return (size_t)-1;                       /* ★ 截断：立刻返回错误 */
    }
    len = (size_t)n;

    n = snprintf(buf + len, size - len, "\"value\":\"%s\"}", value);
    if (n < 0 || (size_t)n >= size - len) {     /* ★ 每次都检查 */
        buf[size - 1] = '\0';
        return (size_t)-1;
    }
    len += (size_t)n;

    return len;
}
```

**更好的写法**（用第 22 题的累积器模式，逻辑集中在一处）：

```c
static int json_appendf(size_t *used, char *buf, size_t size,
                        const char *fmt, ...)
{
    va_list ap;
    int n;

    if (*used >= size) {
        return -1;
    }
    va_start(ap, fmt);
    n = vsnprintf(buf + *used, size - *used, fmt, ap);
    va_end(ap);

    if (n < 0 || (size_t)n >= size - *used) {
        *used = size - 1;
        return -1;
    }
    *used += (size_t)n;
    return 0;
}
```

**关键记忆点**：

```c
int n = snprintf(buf, size, fmt, ...);

/* n < 0            → 编码错误 */
/* n < size          → 全部写入成功 */
/* n >= size         → ★ 被截断，buf 里只有前 size-1 个字符 */
/* 绝不能写成 len += n 然后 n 当长度用 */
```

**通用的安全模式**（推荐直接抄）：

```c
size_t off = 0;
#define APPEND(...)                                                     \
    do {                                                                \
        int _n = snprintf(buf + off, (off < size) ? size - off : 0,    \
                          __VA_ARGS__);                                 \
        if (_n < 0 || (size_t)_n >= size - off) {                       \
            return -1;   /* 截断 */                                     \
        }                                                               \
        off += (size_t)_n;                                              \
    } while (0)
```

注意 `(off < size) ? size - off : 0` 这个三元表达式——**即使 `off` 已经越界也不会下溢**，
这是防御性写法。

</details>

## 39. 改错：`char` 的符号性 ★★☆

```c
/* 需求：从串口读一个字节，如果是 0x80 以上的数据就记录下来 */
void check_byte(void)
{
    char c = (char)UART_READ();

    if (c >= 0x80) {                   /* ① */
        record_high_byte(c);
    }

    /* ② 期望把字节解析成十六进制显示 */
    printf("%02X\n", (uint8_t)c);
}
```

<details>
<summary>解析</summary>

**错误 ①：`char` 的符号性由实现决定**。

- 在 **ARM（Cortex-M，Keil/GCC arm-none-eabi）** 上，`char` 默认**无符号**（`-funsigned-char` 是某些工具链的默认）；
- 在 **x86/PC（GCC/Clang 默认）** 上，`char` 默认**有符号**。

如果 `char` 带符号，`(char)0x80` 是 `-128`，提升为 `int` 后还是 `-128`，
而 `0x80` 是 `128`，所以 `-128 >= 128` 为**假**。结果：**所有 0x80 以上的字节全部漏掉**。

更糟的是这个 bug **在 PC 上测试时可能出现、在 MCU 上不复现**（或反之），
取决于两边编译器的 `char` 默认符号性，是典型的"换平台就崩"。

**错误 ②：`printf("%02X", ...)` 的实参类型要求**。
`%X` 期望的是 `unsigned int`。传 `char`/`uint8_t` 会被整型提升为 `int`，
在某些平台上语义正确（值 0~255 范围内），但用 `(uint8_t)` 转换并不能保证
"提升后仍是正数"——实际上能，因为 `uint8_t` 提升到 `int` 一定是非负的（`int` 能容纳 0~255）。
所以错误 ② 严格说不是 bug，**但显式写成 `(unsigned)c` 更清晰**，能避免误读。

如果用的是 `%d` 就会出问题：`char c = -1; printf("%d", c)` 打印 `-1`，
而期望是 `255`。

**正确写法**：

```c
void check_byte(void)
{
    /* ★ 从硬件/外部来的字节，一律用 uint8_t / unsigned char 接收 */
    uint8_t c = (uint8_t)UART_READ();

    if (c >= 0x80) {                   /* 现在安全了 */
        record_high_byte(c);
    }
    printf("%02X\n", (unsigned)c);     /* 显式转 unsigned，意图明确 */
}
```

**相关规则（背下来）**：

```c
/* 类型选择 */
char          → 只用于「字符」，且明确知道是 ASCII 时
signed char   → 明确需要 -128~127 的有符号字节
unsigned char → ★ 处理字节数据、位运算（默认选择）
uint8_t       → ★ 嵌入式里的标准写法，语义最清晰

/* ctype.h 的函数必须传 unsigned char */
toupper((unsigned char)c);
isdigit((unsigned char)c);        /* ★ 别直接传 char */

/* 位运算建议用无符号，避免符号扩展的意外 */
uint32_t x = 0x80000000u;
if (x >> 31) { /* 逻辑右移，得 1 */ }
int32_t y = 0x80000000;
if (y >> 31) { /* 算术右移，得 -1，且是实现定义行为 */ }
```

**为什么用 `uint8_t` 而不是 `unsigned char`**：
两者在本平台上通常等价，但 `uint8_t` 明确表达了"这是 8 位数据"的意图，
并且在 8 位 AVR 之类平台上也不会误以为它是「比 `char` 宽」。
嵌入式代码里统一用 `uint8_t` 是可读性最好的选择。

**另一个同类坑：右移有符号数**

```c
int8_t v = (int8_t)0x80;      /* -128 */
int8_t r = v >> 1;            /* -64，算术右移。想要 0x40 = 64 就得先转无符号 */
uint8_t ok = (uint8_t)v >> 1; /* 0x40 = 64，逻辑右移 */
```

同理，位掩码操作（`x | 0x80`、`x & 0x7F`）一律用无符号类型，
避免符号位参与运算带来的意外。

</details>
